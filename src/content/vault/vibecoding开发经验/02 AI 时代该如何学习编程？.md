> 一句话概述：AI 时代，"能跑"不等于"能上线"，更不等于"出了事你能兜住"。程序员真正要练的不是跟 AI 比谁敲代码快，而是——**能定义、能判断、能兜底**。AI 负责生成，你负责定义、判断、兜底。

## 一、核心认知：AI 时代最值钱的三样能力

1. **把事说清楚**：知道要做什么、不做什么、什么算成功、出问题怎么办。
2. **把系统想明白**：模块怎么分、数据怎么流、接口怎么定、异常怎么处理、怎么降级。
3. **把结果验住**：AI 写的代码要审、要测、要灰度、要看监控、要能回滚。

### 为什么"知道"和"业务经验"重要

- AI 再强，也得**你先知道要什么**。脑子里没概念就描述不出来；描述不出来，AI 只能瞎猜。
- **正式业务和线上经验，AI 替不了你**。退款、优惠券、支付、库存这些不是写个接口就完事，里面全是坑。线上出过事、对过账、处理过告警，才知道什么叫"能上线"。

### 两个例子

**优惠券核销**：得知道券能不能叠加、有效期多久、每人限领几张、退款退不退券、并发领会不会超发、重复点会不会重复核销、跟支付和库存怎么对账。知道这些，才能告诉 AI 要什么；它写完你才知道哪里可能出事。上线后还得盯核销失败、超卖、重复核销、回调延迟，出事能回滚补偿。

**首页推荐**：不是"给我推 10 个商品"就完了。要定：新老用户都能用吗？点击率目标多少？延迟多少？没结果怎么办？然后设计服务、缓存、A/B 测试、降级开关。AI 可以写草稿，但你要审、要测、要灰度、要看数据。

> 最后一句：**会敲代码越来越不值钱，懂业务、能说清楚、能对线上负责，才值钱。**

## 二、AI 辅助开发 SOP

### 总原则

> AI 负责生成，你负责定义、判断、兜底。
> **没需求不写，没验收不生成，没测试不合并，没监控不回滚不上线，没复盘不结束。**

### 流程 8 步

| 步骤       | 动作                   | 要点                                 |
| :------- | :------------------- | :--------------------------------- |
| 1. 备规则   | 项目里维护 `CLAUDE.md`    | 写规范、业务规则、禁区                        |
| 2. 定需求   | 写清需求文档               | 背景、目标、范围、输入输出、业务规则、异常、验收、回滚        |
| 3. 做方案   | 让 AI 进 Plan mode 出方案 | 模块、数据流、接口、并发幂等、降级、监控、测试、回滚——**你审** |
| 4. 测试先行  | 拆小任务，先写测试            | Hooks 自动跑 lint/test                |
| 5. AI 生成 | 小步写                  | 让它解释改动                             |
| 6. 审查验证  | `/review` + 预发验证     | 看边界、安全、并发、缺测试                      |
| 7. 灰度上线  | 1%-5% 流量             | 盯错误率、延迟、业务指标、对账；异常回滚               |
| 8. 复盘沉淀  | 写回规则库                | 把坑和规则写回 `CLAUDE.md`、文档、测试          |

### 每次只多问 AI 三句

1. 先别写代码，**复述需求**，列出不确定点。
2. 给**计划、风险、异常、测试、回滚**方案。
3. 写完**审查 diff**，列出 bug、安全、边界、缺测试。

> 一句话：**先定义 → 再设计 → 再生成 → 再验证 → 再上线 → 再复盘。**

## 三、学习新技术的方法论

### 总原则

> 先搞清它**解决什么问题** → 跑通**最小 demo** → 拆**核心概念** → 用技术做**小项目**补边界和测试 → 最后才考虑**生产化**。

⚠️ 关键区分：**技术本身**和**用技术做真实项目**是两回事。入门学技术本身，进阶做项目才会遇到业务/工程问题。

### 分阶段重点

| 阶段 | 学什么 | 性质 |
| :--- | :--- | :--- |
| **入门**（学技术本身） | 问题域、核心概念、最小跑通、怎么调试 | 技术语法 |
| **进阶**（用小项目练） | 边界失败、错误处理、测试 | **业务/工程问题**，不是技术语法 |
| **生产**（上线后） | 性能、安全、监控、成本、回滚 | 运维治理 |

### 前端示例：React

- **入门**：组件、props、state、hooks。跑通 TodoList。
- **进阶**：用 React 做真实页面时——请求超时、重复提交、竞态、错误边界、加载/空/错误状态。
- **生产**：首屏性能、包体积、XSS、Sentry 监控、灰度回滚。

### 后端示例：Spring Boot

- **入门**：IoC、注解、Controller/Service/Repository。跑通 REST API。
- **进阶**：用 Spring Boot 做真实服务时——超时、并发、幂等、重试、降级、单元/集成测试。这些**不是 Spring Boot 语法，而是后端业务问题**；Spring Boot 提供工具：`@Transactional`、Spring Retry、Resilience4j、`@SpringBootTest`、MockMvc、Testcontainers。
- **生产**：性能、安全、监控、成本、回滚。

> AI 可以当导师、出题、审查理解，但**结论要查官方文档，亲手验证**。

> 一句话：**入门学技术本身，进阶做项目补边界，生产才管运维；前后端都要，只是表现形式不同。**
