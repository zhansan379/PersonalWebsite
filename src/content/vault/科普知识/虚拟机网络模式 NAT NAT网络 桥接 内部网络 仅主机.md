> 一句话概述：以 VirtualBox 为例讲清五种网络模式的**互通性差异**——NAT（默认，虚拟机各自隔离、只出不进）、NAT 网络（多台虚拟机共享一个 NAT 网络可互通）、桥接（虚拟机与宿主平级进入局域网，全互通）、内部网络（完全隔离，仅虚拟机互通）、仅主机 Host-Only（隔离但宿主可单向访问虚拟机）。记忆锚点：**NAT 只出不进，桥接全亮灯，内部网络全灭灯，仅主机"出去的门关着、进来的门开着"**。

## 一、五种模式互通性速览

不同虚拟机软件的网络模式种类略有不同，但原理相似，本文以网络模式较多的 **VirtualBox** 为示范。

| 模式            | 虚拟机↔虚拟机 | 虚拟机→宿主 | 宿主→虚拟机 | 虚拟机→互联网 | 互联网→虚拟机 |
| :------------ | :-----: | :----: | :----: | :-----: | :-----: |
| NAT           |    ❌    |   ✅    |   ❌    |    ✅    |    ❌    |
| NAT 网络        |    ✅    |   ✅    |   ❌    |    ✅    |    ❌    |
| 桥接 Bridged    |    ✅    |   ✅    |   ✅    |    ✅    |    ✅    |
| 内部网络 Internal |    ✅    |   ❌    |   ❌    |    ❌    |    ❌    |
| 仅主机 Host-Only |    ✅    |   ✅    |   ✅    |    ❌    |    ❌    |

桥接模式下互联网要直接访问虚拟机，需给虚拟机分配**公网地址**。
仅主机模式虚拟机没有网关，只能 ping 到宿主的虚拟网卡地址，访问不了宿主所在局域网的其他私有地址。

**一句话分档**：桥接是一个极端（全通），内部网络是另一个极端（几乎全断），其余三种在中间。

## 二、NAT 模式（VirtualBox 默认）
> NAT（Network Address Translation，网络地址转换）简单说：**把内网私有 IP，转换成公网 IP，实现多台设备共用一个公网 IP 上网**

**背景原理**：家庭网络普遍使用 NAT——只申请到一个公网 IP，路由器给多台设备分配**私有地址**；数据出去时 NAT 把私有地址转成公有地址（用端口标识），回来时再转回去。**私有地址不能被公有地址直接访问**，所以 NAT 天然"只出不进"。

**VirtualBox 中的表现**：

- 创建虚拟机默认就是 NAT 模式；软件提供**虚拟 DHCP 服务器和网关**（默认 `10.0.2.2`），给虚拟机分配私有地址（默认 `10.0.2.15`）
- **每台 NAT 虚拟机都在各自独立的网络里**，即使 IP 都是 `10.0.2.15` 也不冲突——因此**虚拟机之间不能互访**
- 虚拟机访问互联网经过**两层 NAT**：数据包出网关时被改写成"像宿主环境生成的"，再经宿主自身的 NAT 转换发出去
- 虚拟机**可以 ping 宿主**（数据本来就是通过宿主出去的）；但**宿主不能 ping 虚拟机**——对虚拟机来说宿主就是"公网"，公网访问不了私有地址
- 要让外部访问 NAT 虚拟机，需单独配置**端口转发**

## 三、NAT 网络

就是 NAT 多了"网络"二字：**让多台虚拟机共享同一个 NAT 网络，从而可以互通**，其余特性与 NAT 完全一样（可上网、外面进不来）。

- 原理：软件在虚拟机前加了一台**虚拟交换机**，所有选同一 NAT 网络的虚拟机处于同一网络
- 配置：先在全局设置中**创建 NAT 网络**（名字、网段、DHCP），再在每台虚拟机的网络设置里选择对应名字
- ⚠️ 同一网络里虚拟机 **MAC 地址必须不同**：克隆虚拟机后记得**刷新 MAC 地址**，否则 DHCP 握手可能出问题

## 四、桥接模式（Bridged Adapter）

**本质：把虚拟机直接放进宿主所在的局域网，虚拟机与宿主平级**——宿主从哪个 DHCP 服务器拿 IP，虚拟机也从那里拿。

- 因此会**消耗宿主局域网的 IP 地址**
- 配置：网络模式选"桥接网卡"，**适配器选宿主实际联网的那块**（宿主用 WiFi 联网就选 WiFi）；同样要保证 MAC 地址互不相同
- 效果：虚拟机与宿主网关相同，虚拟机↔虚拟机、虚拟机↔宿主、上网**全部互通**——"全部选项亮灯"，是五种模式里最方便的
- 注意：互联网要直接访问虚拟机，仍需给虚拟机分配公网地址

## 五、内部网络（Internal Network）

**完全隔离的网络**：虚拟机之间可以互通，但**不能访问宿主，更不能访问互联网**——虚拟机与宿主被分割开来。

- VirtualBox **默认不提供 DHCP 服务器**，需要**手动配置静态 IP**（如 Ubuntu 在 netplan 的 YAML 文件中添加 `addresses` 指定 IP）
- ⚠️ 切换前建议先在 netplan 配置中加 `optional: true`，避免虚拟机启动时一直卡在等待 DHCP
- 所有虚拟机必须选择**同一个内部网络名**才能互通
- 适用：搭建隔离的测试/实验环境；需要联网装环境时得先切其他模式

## 六、仅主机模式（Host-Only）

与内部网络非常像——仍是隔离网络、虚拟机互通、不能上网，**但有两个关键区别**：

1. **有虚拟 DHCP 服务器**，虚拟机自动获得 IP，不用手动配置
2. **宿主可以访问虚拟机**：虚拟机没有网关，出不去（ping 宿主的虚拟网卡地址为止），但宿主 ping 虚拟机没问题

形象记忆：**里面要出来的门是关的，外面（宿主）要进去的门是开的**——隔离了，但没完全隔离。宿主以外的设备依旧不能访问或被访问。

配置：与 NAT 网络类似，需先**创建仅主机网络**（名字、掩码、地址范围），再让虚拟机选择对应名字。

## 七、如何选

| 需求 | 选什么 |
| :--- | :--- |
| 默认、只要虚拟机能上网 | NAT |
| 多台虚拟机互通 + 上网，但不想暴露给局域网 | NAT 网络 |
| 虚拟机要作为局域网中一台"真实"机器（被其他设备访问） | 桥接 |
| 完全隔离的多机实验环境（如安全测试） | 内部网络 |
| 隔离环境 + 宿主需要 SSH/访问虚拟机（本地开发测试常用） | 仅主机 |
