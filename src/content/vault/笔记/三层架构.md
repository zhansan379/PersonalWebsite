# 三层架构

> LLM Wiki 的三层架构是其最核心的设计：源材料层（raw）、知识层（wiki）、规范层（CLAUDE.md），三层各司其职、互不越界。

## 一、架构图

```
┌─────────────────────────────────────────────────┐
│                  CLAUDE.md                       │
│              （规范层：维护宪法）                    │
│   告诉 LLM 如何提取知识、如何维护 wiki、如何更新索引  │
└──────────────────────┬──────────────────────────┘
                       │ 指导
                       ▼
┌─────────────────────────────────────────────────┐
│                    wiki/                         │
│              （知识层：结构化知识）                  │
│   原子化页面、丰富链接、持续迭代                     │
│   ┌──────────┐ ┌──────────┐ ┌──────────┐        │
│   │ 概念页面  │ │ 方法论页  │ │ 索引页面  │        │
│   └──────────┘ └──────────┘ └──────────┘        │
└──────────────────────┬──────────────────────────┘
                       │ 提取自
                       ▼
┌─────────────────────────────────────────────────┐
│                    raw/                          │
│              （源材料层：不可变原文）                 │
│   原始文档存放地，只读、不修改、不删除               │
│   ┌──────────┐ ┌──────────┐ ┌──────────┐        │
│   │  articles │ │  papers  │ │  books   │ ...     │
│   └──────────┘ └──────────┘ └──────────┘        │
└─────────────────────────────────────────────────┘
```

## 二、第一层：源材料层（raw/）

### 2.1 定位

raw/ 是知识的"原始矿石"。它是不可变的——就像历史档案，一旦放入就不再修改。

### 2.2 核心规则

| 规则 | 说明 |
|---|---|
| **不可变** | 原文写入后绝不修改。纠错、补充、评论都在 wiki 层完成 |
| **只读** | LLM 只能读取 raw，不能修改 raw |
| **有组织** | 按类型分目录，按日期+来源命名 |
| **完整保留** | 不删减、不缩写、不"优化"原文 |

### 2.3 为什么不可变？

- **真理之源**（Source of Truth）：wiki 中的知识可能被错误提取，可以回 raw 验证
- **可复现性**：换一个 LLM，基于同样的 raw，可以重新提取知识
- **版本历史**：raw 的创建时间天然形成时间线，可以追溯知识的来源
- **防止失真**：如果 raw 可修改，经过多轮"改写"后，原始信息会逐渐丢失

### 2.4 目录结构

```
raw/
├── README.md           # 使用说明
├── articles/           # 博客文章、网络文章
├── papers/             # 学术论文
├── books/              # 书籍笔记或摘要
├── web/                # 网页存档
├── videos/             # 视频/播客的文字记录
└── other/              # 其他类型
```

### 2.5 文件命名规范

```
YYYY-MM-DD 来源-标题.md

示例：
2026-05-26 阮一峰-为什么RAG不够用.md
2026-01-15 arXiv-Attention Is All You Need.md
2025-12-01 微信读书-思考快与慢.md
```

## 三、第二层：知识层（wiki/）

### 3.1 定位

wiki/ 是从 raw 中提炼的"纯知识"。它应该是：
- **结构化**：每个页面有清晰的模板和层次
- **原子化**：每个页面聚焦一个主题
- **链接化**：页面之间通过 `[[wiki-link]]` 紧密连接
- **可迭代**：可以持续修改、合并、拆分、重组

### 3.2 页面类型

| 类型 | 说明 | 示例 |
|---|---|---|
| **概念页** | 解释一个核心概念 | [[LLM Wiki]]、[[01 Agent 记忆机制]] |
| **方法论页** | 描述一套方法或流程 | [[知识提取原则]]、[[三层架构]] |
| **索引页** | 组织和导航 | [[index]] |
| **对比页** | 对比不同方案 | （如 RAG vs LLM Wiki 对比） |
| **综述页** | 整合多个来源的知识 | （如某个领域的知识综述） |

### 3.3 链接策略

- **向上链接**：链接到更抽象/更上层的概念
- **向下链接**：链接到更具体/更下层的概念
- **横向链接**：链接到相关但不同分支的概念
- **外部引用**：链接回 raw 中的源材料 `[[raw/...]]`

### 3.4 维护原则

- **增量更新**：不重写整个 wiki，每次只改动必要的页面
- **保持一致性**：相同的概念用相同的术语和格式
- **定期审视**：检查是否有孤立页面、过长页面、过期内容
- **用户主导**：LLM 可以建议修改，但最终由用户决定

## 四、第三层：规范层（CLAUDE.md）

### 4.1 定位

CLAUDE.md 是"元知识"——关于如何管理知识的知识。它告诉 LLM：
- 知识库的结构是什么
- 如何提取知识
- 如何维护 wiki
- 什么能做、什么不能做

### 4.2 为什么需要显式规范？

LLM 每次对话是"无状态"的——它不知道上一次的 LLM 做了什么。CLAUDE.md 解决了这个问题：

- **一致性**：不同的 LLM 实例按同一套规范工作
- **可进化**：规范本身可以迭代优化
- **自文档化**：新加入的协作者（人或 LLM）通过读 CLAUDE.md 就能理解整个体系

### 4.3 规范的内容结构

```
CLAUDE.md
├── 架构总览          # 三层是什么
├── 核心工作流        # 怎么操作的
├── 知识提取原则      # 提取什么、不提取什么
├── Wiki 页面规范     # 命名、frontmatter、结构模板
├── Index 维护规范    # 何时更新、怎么分类
├── Raw 区管理规范    # 目录结构、命名规范
├── 维护周期          # 日常、每周、每月的维护任务
└── LLM 行为准则      # LLM 必须遵守的铁律
```

## 五、三层之间的数据流

```
用户行为                LLM 行为                 产物
───────                ────────                 ────
放入 raw/                                         raw/ 新文件
                           │
                      阅读 raw/ 和 CLAUDE.md
                           │
                      提取知识
                           │
                      写入 wiki/ 新页面 ────────→  wiki/ 新文件
                           │
                      更新 wiki/index.md ──────→  wiki/index.md 更新
                           │
用户审阅 ←─────────────────┘
    │
    ├── 满意 → 完成
    └── 不满意 → 修正（在 wiki 层修改，不动 raw）
```
