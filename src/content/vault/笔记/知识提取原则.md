# 知识提取原则

> 知识提取是 LLM Wiki 的核心环节。把 raw 中的原始材料转化为 wiki 中的结构化知识，需要遵循一套系统化的原则。

## 一、提取的总原则

**目标不是摘要，是重构。**

不要简单地缩写原文，而是：
1. 理解材料在说什么
2. 识别其中的知识单元
3. 将这些知识单元以更清晰的结构重新组织
4. 建立知识单元之间的联系

## 二、提取什么（Inclusion）

### 2.1 核心概念

识别材料中的关键概念，为每个概念创建或更新一个 wiki 页面。

**判断标准**：
- 这个概念在材料中被反复提及或重点解释
- 这个概念是理解其他内容的前提
- 这个概念有独立的讨论价值

**操作方式**：
- 如果 wiki 中已有该概念页面 → 补充新内容
- 如果没有 → 创建新页面
- 如果概念是另一个概念的子概念 → 在页面内用标题层级表达，或根据重要性独立成页

### 2.2 逻辑关系

捕捉概念之间的联系：

| 关系类型 | 示例 | 表达方式 |
|---|---|---|
| 层级（is-a） | "LLM Wiki 是一种知识管理方法" | 页面内标题层级、`[[上级概念]]` 链接 |
| 组成（has-a） | "三层架构包含 raw、wiki、CLAUDE.md" | 页面内列表、`[[组成部分]]` 链接 |
| 因果（leads-to） | "raw 不可变 → 知识可追溯" | 页面内解释、链接到原因和结果页面 |
| 对比（vs） | "LLM Wiki vs RAG" | 对比表格、链接到对比双方的页面 |
| 先后（before-after） | 工作流步骤 | 编号列表、流程图描述 |

### 2.3 方法论 / 流程

可操作的步骤、框架、流程 → 独立成页。

**示例**：
- 工作流描述 → 创建方法论页面
- 最佳实践列表 → 创建实践指南页面
- 决策树/判断标准 → 创建决策页面

### 2.4 关键事实与数据

- 重要的数据点（保留出处链接回 raw）
- 核心结论（标注来源）
- 可验证的引用（标注原文出处）

### 2.5 不同观点

如果材料中涉及同一问题的多种观点，应：
- 在概念页面中客观呈现各方观点
- 不要只保留"主流"或"正确"的观点
- 标注每种观点的来源

## 三、不提取什么（Exclusion）

### 3.1 原文逐字复制

wiki 是重组后的知识，不是原文副本。如果需要查看原文，应直接去 raw/。

❌ 错误做法：把 raw 的内容原样搬到 wiki
✅ 正确做法：理解后用 wiki 的风格重新表述

### 3.2 叙述性内容

材料的"外壳"不需要保留：
- 过渡段落（"接下来我们讨论..."）
- 修辞和修饰
- 作者的个人轶事（除非本身是知识点）
- 重复的强调和总结

### 3.3 已在 wiki 中充分覆盖的内容

提取前先检查：wiki 中是否已经有了？如果有：
- 新内容与旧内容是否重复？→ 跳过重复部分
- 新内容是否补充了旧内容？→ 合并进去
- 新内容是否与旧内容矛盾？→ 标注矛盾，让用户裁决

### 3.4 失效或过时的信息

如果 raw 中包含了已被新信息取代的内容：
- 保留新信息
- 如果历史演变本身有价值，可以用"历史"段落记录旧信息
- 不要用旧信息覆盖新信息

## 四、提取流程

### 4.1 三步法

```
第一步：通读理解
    ↓
第二步：识别知识单元
    ↓
第三步：组织写入 wiki
```

### 4.2 第一步：通读理解

- 完整阅读 raw 材料
- 理解材料的主题、论点、结构
- 标记关键段落（在心里或笔记中）

### 4.3 第二步：识别知识单元

读完后，问自己：

1. 这篇材料讲了哪几个**核心概念**？
2. 这些概念之间有什么**关系**？
3. 有没有可操作的**方法论**？
4. 有哪些值得保留的**关键事实/数据/引用**？
5. 有哪些**不同观点**需要记录？

将答案列为一个清单，这是提取的"施工图"。

### 4.4 第三步：组织写入 wiki

对于清单中的每个知识单元：

```
检查 wiki 中是否已有相关页面
    ├── 有 → 更新现有页面（补充/修正/重组）
    └── 没有 → 创建新页面
                     │
                     ├── 写 frontmatter
                     ├── 写内容（遵循页面模板）
                     ├── 添加链接（连接到相关页面）
                     └── 更新 index（注册新页面）
```

## 五、质量自检清单

提取完成后，LLM 应自问：

- [ ] 新页面能被独立理解吗？（不依赖 raw 上下文）
- [ ] 新页面与已有页面充分链接了吗？
- [ ] 有没有重复已有内容？
- [ ] index 更新了吗？
- [ ] 新内容的"归属"正确吗？（放在合适的页面和分类下）
- [ ] 有没有丢失 raw 中的重要信息？
- [ ] 我的改写有没有曲解原意？

## 六、特殊情况处理

### 6.1 材料质量差

如果 raw 材料组织混乱、质量不高：
- 仍然提取其中有效的知识片段
- 不要在 wiki 中评论材料质量（wiki 是知识，不是书评）
- 如果信息太少不足以成页 → 合并到已有页面或跳过

### 6.2 材料与已有知识矛盾

- 不要直接覆盖已有知识
- 在相关页面中增加"不同观点"段落
- 标注来源，让用户判断

### 6.3 材料涉及敏感或有争议的内容

- 客观呈现事实和观点
- 不选边站队
- 不添加 LLM 自己的价值判断
