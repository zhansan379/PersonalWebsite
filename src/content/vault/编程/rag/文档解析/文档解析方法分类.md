# 文档解析方法分类

> 文档解析（将 PDF 等非结构化文档转为 Markdown 等结构化格式）的三种主流范式。

## 一、三种范式对比

| 范式          | 做法                                    | 优势                   | 劣势                        | 代表方法                                             |
| ----------- | ------------------------------------- | -------------------- | ------------------------- | ------------------------------------------------ |
| **管道方法**    | 将解析分解为独立子任务（布局检测→文本识别→表格提取→公式识别），级联执行 | 每个组件可独立优化            | 跨阶段错误传播，模块间信息丢失           | 传统 OCR 系统                                        |
| **端到端 VLM** | 直接将文档图像映射到结构化输出                       | 避免级联错误               | 原生分辨率处理导致 O(N²) Token 复杂度 | Nougat, GOT-OCR 2.0, Ocean-OCR, olmOCR, dots.ocr |
| **解耦 VLM**  | 布局分析与内容识别分离，结合管道的可控性和 VLM 的语义能力       | 分辨率保真度、计算效率和部署复杂性的平衡 | 架构设计更复杂                   | MinerU 系列, Dolphin, MonkeyOCR                    |

## 二、关键演进节点

1. **Nougat**（2023）：在 Donut 架构上建立了学术文档的图像到标记范式
2. **Dolphin**（2025）：证明了 VLM 解耦范式的可行性
3. **MinerU2.5**（2025）：将布局分析和内容识别统一在同一模型中，支持原生分辨率解析
4. **MinerU2.5-Pro**（2026）：在不改架构的前提下，通过数据工程推动性能上限

此后解耦范式的扩展方向包括：多 Token 预测（吞吐量）、基于扩散的解码（解析效率和鲁棒性）、非平面文档处理、原始鲁棒性、高压缩视觉文本映射。

## 三、通用 VLM vs 专用模型

大型通用 VLM（Gemini 2.5 Pro、Qwen2.5-VL-72B）在文档解析上也取得了有竞争力的结果，但参数规模大（数百 B），在生产规模上成本效益部署困难。专用模型（0.9B-4B）以较小参数规模取得相当甚至更好的效果。

## 四、范式选择的实际考量

- **解耦 VLM** 目前是精度-效率权衡的最优解
- 端到端方法在简化流程上有优势，但高分辨率文档上的效率瓶颈尚未完全解决
- 管道方法在特定可控场景下仍有价值
