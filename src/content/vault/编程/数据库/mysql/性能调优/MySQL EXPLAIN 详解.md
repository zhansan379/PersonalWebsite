# MySQL EXPLAIN 详解

> `EXPLAIN` 是查看 **SQL 执行计划** 的工具，用来分析 SQL 执行过程：**有没有走索引、有没有外部排序、有没有索引覆盖**等。核心主线：**重点看 `type`（扫描方式）和 `extra`（额外行为），据此判断慢查询根因。**

## 一、这是什么

回答"explain 有什么作用"时，先一句话定位（执行计划分析工具），再讲**关键字段**，尤其 `type`（扫描方式效率排序）和 `extra`（Using filesort/temporary/index 等信号）。

## 二、核心内容

### 2.1 常见字段

| 字段 | 含义 |
| :--- | :--- |
| `possible_keys` | **可能**用到的索引 |
| `key` | **实际**用到的索引；**为 NULL 说明没走索引** |
| `key_len` | 索引长度 |
| `rows` | 扫描的行数（估算） |
| `type` | **扫描类型（重点关注）** |
| `extra` | 额外信息（排序、临时表、覆盖索引等信号） |

> 示例：一个没有使用索引、全表扫描的查询，`key=NULL`、`type=All`。

### 2.2 `type` 扫描类型（重点，效率从低到高）

| type       | 说明                                                                 | 效率  |
| :--------- | :----------------------------------------------------------------- | :-- |
| **All**    | 全表扫描，**最坏情况**                                                      | 最低  |
| **index**  | 全索引扫描（扫描索引表），免排序但开销大                                               | 低   |
| **range**  | 索引**范围**扫描（`<`、`>`、`in`、`between`），从这级起索引作用明显                      | 中   |
| **ref**    | **非唯一索引**或唯一索引的非空前缀，可能命中多条                                         | 中高  |
| **eq_ref** | **主键/唯一索引**，常用于多表联查的关联条件（如两张表 user_id 相等且唯一）                       | 高   |
| **const**  | **主键/唯一索引 + 常量**比较（如 `where id=1`），查询最快；`const` 与常量比、`eq_ref` 用于联查 | 最高  |

> 记忆：**尽量让查询用到 `range` 及以上**（range/ref/eq_ref/const），避免 All 全表扫描。

### 2.3 `extra` 重要指标

| extra               | 含义                                                  | 结论      |
| :------------------ | :-------------------------------------------------- | :------ |
| **Using filesort**  | 无法利用索引排序，不得不文件/外部排序（常因 `group by`/`order by` 无法走索引） | ❌ 低效，避免 |
| **Using temporary** | 用临时表保存中间结果（常见于 `order by`/`group by`）               | ❌ 低效，避免 |
| **Using index**     | **覆盖索引**：所需字段全在索引内，**避免回表**                         | ✅ 高效    |

## 三、可能追问

1. 「为什么 `type` 从 range 开始索引才明显发挥作用？」→ 前面的 All/index 是全表/全索引扫描，range 才是利用索引有序做范围裁剪
2. 「`const` 和 `eq_ref` 都是唯一索引，区别？」→ const 对常量、eq_ref 多在联查
3. 「`key` 为 NULL 说明什么？」→ 没走索引，需要加/改索引或排查索引失效
4. 「覆盖索引为什么快？」→ 所有查询列在索引里，免回表（Using index）
5. 「`Using filesort` 怎么优化？」→ 给 `order by`/`group by` 字段建索引，让 B+树天然有序
6. 「EXPLAIN 是真正执行还是预估？」→ 预估执行计划，不实际执行（`EXPLAIN ANALYZE` 才真正跑并给实际耗时）
