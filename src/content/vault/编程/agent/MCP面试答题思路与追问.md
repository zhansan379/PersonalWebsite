# MCP 面试答题思路与追问

> 先抓住**本质定位（协议层 / 系统集成）**，再逐层展开组件、对比、工程与高级话题。对方大概率会围绕"协议层 vs 模型能力"这条主线深挖。

## 一、核心答题逻辑（主线）

回答任何 MCP 问题，先立住三句话：

1. **定位先行**：MCP 是**协议层 / 系统集成问题**，不是模型能力问题——它不提升模型智商，只降低 AI 应用的"基础设施耦合成本"。
2. **解决 N×M 难题**：消除"每接一个工具/模型就写一套胶水代码"的重复建设，类比"USB-C / 通用插座"。
3. **分层思维**：凡是"XX 和 MCP 有什么区别"的问题，先判断对方处于哪一层（协议层 vs 模型能力 vs 接口层），再作答。

**不要背定义，要能落到项目里讲它解决了哪个集成痛点。** 这是全文反复强调的加分项。

## 二、关键知识点清单

| 主题 | 必答要点 |
| :--- | :--- |
| **核心价值** | 标准化通信桥梁；解决 N×M 集成难题；降低基础设施成本；本质是"系统集成问题" |
| **三角色架构** | Host（宿主，UI/环境）→ Client(与单个 Server **一对一**)→ Server(暴露功能) |
| **三种能力** | Tools(动作,带名称/描述/参数Schema)、Resources(只读上下文,URI定位)、Prompts(可复用提示模板) |
| **传输方式** | 本地 stdio；远程 Streamable HTTP |
| **生命周期** | 初始化 → 运行 → 关闭；初始化时 `initialize` 做**能力协商** |
| **对比 Function Calling** | 见下表 |
| **对比 REST API** | 见下表 |
| **实现核心** | 进程边界 + JSON-RPC 消息；官方 SDK + 装饰器（`@mcp.tool()`） |
| **企业价值** | 降重复建设 / 统一治理观测 / 加快模型替换试点 / 明确分工 |
| **生产挑战** | 权限安全 / 稳定性(超时/故障隔离) / 可观测性 / 版本兼容 / 海量工具路由 |
| **失败处理** | 捕获 → 重试/降级 → 结构化错误给模型 → 记日志分析 |

## 三、两组关键对比（高频考点）

### MCP vs Function Calling ⭐ 最高频
> 本质：**不同层次的概念，两者都需要，不是二选一。**

| 维度 | MCP | Function Calling |
| :--- | :--- | :--- |
| 核心定位 | **协议层**，标准化连接 | **模型能力**，单次推理选工具 |
| 架构 | 解耦，Client-Server | 紧耦合，易硬编码进提示词 |
| 动态性 | 高，运行时发现新工具 | 低，工具列表通常静态 |
| 生态 | 可复用，一次编写到处用 | 不可复用，每集成都是定制 |

**加分回答**：MCP 负责把工具标准化暴露；Host 拿到工具列表后，仍需模型用 **Function Calling 能力**决定调哪个工具 —— 两条链路协同。

### MCP Server vs REST API
- **服务对象**：REST 为开发者设计；MCP 为 LLM 设计，使其运行时能发现并调用。
- **发现机制**：MCP 能 `tools/list` 动态提供结构化能力描述；REST 依赖外部文档。

## 四、可能追问方向与应对

| 追问场景 | 对方想考察什么 | 应答要点 |
| :--- | :--- | :--- |
| "MCP 解决了模型能力问题还是系统集成问题？" | 是否真正理解协议定位 | 坚定回答**系统集成问题**，并解释为何不提升模型智商 |
| "有了 MCP 还需要 Function Calling 吗？" | 分层思维 & 链路完整性 | **需要**，MCP 暴露工具，FC 负责选择，二者协同 |
| "MCP Server 如何应对生产环境？" | 工程落地经验 | 5 个维度逐一展开：权限/稳定性/可观测/版本/路由 |
| "工具数量上百怎么办？" | 大规模可扩展性 | 向量检索、分类模型等路由方案，避免 Token 浪费和模型"迷惑" |
| "工具调用失败了怎么处理？" | 错误处理是否成体系 | 结构化四步：捕获→重试降级→给模型结构化错误→日志分析 |
| "实现一个 Server 的步骤？" | 是否真写过 | 建模→协议注册→参数校验→业务执行→结果返回→日志；强调**进程边界+JSON-RPC** |
| "未来趋势？" | 是否跟进社区动态 | 生态共享 / 安全增强 / 协议标准化(Streamable HTTP 取代旧版 SSE) |

## 五、答题避坑

- ❌ 只背定义，不落项目 —— 面试官最反感。
- ❌ 把 MCP 和 Function Calling 对立起来 —— 应是**层叠**关系。
- ❌ 说 MCP"提升模型能力" —— 会被立刻抓住定位错误。
- ❌ 忽略生产落地（权限、路由、可观测）—— 应届/初级考点，但也是拉开差距处。
- ✅ 开口先给定位，再分层展开，最后回扣项目场景。
