# 集合遍历的方法有哪些？

> 答题主线：**按"是否能用索引 / 是否需要删除 / 是否需要并发修改与函数式"来分层**——普通 `for`（List 索引）、`for-each`（最常用，语法糖）、`Iterator`（**遍历中安全删除的唯一解**）、`ListIterator`（双向 + 边遍历边改）、`forEach` 与 `Stream`（Java 8 函数式）。选型核心看：**能否删、要不要改、是否函数式**。

## 一、四步回答骨架

1. **定调**：遍历方法大致可归纳为"**索引遍历 + 迭代器 + 增强循环 + 函数式（forEach/Stream）**"几类。
2. **逐个讲适用场景**（见核心要点表）：每种方法的适用场景与限制。
3. **点关键陷阱**：**遍历中删除**要用 `Iterator`；`for-each` 在遍历中结构修改会抛 `ConcurrentModificationException`。
4. **收尾给选型**：简单读列表用 `for-each`/`forEach`；删元素用 `Iterator`；双向遍历/边巡边改用 `ListIterator`；要过滤/映射/聚合用 Stream。

## 二、核心要点

### 1. 六种遍历方法与适用场景

| 方法 | 代码 | 适用 / 特点 |
| :--- | :--- | :--- |
| **普通 for** | `for(int i=0; i<list.size(); i++)` `list.get(i)` | 有索引、可精确控制步进；只适用于能按索引访问的 List |
| **for-each（增强 for）** | `for(String e : list)` | **最常用**、写法简洁；本质是 `Iterator` 语法糖；不能改结构 |
| **Iterator** | `while(it.hasNext()){ it.next(); }` | **遍历时安全删除的唯一解**（`it.remove()`） |
| **ListIterator** | `while(li.hasNext()){ li.next(); }` | Iterator 子类；**可双向**遍历、遍历中**修改元素** |
| **forEach（Java 8）** | `list.forEach(e -> ...)` | 函数式惯用一句话；不能删除；实现依赖 Iterable 的默认方法 |
| **Stream API** | `list.stream().forEach(...)` | Java 8；能过滤/映射/聚合/并行，遍历只是其一 |

### 2. 遍历中「删除 / 修改」的讲究

- **普通 for / for-each / forEach / Stream**：**遍历中删除集合元素会抛 `ConcurrentModificationException`**（结构性修改检测）。
- **Iterator**：自带 `remove()`，是遍历中安全删除的标准做法（内部用 `it.remove()` 同步修改游标与集合）。
- **ListIterator**：比 Iterator 多个 `set()`/`add()`，能在遍历中修改元素或插入，且支持 `previous()` 反向遍历。

### 3. 普通 for 的局限

只能对**按索引随机访问的 List** 用；对无索引的 `Set`/`Map` 不适用（需转 `forEach` 或 `Iterator` 或 `keySet`/`entrySet`）。


### 4. 一边遍历一边修改元素

能否在遍历中改元素，**取决于遍历方式 + 底层实现**，核心分辨"**改值**（`set`）vs **改结构**（`add`/`remove`）"——只改值不变结构，通常不触雷；增删结构才可能抛 `ConcurrentModificationException`（CME）。

| 遍历方式 | 能改值(set)？ | 能改结构(add/remove)？ |
| :--- | :--- | :--- |
| **普通 for** | ✅ 可，只要索引不越界 | ⚠️ 谨慎（删除会破坏索引对应关系，需处理下标回退） |
| **for-each** | ✅ `set(i,v)` 不改变 `modCount` 结构，**不抛 CME** | ❌ 抛 `ConcurrentModificationException` |
| **Iterator / ListIterator** | ✅ 推荐 `ListIterator.set()`（最通用） | ✅ 删除用 `Iterator.remove()` |
| **CopyOnWriteArrayList** | ✅ 写时复制，**不抛 CME** | ✅ 可，但不读不到最新（改在新副本上，可能读到旧数据） |

```java
// 普通 for：索引在范围内即可改
for (int i = 0; i < list.size(); i++) {
    list.set(i, list.get(i) * 2);
}
```

```java
// for-each 中 add/remove → 抛 CME（底层迭代器检测 modCount != expectedModCount）
for (Integer num : list) {
    if (num == 2) {
        list.remove(num);   // ⚠️ 结构修改，下次 next() 抛 ConcurrentModificationException
    }
}
```

```java
// 用 ListIterator.set() 遍历中改值——最通用、可读性最好
ListIterator<Integer> it = list.listIterator();
while (it.hasNext()) {
    Integer num = it.next();
    if (num.equals(2)) {
        it.set(4);          // 替换元素（替代 list.set(index, v)）
    }
}
```

> **一句话**：
> - **只改值**（`set`）→ `set(i,v)` 或 `ListIterator.set()`，不会因结构导致 CME；
> - **增删**（`add`/`remove`）→ 只有 `Iterator.remove()` / `ListIterator` 系列安全，for-each/forEach 会抛 CME；
> - **CopyOnWriteArrayList** → 写时复制，遍历中可安全改，但可能读到旧数据（改在新副本上）。

## 三、如何应用 / 面试怎么讲

**加分表达：**
- 主动点出 **for-each 是 `Iterator` 的语法糖**——这句话体现"懂原理"而非只背语法。
- 特别强调**删除场景**：想在遍历中删元素，很多人错用 for-each 抛异常，正确姿势是 `Iterator.remove()`。
- 区分 `forEach` 与 `Stream.forEach`：前者是集合的默认方法（简单迭代），后者能链式 `filter/map/collect`。二者**都不能安全删**。

**一句收口**：**读**用增强 for / forEach，**删**用 Iterator，**双向或改**用 ListIterator，**过滤映射聚合**用 Stream。

## 四、可能被追问的点与预案

| 追问 | 应答案点 |
| :--- | :--- |
| 遍历中删除元素会怎样？ | 用 for-each/forEach/for 删会抛 `ConcurrentModificationException`；应用 `Iterator.remove()` 安全删 |
| 为什么 for-each 删元素抛异常？ | for-each 内部是 `Iterator`，迭代器有 `modCount` 快速失败检测，外部结构修改触发该异常 |
| for-each 和 Iterator 什么关系？ | for-each 是 Iterator 的**语法糖**，编译期展开成 Iterator；区别是 for-each 不能手动 `remove()` |
| ListIterator 比 Iterator 多了什么？ | `previous()` 双向遍历 + `set()`/`add()` 迭代中修改/插入 |
| 四种遍历哪个性能最好？ | 对 **ArrayList** 三者相近（都基于数组，for 简化了迭代对象）；对 **LinkedList** 普通 `for` 用 `get(i)` 是 O(n²)（每次从头遍历），**应避免** |
| 为什么 LinkedList 不能普通 for 的 get(i)？ | LinkedList 是链表，`get(i)` 需从头 O(n) 遍历，普通 for 累计 O(n²)；应改用迭代器或 for-each |
| 非 List（Set/Map）能普通 for 吗？ | 不能，无索引；Set 用增强 for/迭代器/forEach，Map 用 `keySet()`/`entrySet()` 或 `forEach((k,v)->)` |
| ConcurrentModificationException 是什么？ | 迭代期间结构被外部修改引发的快速失败异常，用于尽早暴露并发/误用问题 |
