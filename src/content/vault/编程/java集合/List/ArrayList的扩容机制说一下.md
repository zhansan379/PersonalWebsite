# ArrayList 的扩容机制说一下

> ArrayList 底层是数组，容量耗尽时才触发扩容：算出新容量（默认 **1.5 倍**）、建新数组、复制旧元素、替换引用。扩容涉及整数组复制与内存重分配，性能有损耗，所以初始化时预分配容量可减少扩容次数。

## 一、这是什么

`ArrayList` 底层用 `Object[]` 存储。添加元素时若 `size` 已达数组容量上限，就会触发**扩容**——把元素搬运到一个更大的新数组里。理解扩容机制 = 理解 "为什么 ArrayList 增删/频繁添加会慢"。

## 二、核心内容：扩容五步

1. **计算新容量**：默认扩为原容量 **1.5 倍**，再检查是否超最大容量限制。
2. **创建新数组**：按新容量分配一个更大的数组。
3. **复制元素**：把旧数组元素逐个复制到新数组。
4. **更新引用**：让 `ArrayList` 内部引用指向新数组。
5. **完成扩容**：之后继续添加新元素。

```java
// 新容量计算（1.5 倍，用移位实现）
int newCapacity = oldCapacity + (oldCapacity >> 1);
```

### 为什么是 1.5 倍？

**1.5 可以充分利用移位操作**，`oldCapacity >> 1` 即除以 2，减少浮点运算或乘除的运算时间与次数，兼顾扩容次数与浪费空间的平衡。

## 三、如何应用 / 面试怎么讲

- 扩容的核心代价是 **整数组复制 + 内存重分配**，在频繁添加大量元素时会影响性能。
- **减少扩容的优化**：初始化时预分配足够容量（`new ArrayList<>(capacity)`），避免频繁触发扩容。

**回答骨架**：扩容触发时机（满才扩）→ 五步过程 → 1.5 倍原因（移位）→ 性能代价与预分配优化 → 抛 `grow`/`ArraysSupport.newLength`（JDK9 后实现重构但比例不变）深水区。
