你可以把消息队列理解为一个使用队列来通信的组件。它的本质，就是个转发器，包含发消息、存消息、接受消息的过程。
MQ（Message Queue），它其实就指消息中间件，当前业界比较流行的开源消息中间件包括：RabbitMQ、RocketMQ、Kafka。
![[Pasted image 20260803213150.png]]
## MQ选型要点总结
1. **超大型秒杀场景（如双十一）**：核心关注吞吐量，管理界面、消息回溯优先级低，优先选择Kafka、RocketMQ。
2. **企业中台场景（多主题接入）**：重点考量支持的主题数量；Kafka仅适配百级主题，可选用支持千级主题的RocketMQ、支持百万级主题的RabbitMQ。
3. **金融业务场景**：侧重稳定性、安全性，分布式部署的Kafka、RocketMQ更合适。

## 基本概念
### 消息（Message）

消息是指，消息系统所传输信息的物理载体，生产和消费数据的最小单位，每条消息必须属于一个主题。
### 主题（Topic）
![[Pasted image 20260803213447.png|371]]
Topic表示**一类消息的集合**，每个主题包含若干条消息，每条消息只能属于一个主题，是RocketMQ进行消息订阅的基本单位。 topic:message 1:n message:topic 1:1。  
一个生产者可以同时发送多种Topic的消息；而一个消费者只对某种特定的Topic感兴趣，即只可以订阅和消费一种Topic的消息。 producer:topic 1:n consumer:topic 1:1。
### 标签（Tag）

为消息设置的标签，用于同一主题下区分不同类型的消息。Topic是消息的一级分类，Tag是消息的二级分类。

### 队列（Queue）

存储消息的物理实体。一个Topic中可以包含多个Queue，每个Queue中存放的就是该Topic的消息。**一个Topic的Queue也被称为一个Topic中消息的分区（Partition）。**  
![[Pasted image 20260803214328.png|334]]
一个Topic的Queue中的消息只能被一个消费者组中的一个消费者消费。一个Queue中的消息不允许同一个消费者组中的多个消费者同时费。

- **Broker**：消息代理服务节点，物理服务实例；多个 Broker 组成 Broker 集群，负责消息存储、接收生产者消息、推送消息给消费者。
- **Topic（主题）**：消息的**逻辑分类**，用于区分不同业务消息（订单、支付消息），Topic 本身不存储数据。
- **Queue（消息队列，RocketMQ）≈ Partition 分区（Kafka）**
    Queue/Partition 是**Topic 的数据分片**，日常口语统称为分片。
    创建 Topic 时会划分多个 Queue，这些 Queue 会分布式部署在集群不同 Broker 节点上。
![[Pasted image 20260803214757.png|411]]![[Pasted image 20260803220622.png]]

- 我们创建一个 Topic（比如`order_topic`），指定一共 4 个 Queue；
- MQ 自动把 4 个 Queue 分散部署在不同 Broker 上（BrokerA 放 Q0/Q1，BrokerB 放 Q2/Q3）；
- **Queue（分片）一定隶属于某一台 Broker**；
- Producer 发消息：负载均衡挑选一个 Queue → 找到 Queue 所在 Broker → 投递消息。
