# 温度和 Top-k 是什么？如何影响输出？

> 这道题**不是考调参经验，是考你知不知道这两个参数作用在推理链路的哪个环节**。正确的答法是：先定位（推理阶段、不改权重、只改输出分布），再分讲（温度=对 Logits 缩放、改分布锐度；Top-k=截断+掩码+重归一化），最后讲协同与缺陷（静态截断 → Top-p 动态截断）。只说「温度高更有创意、Top-k 取前 k 个」会被判定为只用过 API、没看过源码。

## 一、答题逻辑（骨架）

```
1. 总述定位                    ← 15 秒，一句话锁定层次
   推理阶段 / 解码策略 / 不改权重 / 只作用于输出概率分布
   目的：连贯性 ↔ 多样性 的 trade-off
2. 讲温度（突出数学本质）        ← 落到 Logits 和 Softmax
   ├─ 作用位置：Softmax 之前，对 Logits 做缩放（除以 T）
   ├─ 本质：控制分布的锐度 / 熵
   └─ T<1 更尖锐更确定 · T>1 更平滑更随机 · T=0 等价 Greedy
3. 讲 Top-k（突出操作细节）      ← 三步走，别漏第三步
   排序取前 k → 其余置 -inf 掩码 → 概率重归一化 → 采样
4. 讲协同与顺序                 ← 展现工程闭环
   温度软调节 + Top-k 硬截断；HF 中 温度 → Top-k → Top-p
5. 主动暴露缺陷 → Top-p         ← 辩证思维，也是抢占下一个问题
```

**关键心态**：这题的分水岭在**三个词**——`Logits`、`-inf 掩码`、`重归一化`。能自然说出这三个词，面试官基本判定你读过 `LogitsProcessor` 源码；说不出来就是纯 API 使用者。

## 二、核心答题点

### 2.1 第一步：总述（拔高站位）

> 「温度和 Top-k 是 LLM  **推理（Inference）阶段用于控制**解码策略（Decoding Strategy）**的核心超参数。它们不改变模型的**权重（Weights）**，只作用于最终的**输出概率分布（Output Distribution）**，目的是在**连贯性（Coherence）**和**多样性（Diversity）**之间做 trade-off。」

### 2.2 第二步：温度（突出数学本质）

**作用位置**：**Softmax 之前**，对 **Logits**（未归一化分数）做缩放。

$$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

**数学本质**：控制概率分布的**锐度（Sharpness）**，等价于控制分布的**熵（Entropy）**。

| 温度 | 对 Logits 差距 | 分布形态 | 熵 | 行为 |
|---|---|---|---|---|
| `T → 0` | 差距无限放大 | 退化为 one-hot | → 0 | 等价 **贪心搜索（Greedy）** |
| `T < 1` | **放大**相对差距 | 更**尖锐（Peakier）** | 变小 | 确定性增强，倾向 Argmax |
| `T = 1` | 原始 Logits | 模型原生分布 | — | 不做干预 |
| `T > 1` | **压缩**差距 | 更**平滑（Flatter）** | 变大 | 尾部 token 获得机会，随机性/创意性↑ |
| `T → ∞` | 差距被抹平 | 趋近**均匀分布** | → max | 完全乱码 |

**加分点**：
- 「温度」这个名字来自统计物理的 **玻尔兹曼分布 / 吉布斯分布** $\exp(-E/kT)$，Softmax 就是它的形式，高温=系统混乱度高。
- **温度是单调变换，不改变 token 的排序**（T>0 时），只改变彼此差距。所以 Greedy 解码下调温度是**无意义**的——这是一道高频陷阱题。
- 与 **知识蒸馏（Hinton）** 同源：蒸馏用高温软化 teacher 输出得到 **soft target**，暴露类间的「暗知识」。

### 2.3 第三步：Top-k（突出操作细节）

**Top-k** 是一种**截断采样（Truncated Sampling）**策略，三步走：

1. **排序取前 k**：对全词表 token 按概率（等价于按 Logits）从高到低排序，保留前 k 个候选集；
2. **掩码（Masking）**：把排名 k 之外的 token 的 Logits 直接置为**负无穷（-inf）**，物理上屏蔽极低概率的噪声词；
3. **重归一化（Renormalization）**：对保留的 k 个 token 重新归一化，使概率和回到 1，然后再采样。

> **第 3 步是这题的核心区分点**。只说「取前 k 个」和说「取前 k 个 → 置 -inf → 重归一化后采样」，专业度完全不同。

**边界值**：`k = 1` 等价于 **Greedy**；`k = 词表大小` 等价于不截断（纯温度采样）。工程常用 `k = 40 ~ 50`。

### 2.4 第四步：协同机制与执行顺序

**HuggingFace Transformers / vLLM 的 `LogitsProcessor` 链路顺序**：

```
Logits → [重复惩罚] → [温度缩放] → [Top-k 过滤] → [Top-p 过滤] → Softmax → 采样
```

**分工**：
- **Top-k 负责硬截断（Hard Truncation）**：强行剔除「绝对不合理」的候选词，防止在长尾上抽到导致语义崩塌的 token；
- **温度负责软调节（Soft Scaling）**：精细调整剩余候选词的选拔激烈程度。

**高阶加分点（顺序的真相）**：
- **温度与 Top-k 的先后在数学上等价**。因为温度是单调变换，不改变排序 → 不改变 Top-k 选出的候选集；且 $\frac{\exp(z_i/T)}{\sum_{j \in K}\exp(z_j/T)}$ 无论先除 T 还是先截断都一样。
- **但温度与 Top-p 的先后至关重要**。Top-p 依赖**具体概率值**累加到阈值，而温度会改变概率值：高温使分布变平 → 累积到 p 需要更多 token → **Top-p 保留的候选集变大**。所以「先温度后 Top-p」和反过来结果不同。

> 能主动指出「温度和 Top-k 换序无影响、和 Top-p 换序有影响」，是这题的天花板级回答。

### 2.5 第五步：主动暴露 Top-k 的缺陷（辩证思维）

> 「Top-k 的 k 是**静态（Static）**的，而真实分布的形态是逐 token 变化的：
> - 分布**平缓**时（模型很不确定），第 k 个词概率仍然可观，强行截断会**丢失合理候选**；
> - 分布**尖锐**时（模型很确定），第 2 个词可能已经毫无概率，保留到第 k 个反而**引入噪声**。
>
> 所以现在主流改用 **Top-p（核采样，Nucleus Sampling）** 做**动态截断**：按累积概率达到 p 来决定候选集大小，候选集会随分布形态自适应伸缩。」

## 三、关键术语清单（黑话库）

| 类别 | 关键术语 | 使用场景 |
|---|---|---|
| **底层操作** | **Logits（未归一化分数）**、**Softmax** | 强调你懂温度作用在哪个环节，而非「调概率」 |
| **分布形态** | **锐度（Sharpness）** / **平滑（Flatter）**、**熵（Entropy）** | 高温=熵大=混乱；低温=熵小=确定 |
| **筛选机制** | **截断（Truncation）**、**掩码（Masking，置 -inf）**、**重归一化（Renormalization）** | Top-k 区别于「取前几个」的最核心专业点 |
| **总体策略** | **确定性（Deterministic）** vs **随机性（Stochastic）**、**采样空间（Sampling Space）** | 体现宏观理解 |
| **对照概念** | **Greedy Search**、**Beam Search**、**Top-p / Nucleus Sampling** | 证明你知道解码策略的全貌 |

## 四、30 秒速答版

> 这两个都是**推理阶段的解码参数**，不改模型权重，只作用在最后一层输出的**概率分布**上。
>
> **温度**是在 **Softmax 之前对 Logits 做缩放**，本质是控制分布的**锐度**。T 小于 1 会放大高低分之间的差距，分布更尖锐、更确定；T 大于 1 压缩差距、分布更平，尾部词有机会被采到，随机性更强；T 等于 0 就等价于**贪心解码**。
>
> **Top-k** 是**截断采样**：先按概率排序保留前 k 个，把其余 token 的 Logits **置成负无穷做掩码**，然后对剩下的 k 个**重新归一化**再采样。
>
> 两者配合就是 **Top-k 做硬截断剔掉不合理的词，温度做软调节控制剩下这些词的竞争激烈程度**。Top-k 的问题是 k 是静态的，不适应分布形态变化，所以现在更常用 **Top-p 核采样**做动态截断。

## 五、对方可能追问的问题

### 5.1 顺着温度追（概率最高）

| 追问 | 答题要点 |
|---|---|
| 写出温度的公式 | $p_i = \exp(z_i/T) / \sum_j \exp(z_j/T)$，**除**以 T，作用在 Logits 上不是概率上 |
| T=0 在代码里怎么处理？ | 数学上除零，工程上框架**特殊分支 fallback 到 argmax**（HF 会直接报错并提示改用 `do_sample=False`），不是真的算 0 |
| 温度会改变 token 的排序吗？ | ❌ **不会**。T>0 是单调变换，argmax 不变。推论：**Greedy 下调温度完全无效** |
| 那温度和 Top-k 谁先执行有区别吗？ | **没有区别**（见 2.4 推导）。但**和 Top-p 有区别**，因为 Top-p 依赖概率绝对值 |
| 温度和熵的定量关系？ | T↑ → 分布趋均匀 → **熵单调增**；T→0 熵→0，T→∞ 熵→log(V)。可用「熵」代替「随机性」显得更专业 |
| 温度能大于 2 吗？ | 数学上可以，但基本输出乱码；OpenAI 等 API 通常限制 `0 ~ 2` |
| 为什么叫「温度」？ | 源自统计物理 **玻尔兹曼/吉布斯分布** $\exp(-E/kT)$，Softmax 同形，温度高则系统混乱 |
| 温度还在别的地方用过吗？ | **知识蒸馏**：高温软化 teacher logits 得到 soft target，传递类间相似性（暗知识）；**对比学习**里的温度系数也是同一思想 |
| 调低温度能让模型更"准确"吗？ | ⚠️ 陷阱。**不能提升知识上限**，只是更倾向高概率 token，能减少「偶发抽到坏 token」；但对需要探索的任务（如 **Self-Consistency CoT 多路径投票**）低温反而**有害**，因为采不出多样路径 |

### 5.2 顺着 Top-k / 采样策略追

| 追问 | 答题要点 |
|---|---|
| Top-k 和 Top-p 的区别？ | Top-k **静态固定个数**；Top-p **动态**，按累积概率 ≥ p 决定候选数，候选集随分布锐度自适应伸缩 |
| 为什么必须重归一化？ | 截断后剩余概率和 < 1，不归一化就不是合法概率分布，无法做多项式采样 |
| Top-k 是按概率还是按 Logits 排序？ | **等价**，Softmax 单调递增，两者排序结果相同。实现上直接对 Logits 做 `topk` 更省一次 Softmax |
| Top-k 和 Top-p 同时设置会怎样？ | 串行过滤，**取交集**（HF 顺序：先 Top-k 再 Top-p）。所以同时设会更严格 |
| 除了 Top-k/Top-p 还有什么采样？ | **min-p**（按最高概率的比例设阈值，比 Top-p 更鲁棒）、**typical sampling**（按局部熵挑）、**tail-free / eta sampling**、**Mirostat**（目标困惑度反馈控制） |
| 怎么解决重复啰嗦？ | 采样参数解决不了根因，要用 **repetition_penalty**、**presence / frequency_penalty**、**no_repeat_ngram_size** |
| Beam Search 和采样什么关系？ | Beam 是**确定性搜索**，维护 num_beams 条路径按累积对数概率择优，适合翻译/摘要这类有「正确答案」的任务；采样是**随机生成**，适合开放式创作。两者可组合（beam sample）但少用 |
| Greedy 是 Top-k 还是 Top-p 的特例？ | 都是：`k=1` 或 `p→0`，也等价于 `T→0` |

### 5.3 顺着工程落地追（最容易露馅）

| 追问 | 答题要点 |
|---|---|
| 你项目里怎么设的？为什么？ | 必须有**具体理由**：RAG/工具调用/JSON 输出 → `T=0~0.2` 保稳定可复现；对话 → `T≈0.7, top_p=0.9`；创意写作 → `T=0.9~1.2`；代码 → 低温；数学推理若要 Self-Consistency 投票则**反而要高温 + 多次采样** |
| 为什么 Agent / RAG 场景建议低温？ | ①减少幻觉式外推 ②保证 JSON / 函数调用格式**结构稳定** ③结果可复现便于回归测试与评测 |
| **T=0 就一定 100% 可复现吗？** | ❌ **不一定**——这是最强加分点。原因：GPU 浮点**归约顺序不确定**、**batch size 变化导致 kernel 分块策略变化**（batch invariance 问题）、MoE 模型的专家路由受同 batch 其他请求影响。所以还需要 `seed`，而且跨硬件/跨 batch 仍可能不一致 |
| 这些参数影响推理性能吗？ | 基本不影响。只是对 Logits 做 O(V) 的算术和 topk，相比 Transformer 前向可忽略；但 **batch 内每条序列采样参数不同** 时需要逐序列处理，会带来一点实现复杂度 |
| 和 KV Cache 有关系吗？ | 采样参数**不影响 KV Cache 结构**，它只作用在最后一步 Logits；但采样出的 token 不同 → 后续 KV 不同 → 无法跨不同采样结果复用 |
| 返回的 logprobs 是温度前还是温度后的？ | 通常是**采样处理后**的分布（各家 API 略有差异），做置信度评估时要注意：低温会人为拉高 top-1 的 logprob，**不能直接当模型真实置信度** |
| 和结构化输出 / JSON Schema 什么关系？ | **约束解码（Constrained Decoding，如 grammar / outlines / xgrammar）** 本质就是 Top-k 掩码思想的极端形式——按语法把所有非法 token 置 -inf，是「硬截断」的推广 |
| 和投机解码（Speculative Decoding）有关系吗？ | 有。采样温度影响 draft 与 target 分布的差异，从而影响**接受率**；温度越高分布越平，验证时的接受概率通常越低，加速比下降 |

### 5.4 高频陷阱题速记

1. **「温度作用在 Softmax 之前还是之后？」** → **之前**，除的是 Logits。若在 Softmax 之后对概率除以 T，那还得重新归一化，且效果不等价。
2. **「温度会改变最可能的那个 token 吗？」** → **不会**，单调变换不改排序。
3. **「T=0 输出就完全确定了吗？」** → **不一定**，见 5.3 的浮点非确定性。
4. **「Top-k 是不是只是取概率最高的 k 个就完了？」** → 还有 **-inf 掩码 + 重归一化** 两步。
5. **「温度能解决幻觉吗？」** → **不能**。幻觉根因在训练数据与知识边界；低温只能减少「长尾乱采样」造成的偶发错误，属于治标。
6. **「Top-k 越大越好吗？」** → 不是。k 过大等于不截断，长尾噪声回流；k 过小丢失合理候选、输出趋于呆板。

> **原笔记勘误**：早期版本称「Temperature 不能为 0，否则会破坏随机采样的 CUDA kernel 并行性」——这个说法不准确。真实原因是**数学上除零**，框架据此走 argmax 分支或直接报错；与 kernel 并行性无关。面试中不要这样讲，容易被追问穿。
