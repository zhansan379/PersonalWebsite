## 常量池（Constant Pool）

> 来源：B站「基础篇-4-字节码文件的组成-常量池和方法」（BV1r94y1b7eS）

### 1. 作用：避免重复定义、节省空间

常量池存放常量、类/接口名、字段名、方法名等。核心作用是**避免相同内容重复定义**。

- 例：源代码中两个相同字符串「我爱北京天安门」，编译后的字节码**只存一份**，其余地方用编号引用它；
- 如果复制 100 次，没有常量池就会让字节码文件庞大、读取变慢。

### 2. 引用机制（编号 + 间接引用）

常量池每一项有**编号，从 1 开始**：

- 字段的 `constant value` 属性存放的是**常量池索引**（如 #8），而不是值本身；
- #8 是 `String` 类型常量，但它**不直接存放字面量**，而是再指向另一个常量（如 #27，UTF8 类型）——那才是真正的字符串「我爱北京天安门」。

**为什么要这一层间接引用（#8 → #27）？**

1. **必须保留 String 类型常量**：字节码被解析加载后，需要把 `String` 类型常量池中的内容加载到运行时的**字符串常量池**，所以要有 `String` 类型标识；
2. **必须保留 UTF8 字面量**：字面量不止用于字符串，还可能用作**字段名**。例如字段名 `ABC` 和字符串 `"ABC"` 会引用同一个 UTF8 字面量（如 #10），字段名不是字符串对象，不能只用 `String` 常量表达。

### 3. 符号引用

字段和字节码指令通过**编号**引用常量池中的内容，这一过程统称为**符号引用**。

## 方法（Methods）

### 1. 方法体 = 字节码指令

源代码中方法体被编译成一行行**字节码指令**（存于方法的 `code` 属性），重点就是理解每条指令做了什么。

### 2. 两块内存区域

| 区域 | 作用 | 说明 |
|---|---|---|
| **操作数栈**（Operand Stack） | 临时存放数据 | LIFO（先进后出）。如 `1+2`：两个操作数入栈 → `iadd` 把栈顶两个值相加 → 结果放回栈 |
| **局部变量表**（Local Variables） | 存放方法内局部变量 | 底层是数组。下标 0 通常是方法参数（如 `main` 的 `args`），之后按声明顺序排列（如 1→`i`、2→`j`） |

### 3. 核心指令

| 指令 | 作用 |
|---|---|
| `iconst_<n>` | 将常量 `n` 放入操作数栈 |
| `istore_<n>` | 将操作数栈顶的值**弹出**，存入局部变量表下标 `n` 位置 |
| `iload_<n>` | 将局部变量表下标 `n` 的值**复制**一份放入操作数栈 |
| `iadd` | 将操作数栈最上面两个值相加，结果放回栈 |
| `iinc <index>, <const>` | 直接对局部变量表指定位置的值增加 `const`（**不经过操作数栈**） |

注意：
- `istore` 是**弹出**（栈中数据消失）；`iload` 是**复制**（两边都有数据）；
- 大多数算术发生在操作数栈上；`iinc` 是例外——直接在局部变量表上累加。

### 4. 面试题：`int i = 0; i = i++;` 最终 `i` 是多少？

**答案：0**（通过字节码指令分析）

| 步骤 | 指令 | 效果 |
|---|---|---|
| 1 | `iconst_0` | 0 入栈 |
| 2 | `istore_1` | 0 存入局部变量表[1] → `i = 0` |
| 3 | `iload_1` | 把 `i` 的旧值 **0 复制**到操作数栈（临时保存） |
| 4 | `iinc 1, 1` | 局部变量表[1] 直接 +1 → **`i` 已变为 1** |
| 5 | `istore_1` | 把操作数栈里的**旧值 0** 存回局部变量表[1] → **覆盖，`i` 回到 0** |

**关键点**：`i++` 先把旧值临时放到操作数栈，再对局部变量表中的 `i` 加一；最后赋值用的是操作数栈里的**旧值**，把加一结果**覆盖掉了**。

**对比 `++i`**：`++i` 是先 `iinc 1, 1`（`i` 变 1）再 `iload_1`（加载 1 入栈），赋值后仍为 1。两者本质区别就是 **`iinc` 与 `iload` 的执行顺序颠倒**。

### 5. 练习题

对比 `i++`、`j = j + 1`、`k += 1` 三种「加一」写法编译后的字节码指令条数——一般**指令条数越多，操作性能相对越低**。
