# 程序计数器

> 程序计数器（PC 寄存器）是运行时数据区中「线程不共享」的一块内存，每个线程独有一份，存放**接下来要执行的字节码指令的内存地址**。它控制解释器执行指令的顺序，并在多线程切换时保存执行进度；因只保存固定长度的内存地址，**不会发生内存溢出**。

## 一、运行时数据区总览（背景）

![[Pasted image 20260808221132.png]]
- Java 虚拟机按是否共享分为两大类：

| 类别        | 包含区域                  | 特点                                               |
| --------- | --------------------- | ------------------------------------------------ |
| **线程不共享** | 程序计数器、Java 虚拟机栈、本地方法栈 | 每个线程独有一份，数据自己维护，别的线程无法访问 → 安全性较高；线程结束随之回收、内存得到释放 |
| **线程共享**  | 方法区、堆                 | 任何线程都可放入/获取数据 → 存在**线程安全问题**，使用需注意               |

## 二、学习动机与应用场景

- **解决面试难题**：
  1. Java 内存分成哪几部分（JVM 高频考题）；
  2. 哪些部分会内存溢出；
  3. JDK6 / 7 / 8 的内存结构区别（面试官较关注）。
- **解决工作中的内存问题**：内存占用标高（如监控图显示 69.3%）需定位解决；运行中直接抛 `OutOfMemory` 会导致程序终止。
- **内存调优学习路线**（类比中医「望闻问切」四诊 → 对症下药）：
  1. **确定程序中哪一部分内存出现问题** —— 需要了解每一块内存的结构，并通过专业工具定位；
  2. **掌握内存问题的常见原因** —— 对照工作中遇到的问题是否由此导致；
  3. **再去解决对应的问题**。

## 三、程序计数器（PC 寄存器）

### 1. 定义与归属

- 又叫 **PC 寄存器**，属于**线程不共享**区域，每个线程独有一份；
- 存放内容：**接下来要执行的字节码指令的内存地址**。

### 2. 为什么需要它

- 字节码指令最初保存在字节码文件中，类加载器读取到内存后，每一行指令都对应一个内存地址；
- 字节码指令最终交给**解释器**解释执行，解释器必须知道要执行的指令在哪儿 → 向程序计数器索要地址，即可拿到对应指令执行。

### 3. 工作流程（案例）

源码 `int i = 0; if (i == 0) { i--; } i++;` 编译后的字节码：

| 指令 | 作用 |
|---|---|
| `iconst_0` / `istore_1` | 局部变量 `i` 赋值为 0 |
| `iload_1` | 取出局部变量 `i` 的值（0）放入操作数栈 |
| `ifne` | 把操作数栈中的值与 0 比较：**不相等**继续往下（第 6 行），**相等**跳转第 9 行。当前栈值为 0 → 与 0 相等 → 执行 `i--`（第 6 行）→ 再执行 `i++`（第 9 行） |

加载到内存后的执行过程：
- 字节码文件中每条指令前的**偏移量**（0、1、2、3…，指令长度不一，如 `ifne` 占 3 个位置）会被替换成**内存地址**；
- 解释器执行前，程序计数器保存**当前指令的内存地址**（视频中为直观展示用偏移量替代，但 JVM 实际保存的是内存地址）；
- 每执行完一行，程序计数器刷新为**下一行指令的地址**：`0 → 1 → 2 → 3 → 6 → 9 → 12`，直至方法执行结束；
- **程序计数器中永远保存「接下来要执行的字节码指令的地址」**。

### 4. 实现复杂逻辑

通过修改程序计数器中保存的地址，可实现相对复杂的逻辑：
- **if 分支**：`i == 0` 判断后，把程序计数器内容改为偏移量 6 对应的地址；若 `i != 0` 则改为偏移量 9 对应的地址；
- **跳转、异常**等逻辑同理。

## 四、程序计数器的两个作用

1. **控制解释器执行指令的顺序**：解释器依据程序计数器中的地址找到下一条要执行的指令；
2. **多线程切换时保存执行进度**：CPU 不会盯着一个线程执行，而是在多个线程间来回切换。切回某线程时，只需从它的程序计数器中取出「接下来要执行的指令地址」，即可恢复执行。

## 五、会不会内存溢出？

**不会。**

- **内存溢出** = 程序在某块内存区域存放数据占用的内存超过了虚拟机提供的上限（如上限 1 兆、却要放 2 兆数据）；
- 程序计数器只保存一个**固定长度的内存地址**（如 64 位系统一般为 8 字节），长度固定不变 → 自然**不会发生内存溢出**；
- 程序员**无需对程序计数器做任何处理**，一切由 JVM 自己掌控；了解该知识点主要是为了在面试中回答相关题目。
