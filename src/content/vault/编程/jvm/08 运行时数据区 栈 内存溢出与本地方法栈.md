# 栈 · 内存溢出与本地方法栈

> 每个线程的虚拟机栈**空间有限**，栈帧不断入栈会触及上限，抛出 `StackOverflowError` 并终止该线程。栈大小由 `-Xss` 控制（默认约 1MB，取决于操作系统与体系结构），受 HotSpot 最小/最大值约束；单个栈帧越大（局部变量多、操作数栈深）能容纳的栈帧数越少。本地方法栈在 HotSpot 中与虚拟机栈**共用同一块栈空间**。

> 来源：B站「基础篇-21-栈-内存溢出」（BV1r94y1b7eS）

## 一、结论：虚拟机栈会发生内存溢出

对 Java 虚拟机来说，**每个栈的空间是有限的**。如果占用的内存超过了虚拟机为栈分配的最大内存，就会发生内存溢出。

溢出的过程：

```
线程 A 的虚拟机栈（有上限）
  ┌──────────┐  ← 栈的上限
  │  栈帧 n  │
  │   ...    │   栈帧一个一个往里放
  │  栈帧 2  │
  │  栈帧 1  │
  └──────────┘
栈已满，再放入下一个栈帧 → StackOverflowError
```

两个后果：

| 后果 | 说明 |
|---|---|
| 抛出 `StackOverflowError` | 虚拟机提示给开发人员的错误信息 |
| **该线程停止执行** | 所以这个错误相对来说是比较严重的 |

> **补充（规范层面的准确说法）**：《Java 虚拟机规范》为虚拟机栈定义了两种异常 —— 栈深度超过限制抛 `StackOverflowError`；栈动态扩展时申请不到足够内存抛 `OutOfMemoryError`。**HotSpot 的栈容量不支持动态扩展**，所以实际开发中遇到的基本都是 `StackOverflowError`。另外注意 `StackOverflowError` 是 `Error` 而非 `Exception`。

## 二、栈的默认大小是多少

虚拟机创建虚拟机栈时会分配一个默认大小，也就是它的上限。这个上限**取决于操作系统和计算机的体系结构**。

以 OpenJDK 8 虚拟机源码为例：

| 操作系统 | 体系结构 | 默认栈大小 |
|---|---|---|
| Linux | x86（64 位） | **1024 KB（1 MB）** |
| macOS | 64 位 | 1024 KB |
| **Windows** | — | **不固定，基于操作系统的默认值** |

所以不同的 Windows 操作系统，这个默认值有可能不相同 —— 需要用代码实测。

## 三、代码验证：一兆的栈能放多少个栈帧

### 3.1 测试思路

```java
public class StackOverflowTest {
    private static int count = 0;          // 静态变量，存放栈帧数量

    public static void recursion() {
        count++;                            // 进入方法即累加，代表本次方法要执行了
        System.out.println(count);          // 方法执行多少次就打印多少次
        recursion();                        // 递归调用自身，且没有退出条件
    }

    public static void main(String[] args) {
        recursion();
    }
}
```

设计要点：递归调用自身且**不设退出条件**，栈帧会一个一个放进栈内存并且不会退出，无限递归下去。最终溢出时，**看最后一次打印出的 `count` 值**，就知道这个栈里到底能存放多少个栈帧。

### 3.2 Debug 观察入栈过程

在方法内下断点逐次放行，可以看到：

- 第一次进入：栈里出现 1 个栈帧，控制台打印 `1`
- 再次放行：因为递归调用了自己，第二个栈帧入栈，控制台打印 `2`
- 多点几次：栈帧一直往上累加，控制台同步打印对应数量

### 3.3 运行结果

去掉断点直接放行，**程序自动退出了** —— 按正常来说不该退出，因为没有设置递归退出条件，应该无限递归。往下翻日志可以看到：

```
...
10684
Exception in thread "main" java.lang.StackOverflowError
```

执行到 **10684** 次，下一次（第 10685 次）抛出 `StackOverflowError`。说明栈在 10684 个栈帧之后已经充满了整个栈空间，再放入下一个栈帧时栈空间不足，抛出错误 —— **验证了栈空间确实有上限**。

> **重要提醒**：这样的代码在公司项目中是不可能出现的。一般项目里虚拟机栈的深度达到**几十上百都属于正常情况**。如果栈帧深度达到 1 万多，只可能是**编写递归代码时没有正确设置递归退出条件**，导致栈深度一直增长直到上限。
>
> 所以可以认为：虚拟机给的栈内存上限其实设置得**比较大**，一般用不到这么大的值。

## 四、用 -Xss 设置栈的最大大小

### 4.1 语法与单位

Java 虚拟机参数 `-Xss` 用于设置虚拟机栈的最大大小：

```
-Xss栈大小[单位]
```

| 写法 | 单位 | 说明 |
|---|---|---|
| `-Xss1048576` | **字节**（不写单位时的默认） | 不直观；且**值必须是 1024 的倍数**，否则虚拟机启动过程中就会报错。一般不用 |
| `-Xss1024k` / `-Xss1024K` | KB | **工作中最常用**，1024K = 1MB |
| `-Xss1m` / `-Xss1M` | MB | 设置出来的栈内存偏大，很少用 |
| `-Xss1g` / `-Xss1G` | GB | 过大，几乎不用 |

### 4.2 在 IDEA 中配置

`Run/Debug Configurations` → `Modify options` → 添加 `Add VM options` → 在 VM options 中输入 `-Xss1024k`。

### 4.3 两组对比实验

| 设置 | 栈帧数量 | 说明 |
|---|---|---|
| 不设置（默认） | 10684 | Windows 默认由操作系统决定 |
| `-Xss1024k` | ≈ 10684，几乎没变化 | 反推出 **Windows 上的默认值基本就等于 1024K（1MB）** |
| `-Xss512k` | 5200 多，**约为原来的一半** | 证明参数确实生效，栈空间减半则栈帧数减半 |

## 五、三个注意事项

### 5.1 还可以用 -XX:ThreadStackSize

```
-XX:ThreadStackSize=1024k
```

格式与 `-Xss` 类似，但**需要加一个等号**再连接值和单位。这种写法整体过于复杂，**建议还是用 `-Xss`**。

### 5.2 HotSpot 对栈大小有最小值和最大值要求

不是可以随意设置的。以 **JDK 8** 为例：

| 边界 | 限制 |
|---|---|
| 最小值 | 必须**大于 180K** |
| 最大值 | 不能**超过 1024M** |

超出这个范围，**Java 虚拟机会做出自动调整**，你设置的值等于失效。

实测验证：设置 `-Xss1k`（远小于 180K）后运行，栈帧数量是 **10701 次**，与设置 `1024k` 时基本相同 —— 说明 `1k` 这个设置已经失效，被虚拟机自动调整了。同理设置 `1025m`（超过 1024M）也会失效。

### 5.3 单个栈帧的大小会影响栈帧总数

如果一个方法中**局部变量特别多**，或者**操作数栈的深度很大**，栈内存能容纳的栈帧数量就会受影响。

实测（`-Xss1024k` 不变，在递归方法中声明多个 `long` 类型局部变量）：

| 方法内容 | 栈帧数量 |
|---|---|
| 原始方法 | ≈ 10000 |
| 声明多个 long 局部变量后 | **8500** |

原因：**总的栈空间没有变**，但每一个栈帧包含的数据量变大了，占用内存自然变多，所以能放的数量就下降了。

> 这一点与 [[编程/jvm/06 运行时数据区 栈 局部变量表]] 中「局部变量表按槽分配、`long`/`double` 占 2 个槽」的内容直接呼应 —— 槽越多，栈帧越大。

## 六、工作中怎么设置

一般情况下，工作中即便出现了递归操作，**栈的深度顶多也就是几百**，正常情况下不会出现栈的溢出。

所以可以通过 `-Xss` 给它设置一个相对比较小的值，**节省一定的内存**。

> **建议值：`-Xss256k`**

> **补充（为什么省内存这件事值得做）**：`-Xss` 是**每个线程**的栈大小，而不是全局共享的一块。所以在线程数很多的服务里（比如几百个线程），把每个线程的栈从 1MB 调到 256K，节省的总内存是 **线程数 × 768K**，量级相当可观。这也是为什么高并发服务会关注这个参数。

## 七、本地方法栈

### 7.1 与虚拟机栈的分工

| 栈 | 存放什么 |
|---|---|
| Java 虚拟机栈 | Java 语言编写的方法调用时的栈帧 |
| **本地方法栈** | 使用 **C++ 编写的 `native` 本地方法**的栈帧 |

整体来说，处理思路以及栈帧中存放的数据都是类似的。

### 7.2 HotSpot 中两者共用同一块栈空间

在 HotSpot 虚拟机中，Java 虚拟机栈和本地方法栈**存放在同一个栈空间**里 —— 栈内存中既可以有 Java 方法的栈帧，也可以有 native 方法的栈帧。

因此当方法抛出异常时，**本地方法的栈信息也一样会被打印出来**。

### 7.3 异常栈轨迹演示

```java
// E 盘下的 123.txt 并不存在，必然抛出异常
FileOutputStream fos = new FileOutputStream("E:\\123.txt");
fos.write(1);
```

打印出的异常栈轨迹中：

- **第一行就是 `native method`**，也就是本地方法栈的栈帧
- 底下的几个方法都属于 Java 的栈信息

另一个可观察的区别：Java 中实现的方法，可以**鼠标左键点击跳到源代码**找到出处；而**本地方法点进去找不到源代码**，因为源码位于虚拟机内部的 C++ 代码中。

### 7.4 掌握程度

本地方法栈**仅需了解**即可，因为底层会有虚拟机去处理这部分内容。

核心记忆点：

1. 栈**有上限**，栈帧放满就抛 `StackOverflowError`，**线程终止**
2. 默认约 **1MB**，取决于操作系统与体系结构；Windows 由操作系统决定
