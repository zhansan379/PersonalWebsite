# 栈 · 操作数栈与帧数据

> 栈帧三大组成中的后两部分：操作数栈存放字节码指令执行过程中的**中间数据**（最大深度在编译期确定）；帧数据存放**动态链接、方法出口、异常表**，是虚拟机为执行方法而准备的"辅助信息"。

> 来源：B站「基础篇-20-栈-操作数栈和帧数据」（BV1r94y1b7eS）

## 一、栈帧的三大组成（回顾）

Java 虚拟机栈中每个栈帧由三部分组成：

| 组成 | 作用 | 说明 |
|---|---|---|
| 局部变量表 | 运行过程中存放所有**局部变量**，以及**方法参数**和实例方法的 **this 对象** | 详见 [[编程/jvm/06 运行时数据区 栈 局部变量表]] |
| 操作数栈 | 存放字节码指令执行过程中的**临时/中间数据** | 本页第二节 |
| 帧数据 | 动态链接、方法出口、异常表 | 本页第三节 |

## 二、操作数栈

### 2.1 是什么

- 是一种**栈式结构**（先进后出），用来存放**临时数据**。
- 字节码指令执行时，常常先把一个常量或变量值**压入操作数栈**，再由下一条指令**从栈中取出**，放入局部变量表或参与运算。
- 所以它承担的角色是「指令之间传递数据的中转站」，存放的是**中间数据**。

### 2.2 最大深度在编译期就已确定

操作数栈需要分配多大空间？**编译时**就能确定其**最大深度**，并写入字节码文件。

编译器的做法是：**模拟执行一遍**该方法的所有字节码指令，记录操作数栈中同时存在的数据的最大数量，这个数量就是最大深度。

### 2.3 案例推演

源代码（实例方法，故局部变量表 0 号位置被 this 占用）：

```java
int i = 0;
int j = i + 1;
```

逐条执行字节码，观察操作数栈的变化：

| 步骤 | 字节码指令 | 动作 | 执行后操作数栈 | 局部变量表 |
|---|---|---|---|---|
| 1 | `iconst_0` | 将常量 0 压入操作数栈 | `[0]`（1 个） | 0: this |
| 2 | `istore_1` | 弹出栈顶 0，存入 1 号位置（`i`） | `[]` | 0: this, 1: i=0 |
| 3 | `iload_1` | 取出 1 号位置的值压栈 | `[0]` | — |
| 4 | `iconst_1` | 将常量 1 压栈 | `[0, 1]`（**2 个，峰值**） | — |
| 5 | `iadd` | 弹出栈顶两个数相加，结果再压回栈 | `[1]` | — |
| 6 | `istore_2` | 弹出栈顶 1，存入 2 号位置（`j`） | `[]` | 0: this, 1: i, 2: j=1 |
| 7 | `return` | 方法结束 | `[]` | — |

**结论**：整个过程中操作数栈最多同时存放 **2 个数据**（`iconst_1` 执行后的 0 和 1），因此该方法的操作数栈最大深度 = **2**。创建栈帧时只需分配深度为 2 的操作数栈，内存分配比较合理。

> 对程序员来说，操作数栈**了解即可**：知道它是栈式结构、用于存放字节码指令执行过程中的中间数据。

## 三、帧数据

### 3.1 与前两者的区别

- 局部变量表和操作数栈：基本上**每个虚拟机都按虚拟机规范实现**，结构一致。
- 帧数据：**各虚拟机可以往里添加自己需要的数据**，实现不统一。因此这里只介绍最核心的三部分：**动态链接、方法出口、异常表**。

### 3.2 动态链接

**背景**：类的生命周期中，**连接阶段**会把字节码指令中的编号（**符号引用**）转换为内存地址的**直接引用**。但如果字节码指令要访问**其他类**的方法或属性，这个符号引用**不会在连接阶段被解析为直接引用**。

**例子**：偏移量 12 处的 `getstatic #x` 指令，作用是获取某个类的静态变量——这里获取的是 `System` 类的静态变量 `out`，用来做打印工作。由于访问的是**其他类**的属性，编号在连接阶段不会变成直接引用。

**做法**：Java 虚拟机在执行该方法的字节码指令**之前**，在栈帧中保存「`#x` 这个符号引用 → 运行时常量池中 `System` 类的引用关系」。执行到这行指令时，只需从动态链接中取出对应的内存地址，就能找到 `System` 类，进而获取其静态变量。

**总结**：

- **是什么**：符号引用到当前**运行时常量池**内存地址的**映射关系**。
- **存什么**：主要是**其他类的属性或方法**的映射数据。
- **有什么用**：字节码指令执行过程中，可以根据符号引用**快速找到**运行时常量池中对应的数据。

### 3.3 方法出口

**问题**：当前方法（如 `sleep`）执行结束后，它的栈帧会弹出栈。但[[编程/jvm/05 运行时数据区 程序计数器|程序计数器]]中记录的是"接下来要执行的指令地址"——栈帧一弹出，程序计数器应该指向哪里？

自然是指向调用者（`study` 方法）中的**下一行指令**。但虚拟机并不知道 `study` 方法之前执行到了哪一行。

**类比**：在公司同时并行推进两个任务，从任务一切换到任务二时，必须记录任务一执行到哪了，方便将来切回来时能继续完成。

**做法**：`sleep` 方法在**自己的栈帧中**保存了 `study` 方法下一行指令的地址；在自己的栈帧弹出之前，把这个地址交给程序计数器，程序就能正常继续运行。

**定义**：栈帧中存放的「上一个栈帧中下一条指令的地址」，就称为**方法出口**（返回地址）。

### 3.4 异常表

**是什么**：存放代码中的**异常处理信息**。编译阶段，如果代码中出现了异常捕获（try-catch），编译器会在把源代码编译成字节码文件的过程中，为该方法生成一张**异常表**。

**包含内容**：

1. 异常捕获的**生效范围**（起始 PC、结束 PC）；
2. 异常发生后**跳转到的字节码指令位置**；
3. 捕获的异常类型。

**案例解读**：

```java
int i = 0;
try {
    i = 1;
} catch (Exception e) {
    i = 2;
}
```

对照字节码指令：

| 偏移量 | 对应源代码 | 说明 |
|---|---|---|
| 0、1 | `int i = 0;` | 将局部变量表 0 号位置赋值为 0 |
| 2、3 | try 块中的 `i = 1;` | 赋值为 1 |
| 4 | try 正常结束 | `goto 10` |
| 7 | catch 块入口 | 将捕获到的**异常对象引用**存入局部变量表 **1 号位置** |
| 8、9 | catch 块中的 `i = 2;` | 赋值为 2 |
| 10 | 方法结束 | `return` |

- **起始 PC / 结束 PC**：指明异常捕获的生效范围。本例覆盖偏移量 **2、3、4** 这三行指令，即虚拟机只在这三行指令执行过程中捕获 `Exception`。
- **跳转位置**：捕获到异常后，直接跳转到偏移量 **7** 这一行指令继续执行。
- **异常对象入表**：偏移量 7 的指令把异常对象的引用放到局部变量表 1 号位置（0 号位置存的是 `i`），这样在 catch 代码块中就能使用这个异常对象。
- 如果 try 块**没有异常**，则执行偏移量 4 的 `goto 10` 直接 `return`，跳过 catch 块。

**作用**：通过异常表，Java 虚拟机能够在**一个指定范围**的字节码指令中捕获对应的异常；捕获到之后，也能知道应该**跳转到哪一行**字节码指令继续运行。异常表在异常处理过程中非常有用。

## 四、小结

到这里，Java 虚拟机栈栈帧的三大组成部分——**局部变量表、操作数栈、帧数据**——已全部介绍完毕。

- 对程序员而言，这部分内容**以了解为主**；
- 但了解之后，对「Java 虚拟机在执行方法和字节码指令时到底做了哪些细节上的事」会有更深刻的印象。
