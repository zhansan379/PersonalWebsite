**工厂模式**是软件开发中最常用的**创建型设计模式**之一。它的核心思想是：**将对象的创建逻辑与使用逻辑分离**。简单来说，就是不让调用者直接用 `new` 关键字创建对象，而是通过一个“工厂”来生产对象。

这就好比你去餐厅点餐：你不需要知道厨师具体怎么买菜、切菜、炒菜（复杂的创建过程），你只需要告诉服务员（工厂）你要“宫保鸡丁”（参数），服务员就能给你端上来（返回对象）。

工厂模式通常分为三种形态，难度和复杂度依次递增：

### 1. 简单工厂（Simple Factory）—— 不属GoF经典模式，但最常用
由一个工厂类根据传入的参数，决定创建哪一种具体产品。

- **场景**：产品种类较少，且不经常变动。
- **例子**：一个手机工厂，你传入“Apple”返回iPhone，传入“Huawei”返回Mate。
- **缺点**：违反**开闭原则**（对扩展开放，对修改关闭）。如果新增“Xiaomi”手机，必须修改工厂类的内部代码。

### 2. 工厂方法模式（Factory Method）—— GoF经典模式
定义一个创建对象的抽象接口（或抽象类），但让**子类**来决定实例化哪一个具体类。工厂方法把实例化操作推迟到子类中。

- **场景**：产品种类增多，且不同产品需要不同的创建逻辑。
- **例子**：定义抽象接口 `PhoneFactory`，`AppleFactory` 实现它并生产 iPhone，`HuaweiFactory` 实现它并生产 Mate。客户端想要什么手机，就实例化对应的工厂子类。
- **优点**：新增产品时，只需新增工厂子类，无需修改现有代码，符合开闭原则。

### 3. 抽象工厂模式（Abstract Factory）—— GoF经典模式
这是最复杂的形态。它用于创建**产品族**（一系列相关或相互依赖的对象），而不是单一产品。

- **场景**：需要切换整个产品系列（如换皮肤、换操作系统主题）。
- **例子**：UI 组件库。一个现代风格工厂会生产 `现代按钮` + `现代滚动条`；一个复古风格工厂会生产 `复古按钮` + `复古滚动条`。客户端代码无需改动，只需切换工厂，整套 UI 风格就全变了。

### 为什么要用工厂模式？（优缺点）

**优点（价值所在）：**

1. **解耦**：调用方只依赖接口/抽象类，不依赖具体实现，替换起来极其方便。
2. **统一管理**：如果对象的创建过程很复杂（如需要依赖配置、连接池、缓存等），集中在工厂里管理，避免代码散落各处。
3. **提升可维护性**：修改某个产品的创建细节时，开发者只需要去对应的工厂类中修改，影响范围可控。

**缺点（代价）：**

1. **增加复杂度**：引入大量新类（工厂类），代码结构变复杂。
2. **增加抽象难度**：如果滥用工厂模式，尤其是在产品结构很简单的情况下（只需要 `new` 一下），会过度设计，让代码变得难以阅读。

### 举个最经典的代码示例（Java风格）

假设你有一个支付系统，不直接用 `new Alipay()`：

```java
// 1. 定义接口
interface Payment {
    void pay();
}

// 2. 具体实现
class Alipay implements Payment {
    public void pay() { System.out.println("支付宝支付"); }
}
class WechatPay implements Payment {
    public void pay() { System.out.println("微信支付"); }
}

// 3. 工厂方法模式：定义工厂接口
interface PaymentFactory {
    Payment createPayment();
}

class AlipayFactory implements PaymentFactory {
    public Payment createPayment() { return new Alipay(); }
}
class WechatFactory implements PaymentFactory {
    public Payment createPayment() { return new WechatPay(); }
}

// 4. 客户端调用
public class Client {
    public static void main(String[] args) {
        PaymentFactory factory = new AlipayFactory(); // 只需改这一行即可切换支付方式
        Payment payment = factory.createPayment();
        payment.pay();
    }
}
```

### 什么时候该用，什么时候不该用？

- **该用**：当你发现代码里到处都是 `new` 某类对象，且这个类的构造参数很复杂；或者当你需要根据配置文件/条件动态决定生成哪种对象时。
- **不该用**：如果某个对象创建过程极其简单（就一个无参构造），且几乎不会变化，直接用 `new` 更清晰，没必要为了“设计模式”而硬套工厂。

**总结一句话**：工厂模式就是“**谁用谁不问，想换只换厂**”，它把创建对象的“脏活累活”封装起来，让业务逻辑代码更干净、更灵活。
