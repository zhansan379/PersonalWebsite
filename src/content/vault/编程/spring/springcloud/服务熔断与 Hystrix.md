# 服务熔断与 Hystrix

> **熔断**是应对**微服务雪崩效应**的一种链路保护机制，类比电路里的保险丝：当某个微服务不可用或响应超时，**暂时停止对它的调用**、快速返回错误，保护整个系统；恢复后自动放行。核心主线：**监测 → 阈值触发 → 快速失败 → 恢复。**

## 一、这是什么

回答"服务熔断"时，先用雪崩效应引入问题，再用保险丝类比讲机制，最后落到 Hystrix 的具体触发条件。

## 二、核心内容

### 2.1 为什么要熔断：雪崩效应

微服务间通过**远程调用**交互：

- 链路 `A → B → C`，某时刻对 C 的调用响应过长或不可用
- 随时间增长，对 C 的调用越来越多 → C 崩溃
- 但链路调用还在、对 B 的调用持续增多 → B 崩溃 → 最后 A 也崩溃
- **一个节点故障随着调用链逐级放大，拖垮整条链路，就是雪崩效应**

### 2.2 熔断机制（保险丝类比）

- 高压电路电压过高 → 熔断器熔断保护电路。
- 微服务同理：**当链路某微服务不可用或响应太长 → 熔断，不再调用该节点、快速返回错误响应**；检测到该节点恢复正常后 → 恢复调用链路。
- 一句话：**某服务不可用/超时时，为防止整个系统雪崩，暂时停止调用它**（快速失败）。

### 2.3 Spring Cloud 中的实现：Hystrix

Hystrix 监控微服务间的调用状况。**默认触发条件**（常考）：
- **10 秒滚动窗口**（`metrics.rollingStats.timeInMilliseconds=10000`）内
- **请求数达到 20 次**（`circuitBreaker.requestVolumeThreshold=20`）
- 且 **错误率超过 50%**（`circuitBreaker.errorThresholdPercentage=50%`）

同时满足时启动熔断。

### 2.4 熔断器三态

| 状态 | 行为 |
| :--- | :--- |
| **关闭（Closed）** | 正常，请求正常放行 |
| **打开（Open）** | 触发阈值，直接快速失败，**不再调用下游** |
| **半开（Half-Open）** | 过一段时间放**少量试探请求**，成功则关回 Closed，失败则保持/回到 Open |

> 补一句：为避免频繁抖动，熔断窗口期满后进入 Half-Open 试探恢复。

## 三、可能追问

1. 「熔断触发条件默认是什么？」→ 10s 窗口、20 次请求、50% 错误率
2. 「Hystrix 现在还用吗？替代方案？」→ Hystrix 已停更，替代为 **Resilience4j** 或 SpringCloud Alibaba 的 **Sentinel**
3. 「熔断、降级、限流三者的区别？」→ 熔断是下游故障时主动停调、降级是系统压力大时有损取舍、限流是控制流量速率（见 [[服务降级]]）
4. 「熔断和降级什么关系？」→ 熔断后通常伴随降级（返回 fallback 快速失败）
5. 「熔断恢复原理？」→ Open 后隔一段进入 Half-Open，试探成功即恢复 Closed
