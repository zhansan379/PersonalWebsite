# Spring 循环依赖与三级缓存

> 循环依赖 = A 依赖 B、B 又依赖 A 形成的闭环。**Spring 只解决"单例 + setter/字段注入"这一种**，靠 `DefaultSingletonBeanRegistry` 维护的**三级缓存**提前暴露半成品引用。核心考点：**为什么必须三级缓存、二级不行**——为了兼容 AOP 代理、避免破坏单例。

## 一、这是什么

Spring Bean 创建过程中，若两个 Bean 相互依赖，会形成"先有鸡还是先有蛋"的死结。Spring 用三级缓存 + 提前暴露未初始化对象引用的机制解开。这是容器原理的深水区，也是面试常考。

## 二、核心内容

### 2.1 三类循环依赖，只有一种被解决

| 类型 | 结果 |
| :--- | :--- |
| ① 构造器注入循环依赖 | ❌ 死锁报错（实例化前就必须拿到依赖，无解） |
| ② 原型（多例）作用域 + setter 循环 | ❌ 报错 |
| ③ **单例 + setter/字段注入循环** | ✅ **Spring 能解决** |

> 关键前提：**只有方式③被解决**，其余两种情况 Spring 都抛异常。

### 2.2 三级缓存结构与解决流程

三个缓存都在 `DefaultSingletonBeanRegistry`（`getBean()` 最终从一级返回）：

| 缓存 | 类型 | 存什么 | 用途 |
| :--- | :--- | :--- | :--- |
| **singletonObjects（一级）** | `Map<String,Object>` | 完全初始化好的 Bean（实例化+属性+初始化+AOP 代理都已就绪） | `getBean()` 最终返回这里 |
| **earlySingletonObjects（二级）** | `Map<String,Object>` | 提前暴露的早期引用（原始对象或早期代理对象） | 处理循环依赖，避免重复生成代理 |
| **singletonFactories（三级）** | `Map<String,ObjectFactory<?>>` | 对象工厂（**非实例本身**，value 是工厂） | 按需延迟生成"正确引用"，兼顾 AOP 代理 |

**五步走查**：
1. **创建 A 并提前暴露工厂**：先调 A 构造器得原始对象（未填充属性）→ 往三级缓存放 A 的工厂（刚搭好钢筋骨架的大楼）
2. **填充 A 属性时触发 B 创建**：A 依赖 B → 创建 B，B 构造后也放三级缓存 → 三级缓存同时有 A、B 的工厂
3. **B 属性注入发现循环依赖**：B 需要 A → 一级没找到 → 二级没命中 → **三级定位到 A 工厂** → 调 `getObject()`：若 A 需要 AOP 则提前生成代理，否则返回原始对象 → **放入二级、清三级** → 注入给 B
4. **完成 B 生命周期**：B 依赖齐 → 执行初始化 → 提升到一级缓存，清 B 二/三级临时条目（B 可被使用）
5. **回溯完成 A 构建**：把完备的 B 注入 A → 执行 A 初始化。**关键细节**：若 A 之前生成了早期代理，直接复用二级代理作为最终 Bean，而非重复创建 → A 入一级缓存，循环闭环

**三级缓存设计精髓**：三级工厂负责"实例化后立刻暴露生成能力（兼顾 AOP）"；二级缓存临时存已确定的早期引用（避免重复代理）；一级缓存最终交付完整 Bean。本质是**中断初始化流程 → 逆向注入半成品 → 延迟代理生成**三大策略。

### 2.3 为什么必须三级缓存？二级不够吗？（必考）

> **核心答案：为了兼容 AOP 代理。** 如果只要二级，当 A 依赖 B、B 又依赖 A 且 A 需要被代理（如 `@Transactional`）时：B 去注入 A 拿到的是 A 的 **原始对象**，但 A 初始化完成后容器里存的是 **代理对象** —— 同一个 Bean 出现两个不同实例，**直接违反单例原则**。

- 二级缓存只能存"已确定的早期引用（原始对象）"，无法在"要不要提前做代理"之间动态决策。
- 三级缓存存的是**工厂**（`ObjectFactory`）：循环依赖时调 `getObject()` **按需判断**——需要代理就提前生成代理（进二级），不需要就返回原对象 → 保证 B 拿到的 A 就是最终形态、对象全局唯一。
- 一句话：**三级缓存本质 = "按需延迟生成正确引用"**，既维持 Bean 生命周期完整性，又避免循环依赖下破坏单例。

### 2.4 三级缓存的数据结构（细节题）

三个都是 Map，但 **value 类型不同**：
- 一级 `singletonObjects`：`Map<String, Object>`（全就绪 Bean）
- 二级 `earlySingletonObjects`：`Map<String, Object>`（早期引用）
- 三级 `singletonFactories`：`Map<String, ObjectFactory<?>>`（**value 是工厂函数，不是 Bean 本身**）

## 三、可能追问

1. 「构造器注入为什么解决不了循环依赖？」→ 实例化前就必须拿到依赖，无解
2. 「`@Lazy` 能解决构造器循环依赖吗？」→ 可以，通过代理对象延迟创建
3. 「循环依赖中 AOP 代理为什么提前生成？」→ 保证注入的引用与最终 Bean 一致、不违反单例
4. 「三级缓存 key 是什么？」→ beanName
5. 「原型作用域为什么不能解决循环依赖？」→ 每次都要新实例、无缓存复用提前暴露
6. 「二级缓存什么时候能清掉？」→ Bean 完成后把早期引用升级/清除，只留一级
