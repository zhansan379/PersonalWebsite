# Spring AOP

> **AOP（面向切面编程）** 是对 OOP 的补充：把与业务无关、却处处共用的横切逻辑（日志、事务、权限）抽离出来统一处理，通过 **动态代理** 实现"无侵入"地增强方法。核心主线：**调用的不是原始对象，而是代理对象。**

## 一、这是什么

回答"AOP 介绍 / AOP 解决什么问题 / 谈谈对 AOP 的了解"等问题时，抓住三点：
1. **是什么**：把横切关注点模块化的编程思想，最小单元是"切面"（OOP 最小单元是类）。
2. **解决什么**：减少重复代码、降低模块耦合，提高可扩展性和可维护性。
3. **怎么实现**：基于动态代理（JDK Proxy / CGLIB），运行期织入。

## 二、核心内容

### 2.1 AOP 解决什么问题（认知深度加分）

> 本质是对**多继承不足**的弥补。对象的主要特征（**强共性**）被抽象为继承链；而日志这类**弱共性**——既不抽象、又能横跨继承树下多个同级子节点——既不适合用接口、也不适合用继承强行归纳。AOP 正好统一抽象和集中处理这类"弱共性横切逻辑"。

- OOP 中最小单元是"Class 对象"，AOP 中最小单元是"切面"（可包含多种类型和对象，模块化管理，如事务管理）。
- 把功能分两类：**核心业务**（登录、注册、增删改查）+ **周边业务**（日志、事务等），两者独立开发再"编织"在一起。

### 2.2 AOP 核心概念

| 术语 | 含义 |
| :--- | :--- |
| **Aspect 切面** | 切点 + 通知的统称（概念本身；注意与 AspectJ 框架区分，Spring 只借用了它的注解） |
| **Join Point 连接点** | 程序执行的点；**Spring AOP 仅支持方法级连接点** |
| **Advice 通知** | before / after / after-returning / after-throwing / around 五种 |
| **Pointcut 切点** | 匹配连接点的表达式，决定哪些方法被增强 |
| **Introduction 引介** | 让切面声明被通知对象实现额外的接口 |
| **Weaving 织入** | 在切点引导下把通知逻辑插入目标方法 |
| **AOP Proxy 代理** | JDK 动态代理 / CGLIB 两种 |
| **Target 目标对象** | 被代理的对象 |

### 2.3 AOP 在 Spring 中的应用（说 2~3 个场景加分）

1. **声明式事务**：`@Transactional` 基于 AOP，方法执行前开启事务，执行后按异常提交/回滚
2. **接口日志**：`@Before` 拿入参、`@AfterReturning` 拿返回值、`@Around` 统计执行时间
3. **权限校验**：`@Before` 检查登录状态/角色，不满足直接抛异常阻止执行

> 收尾金句："以上应用本质上都是『切面包裹横切逻辑 → 切点指定方法 → 不同阶段插逻辑』，实现了**无侵入地增强业务功能**。"

### 2.4 原理：动态代理（JDK vs CGLIB）

| 维度 | JDK 动态代理 | CGLIB |
| :--- | :--- | :--- |
| 原理 | `java.lang.reflect.Proxy` + `InvocationHandler`，运行时生成**实现接口**的代理类 | Code Generation Library，运行时生成目标类**子类**，通过继承增强 |
| 前置条件 | 目标类**必须实现接口** | 不需接口 |
| 默认选择 | Spring Boot 2.0 **之前**有接口时默认 | 无接口时默认；**Boot 2.0 起默认 `proxy-target-class=true` 一律优先 CGLIB** |
| 共同点 | 都属**运行期织入**，无需专用编译器（区别于 AspectJ 编译期/类加载期织入），可在普通 Java 项目用 |

### 2.5 动态代理 vs 静态代理

| 维度 | 静态代理 | 动态代理 |
| :--- | :--- | :--- |
| 生成时机 | 编译期确定（程序员/工具手写） | 运行期 JVM 自动生成代理类 |
| 代理数量 | 通常只代理一个类，一个接口一个代理类 | 一个配置覆盖成百上千方法 |
| 变更应对 | 接口改方法名，所有代理类跟着改（僵化） | 反射调用，不怕变动 |
| 筛选能力 | 逻辑写死 | 运行时按切点表达式精准匹配（如"只增强带 `@Transactional` 的方法"） |

**能用静态代理实现 AOP 吗？** 技术上可行，但生产没人用，三大硬伤：**代码爆炸**（100 个 Service 写 100 个代理类）、**僵化**（接口改动牵一发动全身）、**无法动态筛选**（无法按注解/切点表达式运行时匹配）。这是 Spring 选动态代理的根本原因。

### 2.6 AOP 常用注解

| 注解 | 作用 |
| :--- | :--- |
| `@Aspect` | 定义切面，标注在切面类 |
| `@Pointcut` | 定义切点，标注在方法上 |
| `@Before` | 方法执行前通知 |
| `@After` | 方法执行后通知（无论正常返回还是抛异常） |
| `@Around` | 方法前后都执行，功能最强（用 `proceed()` 控制） |
| `@AfterReturning` | 方法正常返回结果后 |
| `@AfterThrowing` | 方法抛出异常后 |

## 三、可能追问

1. 「Spring AOP 用 JDK 还是 CGLIB？什么条件下？」→ 见 2.4 表；Boot 2.0 起默认 CGLIB，切回需 `proxy-target-class=false`
2. 「Spring AOP 能拦截构造方法/字段吗？」→ 不能，只拦截容器内 Bean 的方法；AspectJ 才能（见 [[wiki/编程/spring/springboot/Spring AOP 能力边界与 JoinPoint]]）
3. 「自己 new 的对象 AOP 生效吗？」→ 不生效，必须是容器管理的 Bean
4. 「同一类内部方法调用会触发 AOP 吗？」→ 不会，走 this 绕过代理（同源问题见 [[Spring 事务失效场景]]）
5. 「五个通知的执行顺序？多个切面顺序？」→ `@Order`/`@Ordered` 控制优先级
6. 「`JoinPoint` 和 `ProceedingJoinPoint` 区别？」→ 只读观察者 vs 能 `proceed()` 控制执行，见 [[wiki/编程/spring/springboot/Spring AOP 能力边界与 JoinPoint]]
7. 「动态代理和反射的关系？性能？」→ 运行期生成代理类、反射调用有一定开销
8. 「AOP 与 AspectJ 的区别？」→ Spring AOP 基于运行期动态代理只拦截方法；AspectJ 基于字节码织入连构造/字段都可拦
