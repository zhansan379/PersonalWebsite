# MyBatis 的占位符区别

> `#{}` 走**预编译占位符**（`PreparedStatement`），安全防注入；`${}` 走**字符串拼接**，灵活但**有 SQL 注入风险**。核心主线：**能用 #{} 尽量用 #{}；`${}` 只用于不能预编译的场景（如表名/列名/排序字段）。**

## 一、这是什么

最常考的 MyBatis 细节题之一。回答时从"是否预编译 → 是否安全 → 适用场景"三层展开。

## 二、核心内容

### 对比表

| 维度 | `#{}` | `${}` |
| :--- | :--- | :--- |
| 处理方式 | **预编译**的 SQL，`#{}` 替换为 `?` 占位符 | **普通拼接**，把参数直接拼入 SQL |
| 底层 | 调 `PreparedStatement` 的 set 方法为占位符赋值 | 直接拼接字符串 |
| SQL 注入 | ✅ **可防止** | ❌ **不能防止**（参数直接入 SQL） |
| 性能 | 预编译执行效率更高、可复用 | 每次拼接 |
| 适用场景 | 传**参数值**（如 WHERE 条件值） | **表名/列名/排序字段**等结构部分 |

### 2.1 `#{}`：预编译占位符（推荐）
```sql
SELECT * FROM user WHERE id = #{id}
```
- 编译成 `SELECT * FROM user WHERE id = ?`，再 `setString(1, id)`。
- **安全性**：参数值走 `PreparedStatement` 转义，**可防 SQL 注入**。
- **性能**：预编译，执行效率高。

### 2.2 `${}`：字符串拼接（慎用）
```sql
SELECT * FROM ${tableName} ORDER BY ${orderBy}
```
- 直接把参数值拼进 SQL，如排序字段、表名这类**不能做占位符**的结构部分。
- **风险**：参数未经处理直接拼入 SQL，**存在 SQL 注入漏洞**，如 `; DROP TABLE ...`。
- **注意**：即使使用 `${}`，也务必对参数做**白名单校验**（如排序字段枚举校验）。

### 2.3 什么时候必须用 `$`？什么时候必须用 `#`？
- 传**值**（值参数、条件）→ 用 `#`。
- 传**结构**（表名、列名、`ORDER BY` 字段）→ 占位符 `?` 失效，只能用 `$`，但要防注入。

## 三、可能追问

1. 「`#{}` 为什么能防注入？」→ 走 `PreparedStatement` 预编译，参数值被当作参数而非 SQL 片段，特殊字符被转义
2. 「`${}` 一定能注入吗？如何规避？」→ 直接拼接有风险；用前做白名单/枚举校验
3. 「哪些场景只能用 `#{}` 或只能用 `${}`？」→ 值用 #、结构（表名/排序字段）用 $
4. 「预编译和普通拼接谁快？」→ 预编译更快且占位符 SQL 可复用
5. 「`#{id}` 和 `${id}` 在字符串类型下拼接差异？」→ `#` 会带引号处理成字符串值，`$` 直接裸拼接
