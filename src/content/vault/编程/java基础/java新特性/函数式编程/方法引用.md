# 方法引用

> **方法引用**是 Lambda 的进一步简化：当某个方法的**签名**（只看**参数类型和返回类型**）与接口抽象方法恰好一致时，可直接传入方法引用（写为 `类名::方法`），连参数列表都不用写。可分**静态方法、实例方法、构造方法**三类引用。

## 一、概念：什么算"签名一致"

使用 Lambda 可不必编写 `FunctionalInterface` 的实现类。而**方法引用**更进一步：某个方法签名和接口恰好一致时，直接传入方法引用。

`Comparator<String>` 定义的抽象方法是 `int compare(String, String)`，与静态方法 `int cmp(String, String)` 相比，**方法参数一致、返回类型相同**，只是方法名不同——两者方法签名一致，可直接作为 Lambda 传入：

```java
import java.util.Arrays;

public class Main {
    public static void main(String[] args) {
        String[] array = new String[] { "Apple", "Orange", "Banana", "Lemon" };
        Arrays.sort(array, Main::cmp);   // 传入静态方法引用
        System.out.println(String.join(", ", array));
    }

    static int cmp(String s1, String s2) {
        return s1.compareTo(s2);
    }
}
```

> **注意**：方法签名只看**参数类型和返回类型**，不看方法名称，也不看类的继承关系。

## 二、引用静态方法：`类名::静态方法`

如 `Arrays.sort(array, Main::cmp)` 中的 `Main::cmp`。

## 三、引用实例方法：隐含的 this 参数

再看引用**实例方法** `String::compareTo`：

```java
Arrays.sort(array, String::compareTo);  // 实例方法引用
```

`String.compareTo` 的方法签名只有一个参数，为何能与 `int compare(String, String)`（两个参数）匹配？

因为**实例方法有一个隐含的 `this` 参数**。`String.compareTo()` 实际调用时第一个隐含参数总是传入 `this`，相当于静态方法：

```java
public static int compareTo(String this, String o);
```

所以 `String.compareTo()` 也可作为方法引用传入，实例类型被隐含地作为第一个参数类型。

## 四、引用构造方法：`类名::new`

把 `List<String>` 转换为 `List<Person>` 可用构造方法引用 `Person::new`：

```java
List<String> names = List.of("Bob", "Alice", "Tim");
List<Person> persons = names.stream().map(Person::new).collect(Collectors.toList());
```

其原理：`map()` 需要传入的 `Function<String, R>` 抽象方法签名是 `R apply(T t)`，对应 `Person apply(String)`。而 `Person` 的构造方法参数是 `String`，且构造方法没有 `return` 语句但**会隐式返回 `this` 实例**（类型 `Person`），因此构造方法满足要求，可用 `类名::new` 引用。

## 五、小结：FunctionalInterface 允许传入的四种形式

`FunctionalInterface` 允许传入：

- 接口的**实现类**（传统写法，代码较繁琐）
- **Lambda 表达式**（只需列出参数名，由编译器推断类型）
- 符合方法签名的**静态方法**
- 符合方法签名的**实例方法**（实例类型被看做第一个参数类型）
- 符合方法签名的**构造方法**（实例类型被看做返回类型）

> `FunctionalInterface` **不强制继承关系**，不需要方法名称相同，只要求方法参数（类型和数量）与方法返回类型相同，即认为方法签名相同。
