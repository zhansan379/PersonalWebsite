# Java 21 新特性知道哪些？

> Java 21（LTS）的亮点集中在**语言特性**与**并发模型**两大块：语言侧是"模式匹配"三件套（记录模式 + Switch 模式匹配 + 字符串模板预览）；并发侧是革命性的**虚拟线程**与更安全的 **Scoped Values**——其中虚拟线程堪称里程碑，直接改变了高并发 I/O 应用的写法。

## 一、这是什么

Java 21 是继 Java 17 之后的新一个 **LTS（长期支持）** 版本。相比 Java 8 的偏执行 风格，Java 21 的重点不在加一堆零散 API，而在两件事：

- **让代码更声明式**：用模式匹配 + 记录解构，减少类型转换与样板代码。
- **让并发更省资源**：用虚拟线程挑战"一个请求一个线程"的传统模型，让线程不再昂贵。

## 二、核心内容

### 1. 语言特性：模式匹配三件套

#### （1）Switch 的模式匹配（JEP 441，正式转正）

**是什么**：在 `switch` 的 `case` 标签里直接用模式匹配，而不是"值 + 类型强转"。

**价值**：更灵活、更类型安全，减少样板代码和潜在的错误转换。

```java
// 不用再 instanceof + 强转 switch，直接按模式取
double result = switch (account) {
    case SavingsAccount sa -> sa.getSavings();
    case CurrentAccount ca -> ca.getCurrent();
    // 分支是完整表达式，自动成为 switch 的结果
};
```

#### （2）记录模式（Record Patterns，JEP 440）

**是什么**：把模式匹配扩展到 `record`，在 `instanceof` 或 `switch` 中直接对 record **解构**，拆出组件。

**价值**：省掉手写 getter、再逐个提取字段的样板。

```java
if (obj instanceof Point(int x, int y)) {   // 直接把 Point 组件解构到 x、y
    System.out.println(x + "," + y);
}
```

#### （3）字符串模板（预览版，JEP 430）⚠️

**是什么**：在字符串字面量里直接嵌入表达式，用模板处理器（如 `STR`）调用，表达式用 `\{...}` 括起。

**价值**：比 `"hello " + name + ", welcome!"` 的拼接更可读、更易维护。

```java
String msg = STR."hello \{name}, welcome!";   // 替代字符串拼接
```

> ⚠️ **重要带引注，面试必记的状态**：字符串模板在 **JDK 23 已被撤回再设计**，属预览/实验性质，**不是 Java 21 的稳定特性**。

### 2. 并发特性

#### （1）虚拟线程（Virtual Threads，JEP 444）— 本版本最大亮点

**是什么**：轻量级线程。线程的**栈在堆上动态分配**，运行时**挂载到平台载体线程（carrier thread）**执行，挂起时栈被卸载回堆——因此能以极低内存创建海量虚拟线程。

**为什么重要**：传统"一个线程 = 一个 OS 线程"，量大时受内存限制。虚拟线程让 **I/O 密集型应用** 的吞吐量和响应速度大幅提升——因为阻塞等待 I/O 时，载体线程会腾出来跑别的虚拟线程。

```java
// 三种创建方式
Thread.ofVirtual().start(runnable);                    // 静态构建方法
Thread.builder()...;                                   // 构建器（早期 API）
Executors.newVirtualThreadPerTaskExecutor();           // ExecutorService
```

**适用画像**：I/O 密集（阻塞多）、需要大量并发连接/请求；**不*役* 于 CPU 密集型**（那还是线程数≈核数的线程池 + 并行计算）。

#### （2）Scoped Values（范围值，JEP 446，预览）

**是什么**：一种在线程及子任务间**共享不可变数据**的新方式，意图替代传统的 `ThreadLocal`，促进封装性与线程安全。

**强项**：不通过方法参数一层层传，就能在线程内传递上下文（用户会话、配置）。相比 `ThreadLocal`：不可变、生命周期受代码块/作用域约束（用完自动清理），**不泄漏、不污染子线程**。

```java
// 类似：在作用域内绑定一个共享不可变值，作用域结束即失效
ScopedValue where = ScopedValue.newInstance();
ScopedValue.where(where, val).run(() -> { /* 作用域内可读 */ });
```

## 三、如何应用 / 面试怎么讲

**回答骨架（三步定调）：**

1. **分门别类**：Java 21 是 LTS，亮点分"语言"和"并发"两块。
2. **语言侧**：Switch 模式匹配（正式）、记录模式解构（正式）、字符串模板（**预览，JDK23 已撤回**）。
3. **并发侧（重头戏）**：虚拟线程 + Scoped Values。

**面试加分点：**

- 主动区分**稳定 vs 预览/实验**特性（字符串模板、Scoped Values 是预览）——显示你关注特性成熟度而非只报菜名。
- 给虚拟线程一个**准确的技术画像**：栈在堆上、挂起到载体线程(carrier)、I/O 密集受益、CPU 密集无益。
- 把 Scoped Values 与 `ThreadLocal` 对比：不可变、作用域约束、不泄漏——点出为什么它是"更安全"的替代。

**常见追问预案：**

| 追问 | 应答案点 |
| :--- | :--- |
| 虚拟线程和线程池的区别？ | 一个虚拟线程 ≈ 一个轻量任务，由 JVM 调度挂到少量载体线程；不需"池化复用"，开千百万都很便宜 |
| 虚拟线程适合什么场景？ | I/O 密集（阻塞等待多）；不提升 CPU 密集/计算性能 |
| 字符串模板为什么被撤回？ | 可读性争议 + 语法/处理器设计需重调，JDK 23 撤回再设计，说明其尚未稳定 |
| Scoped Values 比 ThreadLocal 好在哪？ | 不可变、作用域界定生命周期、不泄漏不染子线程，更安全 |
