# Java 创建对象有几种方式？

> Java 创建对象**远不止 `new`**，常见有五种：**`new` 关键字、反射、`clone()`、反序列化、工厂模式**
> 
> 一句话记忆：**调构造器的有两类（new / 反射），不调构造器的有两类（clone / 反序列化），工厂模式只是把 new 包装了一下。** 面试分类标尺就是——**是否调用构造器**。

## 一、回答骨架（先立框架）

面试被问「创建对象有几种方式」，按四步走，结构清晰、不丢分点：

| 步骤     | 动作                | 示例话术                                                       |
| ------ | ----------------- | ---------------------------------------------------------- |
| 1️⃣ 定调 | 给出结论：不止 `new`，共五种 | "Java 创建对象有 5 种方式"                                         |
| 2️⃣ 分类 | 按「是否调用构造器」分成两大类   | "`new` 和反射会调构造器；`clone` 和反序列化不调；工厂封装 `new`"                |
| 3️⃣ 展开 | 讲每一种的原理与场景        | 见下文三种方法表 + 详解                                              |
| 4️⃣ 收尾 | 主动抛一个高阶话题引导追问     | "其中反射/单例有两个坑，比如 `Class.newInstance()` 过时、序列化能破坏单例——要不要展开？" |

## 二、核心分类：是否调用构造器

| 方式                                  | 核心原理       | 是否调用构造器？  | 特点与应用场景                       |
| ----------------------------------- | ---------- | --------- | ----------------------------- |
| **`new` 关键字**                       | JVM 指令     | ✅ 是       | 最标准、最常用；类型在编译期确定、紧密耦合         |
| **反射（`Constructor.newInstance()`）** | 运行时类信息     | ✅ 是       | 灵活、解耦，用于框架/动态代理               |
| **`clone()`**                       | 复制现有对象     | ❌ 否       | 基于原型创建副本；需实现 `Cloneable`      |
| **反序列化**                            | 从字节流恢复     | ❌ 否       | 用于持久化、网络通信；需实现 `Serializable` |
| **工厂模式**                            | 方法封装 `new` | ✅ 是（在方法内） | 解耦、隐藏创建逻辑、集中控制实例              |

> 🔑 **加分关键二分**：面试官最想听你点出——**`clone()` 和反序列化不调用任何构造器**，而 `new` 和反射调用。这是区别于「只会背五种方式」的本质理解。

## 三、五种方式详解

### 3.1 `new` 关键字（最常用）

- 通过调用类的**构造器**实例化对象，可传参、走完整初始化逻辑。
- **优点**：简单、直接、明确。 **缺点**：紧密耦合，必须编译期知道具体类名。

```java
Person p1 = new Person();              // 无参构造
Person p2 = new Person("Alice");       // 有参构造
```

### 3.2 反射（动态创建，运行时才知道类）

- 两种入口：
  - `Class.forName("...").getDeclaredConstructor().newInstance()` —— **推荐**，可指定任意构造器
  - `Class.newInstance()` —— ⚠️ **JDK9 起已过时**（只能调无参公有构造器，且会抛出所有受检异常）
- 应用场景：框架设计（如 Spring 的 IOC 容器）、动态代理。

```java
Class<?> clazz = MyClass.class;
MyClass obj = (MyClass) clazz.getDeclaredConstructor().newInstance();
```

### 3.3 `clone()`（基于原型复制副本）

- 实现 `Cloneable` 接口并重写 `Object.clone()`，基于现有对象（原型）复制出新对象。
- **不调用构造器**；`Object.clone()` 默认是**浅拷贝**（引用字段复制地址，共享对象），需要深拷贝必须手动递归克隆引用对象。

```java
class Person implements Cloneable {
    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();          // 浅拷贝；深拷贝需额外处理引用字段
    }
}
```

### 3.4 反序列化（从字节流恢复）

- 通过 `ObjectInputStream` 从字节流（文件/网络）重建对象。
- **不调用任何构造器**；类必须实现 `java.io.Serializable`。

```java
try (ObjectInputStream ois = new ObjectInputStream(new FileInputStream("person.dat"))) {
    Person restored = (Person) ois.readObject();   // 直接还原，不走构造器
}
```

### 3.5 工厂模式（设计层面封装 `new`）

- 不直接 `new`，而是通过一个方法返回对象实例：`getInstance()`、`valueOf()` 都是常见工厂方法。
- **优点**：将创建与使用分离、降低耦合、可隐藏复杂创建逻辑（池化、缓存、限流）、可返回子类。
- 例：`Integer.valueOf(int)`、`Calendar.getInstance()`。

```java
class Person {
    private Person(String name) { ... }            // 构造器可私有
    public static Person createPerson(String name) { // 静态工厂
        // 可做缓存/日志/返回子类等额外逻辑
        return new Person(name);
    }
}
```

## 四、两处"加分/修正"点（容易出彩）

1. **`Class.newInstance()` 已废弃**：JDK9 起标记过时——它只能调用**无参公有构造器**，且把异常都抛出来；应改用 `Constructor.newInstance()`（更强大、更灵活，`setAccessible(true)` 还能调私有构造器）。
2. **`clone()` / 反序列化都不调构造器**：所以它们能**绕过构造器里的初始化/校验**——这是单例可能被破坏的根源，也是回答里最显功力的细节。

## 五、高频追问预案（对方可能追问）

| 追问 | 回答要点 |
|---|---|
| "什么情况下不能/不该用 `new`？" | 构造器私有（单例/工具类）→ 静态工厂；运行时才知道类名 → 反射；要副本 → `clone`；从文件/网络恢复 → 反序列化；想解耦 → 工厂。 |
| "`new` 和反射创建对象有啥区别？" | `new`：编译期定类型、字节码 `new`+`invokespecial <init>`、性能好但紧耦合；反射：运行时解析 `Class`、动态解耦、性能略低，常用于框架。 |
| "反序列化会调用构造器吗？为什么？" | **不会**。`ObjectInputStream` 直接从字节流分配内存、还原字段，不走 `<init>`。因此可绕过构造器校验，还会破坏单例。 |
| "`clone` 和 `new` 的区别？" | `new` 调构造器从零创建；`clone` 不调构造器、基于原型复制，默认浅拷贝，深拷贝需手动递归。 |
| "`Class.newInstance()` 和 `Constructor.newInstance()` 有何区别？" | 前者只能无参公有构造器、已废弃、异常不精确；后者可控任意构造器（含私有配合 `setAccessible`）、异常更准确。 |
| "`new` 一个对象，JVM 里发生了什么？" | 类检查/加载 → 堆中分配内存（指针碰撞/空闲列表）→ 初始零值 → 设置对象头（`mark word`、Klass 指针）→ 执行 `<init>`（父构造→字段初始化→构造体）。可引向运行时数据区。 |
| "怎么防止反射/序列化破坏单例？" | 反射：构造器判空二次校验 或 用**枚举单例**（天然防反射+防序列化）；序列化：加 `readResolve()` 返回既有实例。 |
| "工厂模式和直接 `new` 的取舍？" | 工厂解耦创建与使用、集中控制（缓存/限流/可返回子类）；代价是多一层抽象、可能过度设计。 |

## 六、易错陷阱

- ❌ "创建对象只能 `new`"——至少 5 种；面试先给总数再展开。
- ❌ 还在用 `Class.newInstance()`——JDK9 已废弃，要会用 `Constructor.newInstance()`。
- ❌ "`clone` 是深拷贝"——`Object.clone()` 默认**浅拷贝**，深拷贝要自己递归（见[[实现深拷贝的三种方法是什么？]]）。
- ❌ "所有方式都调构造器"——`clone`、反序列化**不调用构造器**。
- ❌ 忽略单例隐患——反射（`setAccessible` 破私有构造器）和反序列化都可能破坏单例。
- ❌ "反序列化一定安全"——类必须实现 `Serializable`，字段含不可序列化对象会抛异常；`readResolve`/`serialVersionUID` 别忘。

## 七、40 秒口述版

> Java 创建对象不止 `new`，一共有五种。第一种 `new` 关键字，调构造器，最常用但紧耦合；第二种反射，运行时通过 `Class`/`Constructor` 创建，灵活解耦，常用于框架，注意 JDK9 后要用 `Constructor.newInstance()` 而 `Class.newInstance()` 已废弃；第三种 `clone()`，实现 `Cloneable` 基于原型复制，不调构造器，默认浅拷贝；第四种反序列化，从字节流还原对象，也不调构造器，类要实现 `Serializable`；第五种工厂模式，本质是把 `new` 封装进方法，用于解耦和集中控制。所以核心有两个点：一是会调构造器的有 `new` 和反射，不调构造器的是 `clone` 和反序列化；二是 `clone` 默认浅拷贝、序列化能绕过构造器甚至破坏单例。
