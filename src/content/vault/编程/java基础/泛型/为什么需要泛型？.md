# 为什么需要泛型

> 泛型（Generic）让代码**适用于多种数据类型执行相同的逻辑**，并在**编译期**对类型做出约束，从而避免强制类型转换和 `ClassCastException`。
> 一句话记忆：**泛型解决两件事——「一处代码，多种类型」的代码复用，和「编译期就知道类型」的类型安全。**

## 一、为什么需要泛型（两大核心原因）

| # | 核心原因 | 解决的问题 | 没有泛型时的痛点 |
|---|---|---|---|
| 1 | **代码复用** | 一段逻辑可适用多种类型，无需为每种类型各写一份 | 每种类型都要重载/复制同一段方法 |
| 2 | **类型安全** | 编译期就约束类型，取出元素无需强转 | 元素统一成 `Object`，取出要强转，易抛 `ClassCastException` |

## 二、原因一：代码复用 —— 同一份代码，适用多种类型

> 需求：写一段"加法"，要能支持 `int`、`float`、`double` 等不同类型。

**没有泛型**：每种类型都得重载一个 `add` 方法，代码冗长、重复。

```java
private static int add(int a, int b) {
    System.out.println(a + "+" + b + "=" + (a + b));
    return a + b;
}

private static float add(float a, float b) {
    System.out.println(a + "+" + b + "=" + (a + b));
    return a + b;
}

private static double add(double a, double b) {
    System.out.println(a + "+" + b + "=" + (a + b));
    return a + b;
}
```

**用泛型**：一个方法即可复用，类型参数 `T` 在使用时传入具体类型。

```java
private static <T extends Number> double add(T a, T b) {
    System.out.println(a + "+" + b + "=" + (a.doubleValue() + b.doubleValue()));
    return a.doubleValue() + b.doubleValue();
}
```

## 三、原因二：类型安全 —— 指定类型，编译期检查，免强制转换

> 需求：在一个集合里只放同一种类型的数据，取出后能直接以目标类型使用。

**没有泛型**：`List` 里的元素统一是 `Object`，**无法约束其中的类型**，取出时得人为强转到目标类型，很容易抛 `java.lang.ClassCastException`（编译期看不出来，运行期才炸）。

```java
List list = new ArrayList();          // 元素全是 Object，类型不受约束
list.add("xxString");
list.add(100d);
list.add(new Person());

String s = (String) list.get(0);      // 取出必须手动强转，类型错配就运行期报错
```

**用泛型**：引入泛型后提供**类型的约束**，进行**编译前的检查**——类型不符根本无法写入，也无需强转。

```java
List<String> list = new ArrayList<String>();
list.add("hello");                    // ✅ 只能放 String
// list.add(100d);                    // ❌ 编译期就拒绝，类型不符
String s = list.get(0);               // ✅ 取出自动是 String，无需强转
```

## 四、对比总结

| 维度 | 不用泛型 | 用泛型 |
|---|---|---|
| 方法/类复用 | 每种类型重载一份 | 一份模板 + 类型参数 `T` |
| 类型约束 | 无（统一 `Object`） | 编译期强约束 |
| 取出元素 | 需手动强转 | 自动返回目标类型 |
| 错误发现 | 运行期 `ClassCastException` | **编译期**即可发现 |
| 代码可读性 | 差 | 好 |
