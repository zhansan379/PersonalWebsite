# 对注解解析的底层实现了解吗？

> 注解本质是**声明式接口**（继承 `java.lang.annotation.Annotation`）。运行时注解能否被读到，取决于 `@Retention` 策略与字节码中的属性表；解析则依靠反射在运行时从 `.class` 文件取出注解数据并反序列化为代理对象。

## 一、是什么：注解的底层形态

### 1. 注解是一种特殊的接口

注解本质上继承 `java.lang.annotation.Annotation`，所以也叫**声明式接口**：

```java
public @interface MyAnnotation {
    String value();
}
```

编译后，Java 编译器将其转换为一个继承自 `Annotation` 的接口，并生成相应字节码文件。

### 2. 三种保留策略（`@Retention`）

| 保留策略 | 存在位置 | 运行时是否可反射访问 |
| :--- | :--- | :--- |
| `SOURCE` | 仅源码 | 否（编译后丢弃） |
| `CLASS` | `.class` 文件 | 否（保留但运行时不可见） |
| `RUNTIME` | `.class` 文件 | **是**（唯一能反射解析的） |

**只有 `RUNTIME` 注解可通过反射解析。**

## 二、核心内容：注解如何存储与解析

### 1. 存储：字节码属性表（Attribute Table）

当注解标记为 `RUNTIME` 时，编译器会在 `.class` 文件中保存注解信息，存入属性表：

| 属性 |
| :--- |
| `RuntimeVisibleAnnotations` | 运行时可见的注解信息 |
| `RuntimeInvisibleAnnotations` | 运行时不可见的注解信息 |
| `RuntimeVisibleParameterAnnotations` / `RuntimeInvisibleParameterAnnotations` | 方法参数上的注解信息 |

可通过工具（如 `javap -v`）查看 `.class` 文件中的注解信息。

### 2. 解析：依赖反射机制

**基本流程**：通过反射 API 获取类、方法、字段等元素上的注解。

```java
Class<?> clazz = MyClass.class;
MyAnnotation annotation = clazz.getAnnotation(MyAnnotation.class);
if (annotation != null) {
    System.out.println(annotation.value());
}
```

**底层核心类**：`java.lang.reflect.AnnotatedElement` —— 是所有可被注解修饰的元素（`Class`、`Method`、`Field` 等）的父接口，提供以下方法：

- `getAnnotation(Class<T> annotationClass)`：获取指定类型的注解
- `getAnnotations()`：获取所有注解
- `isAnnotationPresent(Class<? extends Annotation> annotationClass)`：判断是否包含指定注解

### 3. 底层实现细节（关键）

**这些方法由纯 Java 实现，不是 native 方法。** 以 `Class.getAnnotation(...)` 为例，内部会触发**延迟解析**：

1. `AnnotationParser.parseAnnotations(...)` 读取 JVM 在类加载阶段从 class 文件属性表（`RuntimeVisibleAnnotations` 等）抽取并传回的**原始字节**
2. 反序列化成 `Map<Class<? extends Annotation>, Annotation>`
3. 最终以**动态代理对象**（`AnnotationInvocationHandler`）的形式返回给调用方

**关于 native 接口的澄清**：JVM 在类加载阶段确实会解析 `.class` 文件中的注解信息，但这部分工作对应的 native 接口位于**底层的常量池与属性表读取**，而不是 `getAnnotation` 这一层 API。

## 三、如何应用：解析链路总结

注解解析的底层实现主要依赖 **Java 反射机制 + 字节码文件的存储**：

1. `@Retention` 元注解控制注解的保留策略
2. `RUNTIME` 时，运行时可通过反射 API 解析注解信息
3. JVM 层面从字节码文件读取注解信息，并创建注解的**代理对象**来获取属性值
