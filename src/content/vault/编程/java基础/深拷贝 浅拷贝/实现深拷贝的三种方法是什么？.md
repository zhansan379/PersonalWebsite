# 实现深拷贝的三种方法是什么

> 在 Java 中实现深拷贝主要有三种方式：**① 实现 `Cloneable` 并重写 `clone()`（递归克隆引用字段）② 序列化 / 反序列化 ③ 手动递归复制**。
> 一句话记忆：**递归 clone（要自己 `implements Cloneable`）、序列化（要 `implements Serializable`）、手动 new（零依赖但要手写）**。

## 一、共同前提

深拷贝 = 要把对象内部**所有引用类型字段的内容**都复制一份。无论哪种方式，都要照顾到**对象本身 + 嵌套的内部对象**，这是三种方法都要解决的核心问题。

三种方法本质对比：

| 方法 | 额外要求 | 代码量 | 是否依赖接口 | 适用场景 |
|---|---|---|---|---|
| ① `Cloneable` + 递归 `clone()` | 对象及所有引用字段实现 `Cloneable` | 中 | 是 | 类结构可控、需递归复制嵌套引用 |
| ② 序列化 / 反序列化 | 对象及所有引用字段实现 `Serializable` | 少（通用） | 是 | 通用、不想手写递归；性能有损耗 |
| ③ 手动递归复制 | 无 | 多 | 否 | 对象结构简单、可控性强 |

## 二、方法一：实现 `Cloneable` + 重写 `clone()`（递归克隆引用字段）

- **要求**：对象及其所有引用类型字段都实现 `Cloneable` 接口，并重写 `clone()`。
- **原理**：`super.clone()` 先做一层**浅拷贝**，然后在 `clone()` 里对引用类型字段**递归调用 `clone()`**，把共享的引用替换成全新的副本，从而实现深拷贝。

```java
class MyClass implements Cloneable {
    private String field1;
    private NestedClass nestedObject;

    @Override
    protected Object clone() throws CloneNotSupportedException {
        MyClass cloned = (MyClass) super.clone();        // 先浅拷贝一层
        cloned.nestedObject = (NestedClass) nestedObject.clone(); // 再对引用字段递归深拷贝
        return cloned;
    }
}

class NestedClass implements Cloneable {
    private int nestedField;

    @Override
    protected Object clone() throws CloneNotSupportedException {
        return super.clone();                            // 内部类自身无引用字段，浅拷贝即可
    }
}
```

- **优点**：比手动暴力复制简洁；类结构清晰时可读性好。
- **缺点 / 坑**：① 每个引用字段都要记得递归 `clone()`，**漏一个就退化成浅拷贝**；② 若引用链深处的类没实现 `Cloneable`，会抛 `CloneNotSupportedException`；③ `static final` 字段 / 不可变对象要处理好。

## 三、方法二：序列化 / 反序列化

- **要求**：对象及其所有引用类型字段都实现 `Serializable` 接口。
- **原理**：把整个对象 `writeObject` 成**字节流**，再 `readObject` 从字节流重建一个**全新的对象**——对象图整体被复制，天然达到深拷贝，无需手写递归。

```java
import java.io.*;

class MyClass implements Serializable {
    private String field1;
    private NestedClass nestedObject;

    public MyClass deepCopy() {
        try (ByteArrayOutputStream bos = new ByteArrayOutputStream();
             ObjectOutputStream oos = new ObjectOutputStream(bos)) {
            oos.writeObject(this);                       // 序列化：对象 → 字节流
            oos.flush();

            try (ByteArrayInputStream bis = new ByteArrayInputStream(bos.toByteArray());
                 ObjectInputStream ois = new ObjectInputStream(bis)) {
                return (MyClass) ois.readObject();       // 反序列化：字节流 → 全新对象
            }
        } catch (IOException | ClassNotFoundException e) {
            e.printStackTrace();
            return null;
        }
    }
}

class NestedClass implements Serializable {
    private int nestedField;
}
```

- **优点**：**最通用**，不关心对象内部结构，一套代码适用任意深度的对象图；嵌套复杂时最省事。
- **缺点 / 坑**：① 性能相对最差（序列化 + IO 开销大）；② 全员必须 `implements Serializable`（否则 `NotSerializableException`）；③ **`transient` 字段不会被序列化，复制后丢失**；④ 记得定义 `serialVersionUID`，否则类结构变化会导致 `InvalidClassException`；⑤ 单例 / 静态字段语义可能被破坏。

## 四、方法三：手动递归复制

- **要求**：无额外接口依赖，针对**特定对象结构**手动 new 新对象并逐字段赋值。
- **原理**：为每个类手写一个 `deepCopy()`，内部 `new` 一个新对象，把值类型字段直接赋值、引用字段递归调用其 `deepCopy()`。

```java
class MyClass {
    private String field1;
    private NestedClass nestedObject;

    public MyClass deepCopy() {
        MyClass copy = new MyClass();
        copy.setField1(this.field1);                          // 值字段直接复制
        copy.setNestedObject(this.nestedObject.deepCopy());   // 引用字段递归 deepCopy
        return copy;
    }

    // setField1 / setNestedObject 略
}

class NestedClass {
    private int nestedField;

    public NestedClass deepCopy() {
        NestedClass copy = new NestedClass();
        copy.setNestedField(this.nestedField);
        return copy;
    }
}
```

- **优点**：**零依赖、无序列化性能开销**；结构清晰时有最佳性能与可控性。
- **缺点 / 坑**：① 只能手动逐类写，嵌套层一多代码量大；② 新增字段容易**漏拷**导致错误；③ 只适用于**对象结构复杂度不高**的情况。

## 五、如何选型（速查）

| 需求 | 推荐 |
|---|---|
| 结构简单、手写可控 | ③ 手动递归复制 |
| 通用、不关心多层嵌套 | ② 序列化 |
| 想兼顾简洁 + 结构清晰 | ① `Cloneable` + 递归 clone |
| 有 `transient` / 单例 / 巨大对象图 | 谨慎用②，优先①/③ |
