# 深拷贝和浅拷贝的区别

> 拷贝（复制）是给对象造一个副本。按**复制后，原对象与副本是否仍共享内部引用类型字段**，分为**浅拷贝**与**深拷贝**。
> 一句话记忆：**浅拷贝只复制"引用"这一个框，深拷贝连框里指向的对象也复制一份。** 判别就看——改副本的引用字段会不会连累原对象。

## 一、这是什么

- **拷贝**：想独立操作同一个对象的数据而不互相影响，于是复制出一个副本。
- 对象字段分两类，决定了复制难度：
  - **值类型字段**（`int`、`double`、`boolean`…）——直接存值，复制时拷一份值即可，天然独立。
  - **引用类型字段**（对象引用）——只存"指向堆里对象的地址"，复制时是**再存一个引用**还是**连目标对象一起复制**，正是浅与深的界限。

## 二、浅拷贝（Shallow Copy）

> 只复制**对象本身**和其内部的**值类型字段**，但**不复制对象内部的引用类型字段**。

- 做法：创建新对象，把原对象的**字段值**逐项复制过去；引用字段只是把**引用（地址）**复制过去。
- 结果：新对象和原对象的引用字段，**指向的是同一个引用对象**——两者共享内部引用对象。

```java
// 示意：clone() 若只做 super.clone()，nestedObject 两个对象共用同一个
MyClass copy = (MyClass) original.clone();   // 只复制了引用字段的地址
copy.getNested() == original.getNested();    // true —— 共享同一个内部对象
```

## 三、深拷贝（Deep Copy）

> 在复制对象的同时，把**对象内部所有引用类型字段的内容也复制一份**，而不是共享引用。

- 做法：**递归复制**对象内部所有引用类型的字段，生成**一个全新的对象以及其内部的所有对象**。
- 结果：副本与原对象**完全没有共享**的引用对象，互不影响。

```java
// 深拷贝后，内部对象也被全新复制
MyClass copy = original.deepCopy();            // 递归复制了 nestedObject
copy.getNested() == original.getNested();      // false —— 指向不同的新对象
copy.getNested().equals(original.getNested()); // true  —— 但值相同
```

## 四、对比汇总

| 维度 | 浅拷贝 | 深拷贝 |
|---|---|---|
| 复制对象本身 | ✅ | ✅ |
| 值类型字段 | ✅ 复制值 | ✅ 复制值 |
| 引用类型字段 | ⚠️ 只复制引用（共享原对象） | ✅ 递归复制新对象 |
| 副本与原件共享内部对象 | ✅ 共享 | ❌ 不共享 |
| 递归 | 否（一层） | 是（递归到引用链底部） |
| 示例 | `super.clone()` | 手动递归 / 序列化 / 递归 clone（见[[实现深拷贝的三种方法是什么？]]） |
| 典型副作用 | 改副本内部对象会连累原件 | 无共享，安全但相对更耗时 |

## 五、如何选择

- **浅拷贝适用**：对象没有引用字段（纯值对象）、或内部引用对象允许被有意共享（不可变对象 + 只读静态数据）。
- **深拷贝适用**：内部引用对象会被修改、需要副本完全独立（如缓存副本、DTO 快照、事务隔离）。风险是深层结构可能**递归很深**，性能与复杂度需权衡。
- **判断口诀**：把副本的引用字段一改，原对象如果跟着变 → 是浅拷贝；没变 → 是深拷贝。
