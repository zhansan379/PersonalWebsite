# 怎么保证多线程安全？

> 一句话概述：Java 保证多线程安全的手段可以归纳为 **7 大类**——`synchronized`、`volatile`、`Lock` 接口（`ReentrantLock`）、原子类、`ThreadLocal`、并发集合、JUC 工具类。核心思路是 **"要么不让争（互斥/隔离），要么让争的结果是对的（原子/可见）"**。

## 一、这是什么

多线程安全（Thread Safety）的本质是：**多个线程同时访问共享数据时，不产生意料之外的结果**。导致线程不安全的原因有三：

- **原子性**：操作被中断（如 `i++` 不是原子操作）
- **可见性**：一个线程的修改对另一线程不可见
- **有序性**：指令重排导致逻辑错乱

Java 提供了多种机制来分别或同时解决这三个问题，下面逐一介绍。

## 二、核心内容

### 1. `synchronized` 关键字

最基础的同步手段，保证**原子性 + 可见性**。同一时刻只有一个线程能进入被 `synchronized` 修饰的代码块或方法。

```java
// 修饰方法
public synchronized void someMethod() { /* ... */ }

// 修饰代码块，锁定对象监视器（monitor）
public void anotherMethod() {
    synchronized (someObject) {
        /* ... */
    }
}
```

> `synchronized` 的重量级锁在 JDK 1.6 后引入了**偏向锁 → 轻量级锁 → 重量级锁**的升级机制，性能已大幅改善。

### 2. `volatile` 关键字

保证**可见性**（禁止指令重排、强制从主存读写），但**不保证原子性**。适用于"一个线程写、多个线程读"的场景。

```java
public volatile int sharedVariable;
```

> 典型用途：**状态标志位**、**DCL 单例中的 `instance` 字段**。注意 `volatile` 不能替代 `synchronized` 做复合操作（如 `count++`）。

### 3. `Lock` 接口和 `ReentrantLock`

`java.util.concurrent.locks.Lock` 接口提供了比 `synchronized` 更灵活的锁机制。`ReentrantLock` 是最常用的实现：

- 支持**公平锁/非公平锁**
- 支持**超时等待**（`tryLock(timeout, unit)`）
- 支持**可中断**的锁等待
- 配合 `Condition` 进行更精细的线程间通信

```java
private final ReentrantLock lock = new ReentrantLock();

public void someMethod() {
    lock.lock();
    try {
        /* ... */
    } finally {
        lock.unlock();
    }
}
```

> 一定要在 `finally` 中释放锁，否则锁永远不会释放。

### 4. 原子类（Atomic 包）

`java.util.concurrent.atomic` 包提供了一系列原子类，底层基于 **CAS（Compare-And-Swap）** 实现无锁并发，保证原子性，性能优于锁。

| 类别 | 常用类 |
| :--- | :--- |
| 基本类型 | `AtomicInteger`、`AtomicLong`、`AtomicBoolean` |
| 引用类型 | `AtomicReference`、`AtomicStampedReference`（解决 ABA 问题） |
| 数组 | `AtomicIntegerArray`、`AtomicLongArray`、`AtomicReferenceArray` |
| 字段更新器 | `AtomicIntegerFieldUpdater`、`AtomicReferenceFieldUpdater` |

```java
AtomicInteger counter = new AtomicInteger(0);
int newValue = counter.incrementAndGet();  // 原子自增
```

### 5. 线程局部变量（`ThreadLocal`）

`ThreadLocal` 为每个线程提供独立的变量副本，**本质上是"以空间换时间"**——每个线程都有自己的专属变量，彻底消除竞争。

```java
ThreadLocal<Integer> threadLocalVar = new ThreadLocal<>();
threadLocalVar.set(10);
int value = threadLocalVar.get();
```

> ⚠️ **注意内存泄漏**：`ThreadLocalMap` 的 key 是弱引用，但 value 是强引用。使用完毕后务必调用 `remove()` 清理，尤其在**线程池场景**中（线程复用会导致 value 一直存在）。

### 6. 并发集合（Concurrent Collections）

`java.util.concurrent` 包中的线程安全集合，内部已实现线程安全逻辑，是**优先选择**——比手动加锁更高效、更可靠。

| 集合 | 对应非安全版本 | 特点 |
| :--- | :--- | :--- |
| `ConcurrentHashMap` | `HashMap` | 分段锁/JDK 1.8+ 红黑树 + CAS，高并发读 |
| `CopyOnWriteArrayList` | `ArrayList` | 写时复制，适合读多写极少 |
| `ConcurrentLinkedQueue` | — | 无锁队列，基于 CAS |
| `BlockingQueue` 系列 | — | 阻塞队列，常用于生产者-消费者模式 |

### 7. JUC 工具类

`java.util.concurrent` 包中还提供了一些同步工具类，用于控制线程间的协作：

| 工具类 | 作用 |
| :--- | :--- |
| `Semaphore` | 信号量，控制同时访问资源的线程数 |
| `CyclicBarrier` | 循环屏障，一组线程相互等待到达屏障点 |
| `CountDownLatch` | 倒计时器，一个线程等待其他 N 个线程完成 |
| `Exchanger` | 两线程间交换数据 |

## 三、如何应用 / 怎么选

### 选型速查表

| 场景 | 推荐方案 | 理由 |
| :--- | :--- | :--- |
| 简单方法同步 | `synchronized` | 最简洁，JVM 自动优化 |
| 需要灵活锁（超时/公平/可中断） | `ReentrantLock` | 功能最全 |
| 单一变量的读写 | `volatile` 或 `Atomic*` | 轻量级，无锁开销 |
| 每个线程独享变量 | `ThreadLocal` | 彻底消除竞争 |
| 高并发容器 | `ConcurrentHashMap`、`CopyOnWriteArrayList` 等 | 内部已优化，开箱即用 |
| 多线程协作（等待/通知） | `Condition`、`Semaphore`、`CyclicBarrier` | 分工明确 |
| 读多写极少 | `ReadWriteLock` / `StampedLock` | 提高读并发度 |

### 安全等级

```
synchronized / ReentrantLock  (最强互斥，但性能开销大)
    ↑
并发集合 / 原子类             (平衡性能与安全)
    ↑
volatile                      (只保证可见性)
    ↑
ThreadLocal                   (完全隔离，无竞争)
```

> **原则**：优先使用并发集合和原子类等高级工具，而非手动加锁——它们经过了大量优化和实战验证。
