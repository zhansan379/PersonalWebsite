# 如何停止一个线程的运行？

> 一句话概述：Java **没有安全的强制终止 API**（`stop()` 已废弃），正确做法是**协作式停止**——让目标线程自己决定何时退出。总结有**五种方式**：① 共享标志位（volatile boolean 循环检测）；② 中断机制（`interrupt()` 打标 + 主动响应，最通用推荐）；③ `Future.cancel()`（线程池取消任务）；④ 资源关闭（针对 Socket 等不可中断阻塞）；⑤ 暴力法 `stop()/suspend()/resume()`（已废弃，作反例）。核心区别：`interrupt()` 只是"贴个中断标记"，不会立即杀掉线程，如何响应由被中断线程自己决定。

## 一、这是什么

Java 线程**没有安全地强制终止的 API**（`stop()` 已弃用）。正确做法是**协商式/协作式停止**：让目标线程监听自己的停止信号，由它自己决定优雅退出。难点在于——线程可能在**正常运行**，也可能**阻塞在 sleep/join/wait**，还可能阻塞在**不可中断的 I/O**（如 Socket），三种状态下"怎么叫停"的方式不同。据此展开五种停止方式，面试可先抛这个分类框架再逐条展开。

## 二、核心内容：停止线程的五种方式

### 方式 1 · 共享标志位（最简单，适合无阻塞逻辑）

定义一个 `volatile` 的 `running` 标志位，由外部线程置 false，工作线程在循环里检测该变量决定是否退出。**`volatile` 保证跨线程可见性**（标志位修改能立刻被工作线程看到）：

```java
private volatile boolean running = true;

@Override
public void run() {
    while (running) {
        try {
            System.out.println("Thread is running...");
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            running = false;
            Thread.currentThread().interrupt(); // 重新设置中断标志
        }
    }
    System.out.println("Thread terminated safely.");
}

public void stop() { running = false; } // 外部调用，置 false 让线程退出
```

- 特点：直接、可读，用业务语义（running）表达停止意图。
- 局限：适合**简单、无耗时阻塞**的逻辑；若线程长时间阻塞在不响应中断的操作里，标志位检测不到，仍无法及时停。

### 方式 2 · 中断机制（最通用，推荐）

线程 A 调目标线程的 `interrupt()` 打标，目标线程**主动响应**。它分两种响应场景：

**a) 运行中——打标 + 轮询退出（异常法 / return 法）**

线程正在跑非阻塞代码时，`interrupt()` 只设置中断标志；目标线程在 `run()` 里轮询 `isInterrupted()` 判断是否退出（可抛异常、也可直接 return，思想相同）：

```java
public void run() {
    while (!Thread.currentThread().isInterrupted()) {
        // 干活的代码
    }
    // 收到中断，主动退出
}
```

**b) 沉睡/阻塞中——解除阻塞抛 `InterruptedException`（沉睡中停法）**

线程先 `sleep()`/`wait()`/`join()` 阻塞，被 `interrupt()` 后立即解除阻塞并抛 `InterruptedException`，在 catch 里按需退出：

```java
try {
    Thread.sleep(1000);
} catch (InterruptedException e) {
    Thread.currentThread().interrupt(); // 恢复中断标志，交给外层决定
    // 或直接 return 退出
}
```

> ⚠️ **要点**：判断用 `Thread.currentThread().isInterrupted()`，**不要用静态方法 `Thread.interrupted()`**——后者读取后会**清除中断标志**，导致状态丢失；`catch (InterruptedException)` 后若自己不处理而交给上层，应调用 `Thread.currentThread().interrupt()` **恢复中断标记**。

### 方式 3 · Future.cancel()（线程池 / 异步任务取消）

通过线程池提交任务拿到 `Future`，调用 `future.cancel(true)` 尝试取消任务——`true` 表示**尝试中断任务的执行线程**。底层的取消机制仍是"中断"，所以任务本身需支持中断响应：

```java
ExecutorService executor = Executors.newSingleThreadExecutor();
Future<?> future = executor.submit(() -> {
    while (!Thread.currentThread().isInterrupted()) {
        System.out.println("Task running...");
        try {
            Thread.sleep(1000);
        } catch (InterruptedException e) {
            System.out.println("Task interrupted.");
            Thread.currentThread().interrupt();
        }
    }
});

future.cancel(true); // true = 尝试中断任务线程
executor.shutdown();
```

- 特点：把"停止"提升到**任务/句柄**层面，适合线程池管理的异步任务，与 `Future.get()` 配套。
- 局限：依赖底层中断机制；`cancel(false)` 只取消未执行任务、不中断正在执行的。

### 方式 4 · 资源关闭（处理不可中断的阻塞）

某些 I/O 或同步操作（如 `Socket.accept()`、`Lock.lock()`）**无法响应中断**。此时只能**显式关闭资源**来解除阻塞——关闭 Socket 会让 `accept()` 抛异常退出：

```java
public class SocketHandler implements Runnable {
    private ServerSocket serverSocket;

    @Override
    public void run() {
        try {
            while (!Thread.currentThread().isInterrupted()) {
                Socket socket = serverSocket.accept(); // accept() 阻塞时无法响应中断
                // 处理连接...
            }
        } catch (IOException e) {
            if (Thread.currentThread().isInterrupted()) {
                System.out.println("Thread stopped by interrupt.");
            }
        }
    }

    public void stop() {
        try {
            serverSocket.close(); // 关闭资源使 accept() 抛异常退出，解除阻塞
        } catch (IOException e) {
            System.out.println("Error closing socket: " + e);
        }
    }
}
```

- 特点：是"中断机制"的补充——中断叫不醒的场景，用**关闭资源触发异常** + 结合中断标志判断回滚/退出。
- 适用：Socket、IO、锁等不可中断的阻塞操作。

### 方式 5 · 暴力停止（已废弃，作反例）

- `Thread.stop()`：立即强制终止线程，**跳过 finally/锁释放等清理**，会造成资源泄漏、数据不一致，已弃用。
- `Thread.suspend()/resume()`：**易导致死锁**（暂停时可能正持有锁），已弃用。
- 结论：**绝不用**，面试点出"为什么弃用"即为加分项。

### 方法速查表

| 方式 | 适用场景 | 注意事项 |
| :--- | :--- | :--- |
| 共享标志位 | 简单、无阻塞的逻辑 | 标志位必须用 `volatile`（或用锁）保证可见性 |
| 中断机制 | 可中断的阻塞操作 | 正确处理 `InterruptedException` 并**恢复中断标志** |
| Future.cancel(true) | 线程池管理任务 | 任务需支持中断处理；cancel(false) 不中断执行中任务 |
| 资源关闭 | 不可中断的阻塞（Socket/锁） | 显式关闭资源触发异常，结合中断状态判断回滚/退出 |
| stop/suspend/resume | 无（已废弃） | 会破坏清理/死锁，绝不能在生产用 |

## 三、核心机制：interrupt() 是如何让线程知道该停的？

每个线程都有一个中断状态（bool，初始 false）。当别处调 `Thread.interrupt()`，JVM **根据该线程当前所处状态**做出不同响应：

- **正执行可中断的阻塞方法**（`Thread.sleep()`、`Thread.join()`、`Object.wait()`、`lockInterruptibly`）→ **立即解除阻塞**并抛 `InterruptedException`。
- **正在运行（非阻塞）** → 仅设置中断标志，线程继续跑；要靠轮询 `isInterrupted()` 自己判断是否退出。
- **不可中断的阻塞**（`Socket.accept()`、`Lock.lock()` 等）→ **中断无效**，只能通过关闭资源等方式让阻塞抛出异常。

> **一句话**：阻塞中的线程被 interrupt 会立刻抛异常醒来；运行中的线程被 interrupt 只是被"贴了标记"；不可中断的阻塞连标记都叫不醒——分别对应上面的方式 2、方式 1/2、方式 4。

## 四、如何应用 / 面试怎么讲

**加分表达：**
- 先摆总原则：**Java 不提供安全的强制终止，靠协作式停止**——这一句体现"懂设计"，避免踩 `stop()` 的坑。
- 主动给**五种方式分类**再逐个展开：标志位最简单、中断最通用、Future 适合线程池、资源关闭针对不可中断阻塞、暴力法作反例——比零散背强得多。
- 能讲清 interrupt() **不是命令而是"提议/标记"**，真正响应的是被中断线程自己（轮询 isInterrupted 或抛 InterruptedException）。
- 区分**三种中断响应**：阻塞中抛异常醒来 / 运行中打标稍后轮询 / 不可中断阻塞需关资源。
- 点出 `isInterrupted()` vs `Thread.interrupted()` 的**清除标志差异**，以及 volatile 标志位的可见性依据。

**追问预案：**

| 追问 | 应答案点 |
| :--- | :--- |
| interrupt() 会立即停线程吗？ | 不会，它只设置中断标志；线程是否停由被中断线程自己决定（协作式） |
| stop() 为什么不安全/弃用？ | 强制终止会跳过 finally/锁释放等清理，可能造成资源泄漏、数据不一致 |
| isInterrupted() 和 interrupted() 区别？ | `Thread.currentThread().isInterrupted()` 只读不清除；静态 `Thread.interrupted()` 读取后会把标志清除 |
| 共享标志位中断法该用哪种？ | 都得用起来：标志位法简单直观但治不了长时间不可中断阻塞；中断法更通用、能唤醒可中断阻塞。两者可结合（catch 里置 false + interrupt） |
| 共享标志位为什么用 volatile？ | 保证标志位的**跨线程可见性**，避免工作线程缓存旧值而看不到停止信号 |
| Future.cancel(true) 的底层？ | 底层就是中断机制——`cancel(true)` 会对执行任务的线程调 `interrupt()`；任务需响应中断才真正停 |
| 阻塞中线程被中断会怎样？ | 正在 sleep/join/wait 的线程立即解除阻塞并**抛 InterruptedException** |
| 运行中（非阻塞）线程被中断？ | 只设置中断标志，线程继续跑；要靠轮询 `isInterrupted()` 自行判断退出 |
| 不可中断的阻塞（Socket.accept）怎么停？ | interrupt 无效；需**显式关闭资源**（close Socket）令 accept() 抛异常，再结合中断状态判断退出 |
| 捕获 InterruptedException 后该不该恢复标志？ | 若自己不处理而交给上层，应 `Thread.currentThread().interrupt()` 恢复标志，避免状态丢失 |
| 用 shutdownNow() 停线程和 stop() 一样吗？ | 不一样：`ExecutorService.shutdownNow()` 是向工作线程发 `interrupt()`（协作式优雅中断），而非强制杀线程 |
