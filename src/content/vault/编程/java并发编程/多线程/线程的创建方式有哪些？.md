# 线程的创建方式有哪些？

> 一句话概述：Java 有四类创建线程的写法——**继承 `Thread`**、**实现 `Runnable`**、**实现 `Callable` + `FutureTask`**（可选返回结果）、**线程池（Executor 框架）**。前三者是"怎么造一个线程"，第四类是"怎么复用一堆线程"。核心取舍是：任务无返回值用 Runnable 最省事，要返回值用 Callable+FutureTask，日常多用线程池避免频繁创建销毁。

## 一、这是什么

四种方式本质是两种思路：**① 手工造线程**（Thread/Runnable/Callable 都要 new 一个 Thread 对象，用完即弃）和 **② 线程池复用**（预创建一批线程反复干活）。下面按从无返回值到有返回值、再到复用的递进顺序讲。

## 二、核心内容：四类创建方式

### 1. 继承 Thread 类（最直接）

自定义类继承 `java.lang.Thread` 并重写 `run()`（run 里是线程要执行的任务），new 出实例后调 `start()` 启动：

```java
class MyThread extends Thread {
    @Override
    public void run() {
        // 线程执行的代码
    }
}

public static void main(String[] args) {
    MyThread t = new MyThread();
    t.start();
}
```

- **优点**：编写简单；想访问当前线程时直接用 `this` 即可，无需 `Thread.currentThread()`。
- **缺点**：线程类已继承 Thread，**不能再继承其他父类**（Java 单继承限制）。

### 2. 实现 Runnable 接口（更灵活、常用）

若类已继承其他类，就不能继承 Thread，此时实现 `java.lang.Runnable`、重写 `run()`，再把 Runnable 对象作为参数传进 Thread 构造器，`start()` 启动：

```java
class MyRunnable implements Runnable {
    @Override
    public void run() {
        // 线程执行的代码
    }
}

public static void main(String[] args) {
    Thread t = new Thread(new MyRunnable());
    t.start();
}
```

- **优点**：实现接口，**仍可继承别的类**；多个线程可共享同一个目标对象，非常适合多个相同线程处理同一份资源，把 CPU 代码和数据分开，模型清晰、更符合面向对象。
- **缺点**：编程稍复杂；想访问当前线程要用 `Thread.currentThread()`。

### 3. 实现 Callable 接口 + FutureTask（能取结果）

`java.util.concurrent.Callable` 与 Runnable 类似，但 `call()` **可以有返回值且能抛异常**。因为 Thread 构造器只接受 Runnable，而 `FutureTask` 实现了 Runnable，所以把 Callable 包装进 FutureTask 再交给 Thread 执行，最后 `get()` 取结果：

```java
class MyCallable implements Callable<Integer> {
    @Override
    public Integer call() throws Exception {
        // 线程执行的代码, 这里返回一个整型结果
        return 1;
    }
}

public static void main(String[] args) {
    MyCallable task = new MyCallable();
    FutureTask<Integer> futureTask = new FutureTask<>(task);
    Thread t = new Thread(futureTask);
    t.start();

    try {
        Integer result = futureTask.get();  // 获取线程执行结果（阻塞直到有结果）
        System.out.println("Result: " + result);
    } catch (InterruptedException | ExecutionException e) {
        e.printStackTrace();
    }
}
```

- **优点**：只实现 Callable 接口，**仍可继承其他类**；`call()` 有返回值、可抛异常，配合 FutureTask 能方便地拿到**异步执行结果**。
- **缺点**：编程稍复杂；访问当前线程需 `Thread.currentThread()`。

### 4. 使用线程池（Executor 框架，最高效）

Java 5 起引入 `java.util.concurrent.ExecutorService` 及相关类提供线程池，**复用线程、避免频繁创建和销毁**。用 `Executors` 静态方法创建不同类型的池，`submit` 提交任务，`shutdown` 关闭：

```java
class Task implements Runnable {
    @Override
    public void run() {
        // 线程执行的代码
    }
}

public static void main(String[] args) {
    ExecutorService executor = Executors.newFixedThreadPool(10); // 创建固定大小的线程池
    for (int i = 0; i < 100; i++) {
        executor.submit(new Task()); // 提交任务到线程池执行
    }
    executor.shutdown(); // 关闭线程池
}
```

- **优点**：重用预创建线程，**避免反复创建/销毁的开销**，显著提性能；并发请求能快速得到线程处理，减少等待；能**控制运行线程数量**，防止创建过多线程导致资源耗尽（如内存溢出），合理配置可最大化 CPU 利用率和吞吐。
- **缺点**：增加程序复杂度，线程池参数调整与故障排查难度高；错误配置可能引发**死锁、资源耗尽**等问题，且诊断修复较复杂。

## 三、如何应用 / 面试怎么讲

**加分表达：**
- 按"**有无返回值 + 是否复用**"给四者分层：无返回值用 Runnable（能继承别的类、可共享对象），有返回值用 Callable+FutureTask（`get()` 取结果），并发量大用线程池；继承 Thread 尽量少用（锁死继承，且把任务和线程揉一起）。
- 点出 **Runnable vs Thread** 的本质：Runnable 是"任务"、Thread 是"能跑任务的载体"——把两者分开才谈得上复用和共享，这是面试官喜欢听到的"理解"。
- 主动提 **Callable + FutureTask 能取返回值的价值**，并自然引到 `ExecutorService.submit` 返回 `Future` → 升维到 CompletableFuture。
- 线程池部分强调**复用带来的性能优劣势都源于"预创建+复用"**，避免优点缺点各背一遍。

**追问预案：**

| 追问 | 应答案点 |
| :--- | :--- |
| 为什么不推荐继承 Thread？ | 单继承锁死子类不能再继承别的；且把"任务逻辑"和"线程本身"耦合成一个类，难复用、难共享数据 |
| Runnable 和 Callable 区别？ | Runnable 的 `run()` 无返回值、不能抛受检异常；Callable 的 `call()` 有返回值、能抛异常 |
| 三种手工方式里，哪个能取结果？ | 只有 Callable + FutureTask（`get()` 阻塞取结果）；Thread 和 Runnable 的 run() 都没有返回值 |
| `start()` 和直接调 `run()` 区别？ | `start()` 让 JVM 新建线程去执行 run（异步）；直接调 `run()` 是**当前线程同步执行**普通方法，没有开新线程 |
| 多次调用 start() 会怎样？ | 抛出 `IllegalThreadStateException`，一个线程只能启动一次 |
| 线程池相比手工创建的好处？ | 复用线程省创建/销毁开销；控制并发线程数防资源耗尽；任务提交调度统一管理 |
| 为什么 submit 能返回结果？ | `ExecutorService.submit(Callable)` 返回 `Future`；线程池内部用 Callable 包裹任务，故有返回值（Runnable 任务 submit 也包成 Callable） |
| 线程池会不会让任务丢失？ | 取决于**队列与拒绝策略**：队列有界且满 + 到达 maximum 后触发拒绝策略（抛异常/调用者执行/丢弃等），处理不当才丢任务（详见线程池参数笔记） |
