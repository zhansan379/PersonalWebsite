## 一、优惠券的本质与目的
- **本质**：通过让利促进商品销售，是刺激消费的营销手段。
- **应用场景**：拼多多/淘宝购物券、美团外卖神券等。

---

## 二、优惠券的来源
| 类型 | 创建方 | 成本承担 |
|------|--------|----------|
| **平台券** | 平台创建，用户领取后提交订单 | 平台与商家共同分摊 |
| **店铺券** | 店铺自行创建 | 全部由店铺承担 |

---

## 三、优惠券的类型
| 类型 | 规则 | 示例 |
|------|------|------|
| **折扣券** | 订单满足最低金额后，按比例打折 | 满100打7折，即优惠30元 |
| **满减券** | 订单满指定金额后，减固定金额 | 满10.01元减10元 |
| **立减券** | 无条件立即生效，但金额通常很小 | 防止出现“商品1元、券30元”倒贴情况 |

---

## 四、优惠券的使用限制
- **有效期**：领取时间限制 + 使用期限（如领取后N小时内有效）。
- **商品限制**：
  - 小额券（1~2元）通常全品类通用；
  - 大额券仅限指定商品，价格也更高。
- **领取次数**：同一用户可重复领取的上限，超过后无法再领。

## 五、系统架构概览

![[Pasted image 20260902174619.png]]
### 1. 展现层（用户触达渠道）
- APP、Web、小程序、公众号
- 示例：美团通过小程序/群聊发放优惠券，多渠道促进消费。

### 2. 应用层（核心业务模块）
- **主要模块**：商家管理引擎、结算模块等
- **技术挑战**：
  - 秒杀抢券、高并发处理
  - 订单计算可用优惠券并核销
  - 应对流量高峰（防雪崩、消息队列异步解耦、延迟消息）
  - 百万级Excel导入、内存管理、限流熔断
- **设计目标**：高内聚、低耦合、可扩展（应用设计模式）
![[Pasted image 20260902174810.png]]
### 3. 数据层
- **数据库**：MySQL（通过Sharding-JDBC分库分表）
- **搜索引擎**：Elasticsearch（通过Canal同步数据，支持搜索）
- **缓存**：Redis集群（提升接口响应）
- **消息队列**：RocketMQ（异步解耦 + 任意延时消息）

### 4. 基础设施层
- **部署方式**：云服务器（以阿里云为例）
  - 对象存储OSS、ECS、SLB负载均衡
- **性能测试**：PTS（性能测试服务）
- **监控**：Prometheus + Grafana 大屏展示

## 六、云上技术架构（Spring Cloud体系）

![[Pasted image 20260902174740.png]]
### 请求流转路径
用户（手机/PC）→ Nginx → Spring Cloud Gateway → 微服务

### 为什么同时使用 Nginx 和 Gateway？
| 组件 | 职责 |
|------|------|
| **Nginx** | ① 高性能限流/风控，防无效请求；② 对Gateway做负载均衡；③ HTTP代理；④ 前端静态资源访问 |
| **Spring Cloud Gateway** | ① 原生适配Spring Boot/Cloud；② 支持复杂路由、过滤器（日志、鉴权、限流）；③ 用Java编写，易维护 |

### 其他关键组件
- **注册/配置中心**：Nacos（服务发现与配置管理）
- **链路追踪**：SkyWalking（监控微服务调用链及性能瓶颈）
- **限流熔断**：Sentinel
- **定时任务**：XXL-JOB（分布式调度）
- **消息队列**：RocketMQ 5.0（支持任意延迟消息，基于时间轮算法）
- **缓存**：Redis
- **数据库**：MySQL（分库分表）

## 七、典型业务场景：秒杀/兑换优惠券
- **两种场景**：
  1. 低吸引力券：按需领取，无库存压力；
  2. 高吸引力券：限时限量秒杀，需应对高并发和库存扣减。

## 八、总结
- 优惠券系统涵盖营销规则、用户限制、高并发处理、分布式架构等多个维度。
- 技术选型强调性能、扩展性和可维护性，核心依赖 MySQL + Redis + RocketMQ。
- 网关层采用 Nginx + Gateway 分工协作，各司其职。
