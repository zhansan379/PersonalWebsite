# LLM Wiki

> LLM Wiki 是一种用 LLM 构建和维护个人知识库的方法论。核心理念：不是每次查询时去原始文档中检索（RAG），而是让 LLM 增量构建并持续维护一个结构化的 wiki。

## 一、背景与动机

### 1.1 RAG 的局限

传统的 RAG（Retrieval-Augmented Generation）模式存在几个问题：

- **重复检索成本高**：每次查询都需要重新检索和推理，同一份材料被反复处理
- **知识碎片化**：检索结果是一次性的，无法积累为结构化知识
- **缺乏全局视野**：每次只看到与当前查询相关的片段，看不到知识的全貌
- **无法迭代优化**：检索结果无法被修正、补充、重组

### 1.2 LLM Wiki 的思路

与其每次"临时抱佛脚"，不如让 LLM 像图书管理员一样：

1. 读一次原始材料
2. 提炼出结构化知识
3. 存入 wiki
4. 持续维护和优化

这样每次查询时，LLM 直接读取已经整理好的结构化知识，又快又准。

## 二、核心架构

### 2.1 三层分离

```
raw/  ──── 提取 ────→  wiki/  ←────  CLAUDE.md
(不可变源材料)         (结构化知识)      (维护规范)
```

三层各司其职，互不越界。详见 [[三层架构]]。

### 2.2 关键设计决策

| 决策 | 理由 |
|---|---|
| raw 不可变 | 保留原文作为"真理之源"，防止知识在提取中失真 |
| wiki 结构化 | 原子化页面 + 丰富链接 = 可导航的知识网络 |
| CLAUDE.md 显式化 | 把维护规则写下来，LLM 才不会"自由发挥" |

## 三、工作流程

```
放入 raw → LLM 阅读 → 提取知识到 wiki → 更新 index → 审阅迭代
```

### 3.1 各步骤详解

1. **放入 raw**：用户将原始材料放入 `raw/`。可以是文章、论文、书籍笔记、网页存档等。命名格式：`YYYY-MM-DD 来源-标题.md`。

2. **LLM 阅读**：LLM 完整阅读 raw 中的材料。这一步不可跳过——LLM 需要有全局理解才能做好的提取。

3. **提取知识**：LLM 将材料中的知识提炼为独立的 wiki 页面。关键操作：
   - 识别核心概念 → 创建或更新对应页面
   - 发现概念间的关系 → 建立链接
   - 抽象出方法论 → 独立成页
   - 提取关键数据和引用 → 补充到相关页面

4. **更新 index**：在 `wiki/index.md` 中注册新页面，调整已有页面的分类。

5. **审阅迭代**：用户审阅提取结果。可以：
   - 确认提取内容准确
   - 补充遗漏的知识
   - 修正理解偏差
   - 要求重新组织

## 四、与传统方法的对比

| 维度 | 传统笔记 | RAG | LLM Wiki |
|---|---|---|---|
| 知识结构 | 依赖人工整理 | 无持久结构 | LLM 自动结构化 |
| 检索方式 | 人工搜索/浏览 | 语义检索 | 直接读取结构化页面 |
| 维护成本 | 高（人工） | 低（自动） | 中（LLM 辅助） |
| 知识积累 | 线性增长 | 不积累 | 复利增长 |
| 可迭代性 | 低 | 无 | 高 |

## 五、适用场景

### 5.1 最适合

- **研究型知识管理**：需要深入理解一个领域，积累大量材料
- **长期项目**：知识需要持续积累和迭代
- **多来源整合**：需要融合来自文章、论文、书籍、网页的知识
- **团队知识库**：多人共享和维护（各自放入 raw，LLM 统一提取）

### 5.2 不太适合

- 临时性信息收集（用临时笔记更合适）
- 高度私密的个人日记（不需要结构化提取）
- 一次性参考材料（看完就扔）
