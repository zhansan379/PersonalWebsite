> 责任链的面试考点不是"定义背得熟不熟"，而是：**你能不能讲清"什么时候该用它、它和 if-else / 拦截器 / 装饰器什么关系、链条怎么保证正确"。** 本文整理回答主线、记忆锚点与被追问清单。

## 一、回答主线（三段式，别超 1.5 分钟）

**1. 一句话定位**（先定性）
> 一种**行为型模式**（GoF 分类）：把多个独立的处理逻辑串成一条**链**，请求从链头进入，每个节点要么自己处理终止，要么转发给下一个节点。发起方只依赖链头，不知道后面有多少节点。

**2. 核心价值**（讲"为什么用"，对照 if-else）
- **解耦**：请求方只认链头，不感知参与节点数量。
- **开闭原则**：要加一个校验/处理逻辑，只新增一个节点并挂链即可，**不改动任何已有节点代码**。
- **可配置**：同样一组节点，按接口/场景灵活组装顺序、增删节点（甚至可配置化）。

**3. 一个标志性场景**（接口校验链，方便记忆）
> 登录态 → Token 有效性 → 权限 → 频率限制。登录接口只需验验证码，查询接口要过登录+权限——用责任链，每个接口组不同的链，而不是每个接口写一堆 if-else。

> **加分的一句话**："SpringMVC 的拦截器链、Servlet 的 FilterChain、Spring Security 的过滤器链，本质都是责任链思想；Java 里最常见的落地是构建者链式 `setNext(...)` 拼接。" —— 把模式挂到框架原理上，面试官立刻知道你见过真场景。

## 二、必须能说出的记忆锚点

1. **三类参与者**：抽象处理者 `Handler`（持 next 指针+抽象 handle）、具体处理者（各自实现）、组装方（构建链）。
2. **两个转发方向**：条件满足→往下传；条件不满足→**终止链**（返回失败）——这是关键语义。
3. **核心价值三连**：解耦 / 开闭 / 可配置。
4. **经典代码**：`Handler.setNext(...)` 链式返回自身（builder 风味）、`handle()` 内 `return next != null ? next.handle(req) : true;`。
5. **两种请求终止形态**：①返回 boolean 短路（校验链，遇到失败停）；②一直传到链表尾兜底处理（中间件/日志链）。

## 三、五类被追问清单

### Q1：责任链和 if-else 的区别？什么时候值得上责任链？
**答**：
- if-else 把"判断逻辑"和"业务代码"揉在一起，节点一多就难维护、难复用、难扩展（加规则要改入口方法，违反开闭）。
- 责任链每个节点独立成类 = **单一职责 + 可复用 + 可插拔**。
- 但责任链也有成本：节点数多、链条结构冗余、调试时栈更长。
- **判断标准**：当处理节点 ≥ 3 个、且可能动态增删顺序、且希望加节点不改已有代码时，值得上；一两步校验用 if-else 反而更简单。**面试加分：说出"过度设计也是坑"，比一味用模式强。**

### Q2：责任链和"拦截器 / Filter / Spider 中间件"什么关系？
**答**：是**同一思想的不同落地**。Servlet FilterChain、Spring MVC Interceptor、Spring Security 过滤器链、Netty 的 pipeline、Express/Koa 中间件，底层都是"请求→节点序列→可拦截可放行"的责任链变体。区别多在**变体语义**：
- 传统责任链常见"一对一选一个节点处理"；
- 中间件/过滤器链条通常"逐级放行，可提前拦截，也可多个节点都处理"。

### Q3：手写链要注意什么坑？
**答**：
- **循环链 / 断链**：`setNext` 拼错可能成环死循环，或漏接导致请求到不了终点兜底节点——生产里建议加"链尾兜底节点 + 构建时校验环"。
- **判空**：末尾节点 `next == null` 时 `next.handle()` 会 NPE，模板里要习惯性判空。
- **终止语义要统一**：区分"处理完继续往下" vs "处理后终止"，不同场景不要混淆。
- 纯手写链不好排错/不好并发。工程上常直接用现成框架（Spring Security 的 filter chain、Netty pipeline），或配合**建造者模式**优雅组装。

### Q4：能实现"动态增删/调整顺序"吗？怎么做？
**答**：这也是责任链的卖点之一：
- **改代码**：链组装处增删 `setNext` 即可（仍要改组装代码）。
- **配置化**：把节点顺序/是否生效放到**配置文件/注册表**（如 Bean 列表按 `@Order` 排序注入），运行时按配置拼链，达到"加节点不改代码、只改配置"。
- 注意：更复杂的运行时热插拔需要额外的生命周期管理，一般业务用编译期+配置化组装足够。

### Q5：责任链 vs 装饰器 vs 策略 vs 观察者，怎么区分？
**答**（这道题专治"只会背名字"）：
- **责任链**：一堆处理者，请求**按顺序流经**，每个可决定"终止或放行"，总体是一根**流水线**。
- **装饰器**：给**同一对象**逐层"增强"，外层包内层，职责是叠加能力而非判断是否放行。
- **策略**：在多个算法里**二选一（互斥）**，把可替换的算法家族拆开，不是链式流转。
- **观察者**：一对多"广播"通知，**发布者不关心谁在听**，无请求流转、无拦截。
- 一句话：责任链=流水线上可能有多个节点处理同一请求的流转；策略=互斥选择一个；装饰=层层增强同一个；观察者=一对多通知。

### Q6：框架层——Spring Security / MyBatis 插件 / Netty 里的责任链你了解多少？（进阶加分）
**答**：
- **Spring Security**：过滤器链（FilterChainProxy 一串 SecurityFilter），每步认证/授权可放行或拦截。
- **MyBatis 插件**：基于 `Interceptor` + 动态代理织入 Executor，也是责任链形态（可 ordered 排序）。
- **Netty pipeline**：每个 ChannelHandler 是链上节点，加了可 `fireXXX` 沿链传递事件。
- 提这些一是证明"模式有真实落地"，二是展示"从框架里识别设计模式"的能力。

## 四、代码记忆模板（背这版即可）

```java
// 抽象处理者
abstract class Handler {
    protected Handler next;
    public Handler setNext(Handler next) { this.next = next; return this; } // 可链式
    public abstract boolean handle(Request req);
}

// 具体节点：满足则传给下一位，否则终止
class LoginHandler extends Handler {
    @Override
    public boolean handle(Request req) {
        if (req.isLogin()) return next != null ? next.handle(req) : true;
        return false; // 校验失败，终止链条
    }
}

// 组装：LoginHandler→AuthHandler→RateLimitHandler
new LoginHandler()
  .setNext(new AuthHandler())
  .setNext(new RateLimitHandler())
  .handle(req);
```
