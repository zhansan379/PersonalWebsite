# 类的生命周期：初始化阶段

> 连接阶段结束后，类信息已在内存中、校验与前置准备均已完成。初始化阶段是**唯一与程序员有关**的阶段，也是**大厂笔试题的高发区**。
> 一句话概括：**初始化阶段就是执行字节码中的 `<clinit>` 方法——执行静态代码块，并为静态变量赋上代码里写的值。**

## 一、`<clinit>` 是什么

| 拆解 | 含义 |
|---|---|
| `cl` | **cl**ass 的前两个字母，代表「类」 |
| `init` | initialization，初始化 |
| `<clinit>` | **类的初始化**方法 |

连接的准备阶段中，非 `final` 静态变量保存的只是**初值（零值）**，存放在堆里的 `Class` 对象中。而**把它变成代码里写的值**这个操作，就发生在初始化阶段。

**初始化阶段做两件事：**
1. 执行**静态代码块**中的代码
2. 为**静态变量赋值**

### 1.1 字节码视角：`putstatic` 指令

以 `static int value = 1;` + `static { value = 2; }` 为例，编译后类中共有**三个方法**：

| 方法 | 说明 |
|---|---|
| `<init>` | 构造方法——即使没写，编译器也会生成默认无参构造 |
| `main` | 主方法 |
| **`<clinit>`** | **类的初始化方法**（本节重点） |

`<clinit>` 的字节码指令：

```
iconst_1        // 将常量 1 放入操作数栈
putstatic #2    // 给静态变量赋值
iconst_2        // 将常量 2 放入操作数栈
putstatic #2    // 再次赋值
```

**`putstatic` 指令（查规范得出）：**

> 作用：给类中的**静态字段赋值**。
> **哪个字段要赋值** → 从**常量池**中获取（参数即常量池编号）
> **赋什么值** → 从**操作数栈**中弹出

**执行过程拆解：**

| 步骤 | 操作数栈 | `value` 的值 |
|---|---|---|
| 连接·准备阶段结束 | — | `0`（零值） |
| `iconst_1` | `[1]` | `0` |
| `putstatic #2` | `[]` | **`1`** |
| `iconst_2` | `[2]` | `1` |
| `putstatic #2` | `[]` | **`2`** |

### 1.2 ⚠️ 核心结论：`<clinit>` 中指令顺序 == 源码编写顺序

**把源码顺序颠倒：静态代码块写在前面，静态变量声明写在后面**

```java
static { value = 2; }      // 先写
static int value = 1;      // 后写
```

字节码中 `2` 和 `1` 两行**对应颠倒**，其余不变。执行流程：

```
准备阶段：value = 0（零值）
→ 执行静态代码块：value = 2
→ 执行静态变量赋值：value = 1
最终结果：1
```

> **必须记住的结论**：`<clinit>` 中字节码指令的执行顺序与 **Java 源码的编写顺序完全一致**。
> **常见错误认知**：以为「先把 `value` 赋成 1，再执行静态代码块变成 2」，从而答成 2 —— **这是错的**。

## 二、触发类初始化的四种方式

**验证手段**：
- JVM 参数 **`-XX:+TraceClassLoading`**（`+` 表示开启功能）→ 打印当前程序加载并初始化的类
- 或直接在静态代码块中打印一行内容

| # | 触发方式 | 注意点 |
|---|---|---|
| 1 | **访问类的静态变量或静态方法** | **⚠️ 例外**：若变量被 `final` 修饰**且等号右边是常量**，则在**准备阶段**就已赋值，访问它**不会**触发初始化 |
| 2 | **`Class.forName(类名)`** | 会触发**加载和初始化**，不管你有没有使用返回的 `Class` 对象 |
| 3 | **`new` 关键字创建对象** | — |
| 4 | **执行主方法（`main`）** | `main` 所在的类**一定会**被加载并初始化，且**优先**于其他类 |

### 2.1 `Class.forName` 的重载细节（加分点）

| 重载 | 行为 |
|---|---|
| `Class.forName(String name)` | 内部调用 `forName0(...)`，其第二个参数（是否初始化）**默认为 `true`** → **会初始化** |
| `Class.forName(String name, boolean initialize, ClassLoader loader)` | 第二个参数可传 **`false`**，此时**只加载不初始化** |

### 2.2 实测验证结论

| 实验 | 结果 |
|---|---|
| `static int i = 0;`（无 `final`），`main` 中访问 `Demo2.i` | 打印「初始化了」；`TraceClassLoading` 中能搜到 `Demo2` |
| 改为 **`static final int i = 0;`** | **不打印**「初始化了」；`TraceClassLoading` 中**搜不到** `Demo2` |
| `Class.forName("...Demo4")` | 打印「初始化了」 |
| `main` 在 `Demo5`，其中 `new Demo6()` | **先**打印「Demo5 初始化了」（main 所在类优先），执行到 `new` 时**再**打印「Demo6 初始化了」 |

## 三、笔试题一：`DACBCB`（构造方法 vs 代码块 vs 静态代码块）

```java
public class Test1 {
    public Test1() { System.out.println("B"); }   // 构造方法
    { System.out.println("C"); }                  // 实例代码块
    static { System.out.println("D"); }           // 静态代码块

    public static void main(String[] args) {
        System.out.println("A");
        new Test1();
        new Test1();
    }
}
```

### 3.1 解题步骤

**第一步：执行 `main` 前，`Test1` 必须先被加载并初始化** → 执行 `<clinit>`

`<clinit>` 的三行字节码作用合起来就是「打印字符串 D」：
- 从**常量池**把字符串 `"D"` 加载到操作数栈
- 调用 `println` 方法打印操作数栈上的内容

> 这三行指令可以简单理解成一组，作用就是「打印一个字符串」。

→ 输出 **`D`**

**第二步：执行 `main` 第一行** → 输出 **`A`**（此时结果为 `DA`）

**第三步：`new Test1()` 两次**

⚠️ 虽然 `new` 了对象，但 **`Test1` 已经被加载过，不会再次被加载和初始化**。

用 jclasslib 查看方法，可以看到**三个方法**：

| 方法 | 内容 |
|---|---|
| `main` | 主方法 |
| **`<init>`** | 构造方法 —— **实例代码块编译后被放到了这里** |
| `<clinit>` | 类的初始化方法 |

**关键发现**：**实例代码块**（打印 C）在**编译阶段**就被编译进了**构造方法的字节码指令**中，且**位置在原构造方法代码（打印 B）之前**。

→ 每次 `new` 输出 **`CB`**，两次即 `CBCB`

### 3.2 最终答案

```
D A C B C B  →  DACBCB
```

### 3.3 提炼的两条结论

> - **类的加载和初始化，一般只会执行一次**
> - **构造方法每创建一个对象就执行一次**（可执行多次）

## 四、`<clinit>` 不会生成的三种情况

> **不要认为初始化阶段一定存在。** 以下三种情况 JVM 认为初始化阶段什么都不用做，编译器**不会生成 `<clinit>` 方法**：

| # | 情况 | 说明 |
|---|---|---|
| 1 | **没有静态代码块，也没有对静态变量赋值** | 类中只有 `main` 方法时，jclasslib 里压根找不到 `<clinit>` |
| 2 | **只有静态变量的声明，没有赋值语句** | 如 `static int i;` → 依然没有 `<clinit>` |
| 3 | **静态变量被 `final` 修饰且右边是常量** | 如 `static final int i = 10;` → 在**准备阶段**就直接初始化了 |

**实测对照**：把第 3 种的 `final` 去掉（变成 `static int i = 10;`）后重新编译 → **`<clinit>` 立即出现**，其中就是把 `i` 赋值为 10 的指令。

## 五、继承场景下的初始化（笔试题二）

### 5.1 两条核心规则

> - **直接访问父类的静态变量，不会触发子类的初始化**（只初始化父类）
> - **初始化子类之前，一定会先初始化父类**

### 5.2 2021 年大厂笔试题

```java
class A02 {
    static int a = 0;
    static { a = 1; }
}
class B02 extends A02 {
    static { a = 2; }
}
// main 中：
new B02();
System.out.println(B02.a);
```

**分析**：`new B02()` 要初始化子类 → **先初始化父类** `A02`，执行父类静态代码块 `a = 1` → 再初始化子类 `B02`，执行 `a = 2`

→ **答案：`2`**

**变式：把 `new B02();` 去掉**

`a` 本身定义在父类中，直接打印 `B02.a` 只需访问父类即可 → **只初始化父类**，`a = 1`

→ **答案：`1`**

## 六、两个自行验证的练习题（结论已给）

| # | 结论 |
|---|---|
| 1 | **数组的创建不会导致数组中元素的类进行初始化**。如 `new Test2A[10]` 执行完，`Test2A` 类**不会**初始化 |
| 2 | **`final` 修饰但等号右边不是常量**时，这段赋值**仍会放入 `<clinit>`** 方法中进行初始化 |

## 七、全章回顾：类的生命周期七块内容

| # | 阶段 | 核心动作 |
|---|---|---|
| 1 | **加载** | 按**全限定名**把字节码信息加载到内存，方法区生成 `InstanceKlass`、堆区生成 `Class` 对象；**静态字段存放在堆区（JDK8 以后）** |
| 2 | **连接·验证** | 校验魔数、版本号及其他信息是否合理，**一般不需要程序员关注** |
| 3 | **连接·准备** | 给静态变量分配内存并设置**初始值**（`int` → **`0`**） |
| 4 | **连接·解析** | 常量池中的**符号引用**（编号）→ **直接引用**（内存地址） |
| 5 | **初始化** ⭐ | **执行静态代码块 + 为静态变量赋值**（学习重点） |
| 6 | 使用 | `new`、反射等 |
| 7 | 卸载 | 垃圾回收篇讲解 |

**两个笔试高频要点（原视频点名）：**
1. 静态变量若被 `final` 修饰**且右边是常量**，会在**准备阶段**直接初始化
2. **直接访问父类静态变量不会触发子类初始化**；而**子类初始化前会优先调用父类的初始化方法**

## 八、面试答题逻辑

### 8.1 「初始化阶段做了什么」四步框架

```
1. 定位 + 本质：连接之后，唯一程序员可干涉的阶段，本质是执行 <clinit> 方法
2. 内容：执行静态代码块 + 为静态变量赋代码中的值（区别于准备阶段的零值）
3. 关键规则三连：
   ① <clinit> 中指令顺序 == 源码书写顺序
   ② 四种触发方式 + final 常量例外
   ③ 继承：初始化子类前必先初始化父类；访问父类静态变量不初始化子类
4. 主动补充：三种不生成 <clinit> 的情况 + <clinit> 只执行一次（JVM 加锁保证）
```

### 8.2 40 秒口述版

> 初始化阶段是唯一和程序员相关的阶段，本质就是执行字节码里的 `<clinit>` 方法——`cl` 是 class，`init` 是初始化。它做两件事：执行静态代码块、给静态变量赋代码里写的值。准备阶段只给了零值，真正的值是这里赋的，字节码上对应 `putstatic` 指令：赋哪个字段从常量池取，赋什么值从操作数栈弹。
> 有个重点：**`<clinit>` 里指令的执行顺序和源码书写顺序完全一致**。如果静态代码块写在静态变量声明前面，就先执行静态代码块，最终值由后写的那句决定。
> 触发初始化有四种方式：访问静态变量或静态方法、`Class.forName`、`new` 对象、执行 `main` 方法所在的类。例外是 `static final` 且右边是常量，准备阶段就赋好了，访问它不触发初始化。可以用 `-XX:+TraceClassLoading` 验证。
> 继承场景两条规则：初始化子类前一定先初始化父类；但直接访问父类的静态变量只会初始化父类，不会初始化子类。另外三种情况下编译器根本不生成 `<clinit>`：没有静态代码块也没有静态变量赋值、只声明不赋值、`static final` 常量。

## 九、高频追问预案

### 9.1 `<clinit>` 机制方向

| 追问 | 回答要点 |
|---|---|
| `<clinit>` 名字什么含义？ | `cl` = class，`init` = 初始化，即「类的初始化方法」，由编译器自动生成，**不是程序员能直接调用的方法**。 |
| `<clinit>` 里都有什么？ | **静态变量的显式赋值语句** + **静态代码块**，按**源码书写顺序**合并。 |
| `putstatic` 指令怎么工作？ | 给静态字段赋值：**字段从常量池取**（参数是常量池编号），**值从操作数栈弹出**。 |
| 静态变量赋值和静态代码块谁先执行？ | **看谁写在前面**——顺序即源码顺序，没有「变量总在代码块之前」这回事。 |
| `<clinit>` 和 `<init>` 的区别？ | `<clinit>` 是类初始化，**只执行一次**；`<init>` 是构造方法，**每次 `new` 执行一次**。**实例代码块被编译进 `<init>`**，且位于构造方法原有代码**之前**。 |
| `<clinit>` 一定存在吗？ | **不一定**。三种情况不生成：①无静态代码块且无静态变量赋值；②只声明静态变量不赋值；③`static final` + 右边是常量。 |
| `<clinit>` 线程安全吗？ | **是**。JVM 用类初始化锁保证 `<clinit>` **只被执行一次**且对其他线程可见——这正是**静态内部类式单例**天然线程安全的根本原因。 |
| `<clinit>` 里抛异常会怎样？ | 包装成 **`ExceptionInInitializerError`**；该类被标记为**错误状态**，后续再用会抛 `NoClassDefFoundError`。这是排查「第一次报错后续报错不一样」的关键。 |

### 9.2 触发条件方向

| 追问 | 回答要点 |
|---|---|
| 哪些操作会触发类初始化？ | 四种：访问静态变量/静态方法、`Class.forName`、`new` 对象、执行 `main` 所在类。（规范中还包括子类初始化触发父类、反射调用等） |
| 怎么验证一个类有没有被初始化？ | JVM 参数 **`-XX:+TraceClassLoading`** 打印加载并初始化的类；或在静态代码块中打印一行。 |
| **访问 `static final int i = 0;` 会触发初始化吗？** | **不会**。`final` + 常量在**准备阶段**已赋值，不需要 `<clinit>`，因此不触发初始化。 |
| `final` 修饰但右边**不是**常量呢？ | **会**放入 `<clinit>` 初始化（编译期无法确定值）。 |
| `Class.forName` 一定会初始化吗？ | 单参重载会（内部 `forName0` 的 initialize 默认 `true`）；三参重载可传 **`false`** 做到**只加载不初始化**。 |
| `ClassLoader.loadClass()` 会初始化吗？ | **不会**，只加载。这是它与 `Class.forName` 的核心区别（Spring 懒加载常用）。 |
| **创建数组会初始化元素类型吗？** | **不会**。`new Test2A[10]` 执行完 `Test2A` 仍未初始化（数组类型由 JVM 自动生成，与元素类无关）。 |
| 访问一个类的静态常量算「使用」这个类吗？ | 不算。编译期常量已被**内联到调用方**字节码，运行时甚至不依赖原类。 |

### 9.3 继承 / 顺序方向

| 追问 | 回答要点 |
|---|---|
| 子类初始化会触发父类初始化吗？ | **会，且父类优先**。 |
| 访问父类静态变量会初始化子类吗？ | **不会**，只初始化父类（静态变量属于父类）。 |
| 父子类完整执行顺序？ | **父类 `<clinit>` → 子类 `<clinit>` → 父类 `<init>`（含父类实例代码块）→ 子类 `<init>`（含子类实例代码块）**。 |
| 接口有 `<clinit>` 吗？ | 有（接口中的字段隐式 `public static final`，若值非编译期常量则需 `<clinit>`）。但**接口初始化不要求其父接口先初始化**——与类不同。 |
| 笔试题 `DACBCB` 的关键在哪？ | ①`main` 所在类先初始化 → D；②实例代码块被编译进构造方法且**在构造方法原代码之前** → `CB`；③类初始化只一次，构造方法两次 → `CBCB`。 |
| 2021 题为什么 `new B02()` 是 2、去掉是 1？ | 有 `new` → 初始化子类，父类先执行 `a=1`，子类再执行 `a=2` → 2；无 `new` → 只访问父类静态变量，只初始化父类 → 1。 |

### 9.4 陷阱题方向

| 追问 | 回答要点 |
|---|---|
| 类会被初始化几次？ | 同一类加载器下**只一次**；**不同类加载器**加载的同名类是**不同的类**，各自初始化。 |
| 准备阶段和初始化阶段怎么分工？ | 准备 = **系统给的零值**（`int`→0、`boolean`→false、引用→null）；初始化 = **程序员写的值**。 |
| 只 `new` 数组、只声明变量、只访问常量——哪些会初始化？ | **都不会**。这是三大经典「被动引用」陷阱。 |
| 初始化阶段之后呢？ | 使用（`new`、反射）→ 卸载（垃圾回收篇）。加上加载、验证、准备、解析共**七块**内容构成完整生命周期。 |
