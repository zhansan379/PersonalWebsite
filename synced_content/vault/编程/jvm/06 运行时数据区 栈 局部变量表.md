# 栈 · 局部变量表

> 栈（Java 虚拟机栈）是运行时数据区中「线程不共享」的部分，采用先进后出（LIFO）结构保存每个方法调用对应的**栈帧**。栈帧由**局部变量表**、**操作数栈**、**帧数据**三部分组成。本页重点讲解栈的整体结构与局部变量表（本质是数组，按 slot 槽存取，long/double 占 2 槽）。

- **虚拟机栈是“容器”**：它是线程私有的内存空间，在创建线程时被分配。你可以把它看作是一个**后进先出（LIFO）**的栈结构。
- **栈帧是“元素”**：它是栈中的基本组成单位，每一个栈帧都对应着一个正在被调用的 Java 方法。
## 一、栈的总览：Java 虚拟机栈 vs 本地方法栈

栈在 JVM 规范中明确划分成两部分，但本质上都属于栈：

| 栈 | 保存什么 |
|---|---|
| **Java 虚拟机栈** | 用 **Java** 实现的方法——每次执行方法，把该方法的信息往栈里保存 |
| **本地方法栈** | 加 `native` 关键字、用 **C++** 实现的方法 |

> **HotSpot 的特殊实现**：设计人员发现无论 Java 实现还是 C++ 实现，这些方法本质上都是方法，所以 HotSpot **只使用了一个栈**来保存这两种方法的信息。

## 二、Java 虚拟机栈：栈帧的入栈与出栈

- 采用**栈的数据结构（先进后出 LIFO）**保存每一个方法调用对应的信息；
- 每次执行一个方法 → 把该方法对应的**栈帧**入栈；方法结束 → 弹栈出栈。
![[Pasted image 20260808223352.png]]
**案例**：`main()` → `study()` → `eat()` / `sleep()`（eat 打印"吃饭"，sleep 打印"睡觉"）

| 步骤 | 动作 |
|---|---|
| 1 | `main` 方法入栈 → 在**栈底** |
| 2 | `main` 未退出，执行 `study` → `study` 栈帧入栈（压在 `main` 上面） |
| 3 | `study` 执行 `eat` → `eat` 入栈，打印"吃饭" → 结束弹栈 |
| 4 | `study` 执行 `sleep` → `sleep` 入栈，打印"睡觉" → 结束弹栈 |
| 5 | `study` 结束 → 弹栈 |
| 6 | `main` 结束 → 弹栈，完整执行流程结束 |

## 三、查看栈帧：IDEA Debug 与异常栈

- **IDEA Debug**：在方法 C 打断点 → debug 运行 → debug 窗口出现 **Frames** 标签页，展示当前线程所有的栈帧：`main`（栈底）→ `A` → `B` → `C`（栈顶，正在执行）。选中某个栈帧会跳转到对应代码行；
- **每个线程都有自己的栈和栈帧**（线程不共享）——切换到别的线程，能看到它自己独立的栈帧集合；
- **异常栈轨迹**：在 C 行 `throw new RuntimeException(...)`，控制台打印的栈帧顺序是 `C → B → A → main`，与 Frames 看到的完全一致。原理：Java 程序遇到异常时，把整个线程栈中保存的栈帧**一个个弹出**，取出栈帧里保存的**方法名和代码行数**打印到控制台，方便定位问题；
- 打印顺序与执行顺序相反的原因：栈是**先进后出**结构。

## 四、虚拟机栈的生命周期

- **随线程创建而创建**，生命周期与线程一致；
- 线程销毁 → 这块栈空间自然被回收，所以**虚拟机栈的回收相对比较简单**；
- 每个线程都包含一个自己的虚拟机栈。

## 五、栈帧的组成（3 部分）

| 组成 | 作用 |
|---|---|
| **局部变量表** | 保存运行过程中存放的**所有局部变量** |
| **操作数栈** | 保存字节码指令执行过程中用到的**临时数据** |
| **帧数据** | 内容较多：动态链接、方法出口、异常表等 |

## 六、局部变量表

### 1. 作用

在方法执行过程中存放**所有的局部变量**。

### 2. 字节码文件中的 LocalVariableTable
![[Pasted image 20260808223503.png]]
方法编译成字节码后，字节码文件内部就存放了局部变量表。可用 IDEA + **jclasslib** 插件查看（View → jclasslib → 选中方法 → 展开 Code → LocalVariableTable），包含 4 列：

| 列 | 含义 |
|---|---|
| **Name** | 局部变量的名字 |
| **起始PC** | 从哪一行字节码指令开始可以访问该变量 |
| **长度** | 可访问的范围（起始 PC 起，覆盖多少行字节码指令） |
| **序号** | 该变量在栈帧局部变量表（槽数组）中的**起始槽位置** |

**起始 PC / 长度示例**：`int i = 0; long j = 1;` 编译为 5 行字节码指令：

- `i` 对应偏移量 0、1（`iconst_0` / `istore_0`），`j` 对应偏移量 2、3（`lconst_1` / `lstore_1`）；
- `i` 必须经过 0、1 的初始化赋值后才能访问 → 起始 PC = 2，长度 = 3（覆盖偏移量 2、3、4）；
- `j` 在偏移量 3 赋值成功 → 从偏移量 4 起可访问，长度 = 1。

> JVM 通过起始 PC + 长度控制每个局部变量的生效范围；在范围外的字节码指令访问该变量会被判定为有问题、**拒绝执行**，从而提高安全性。

### 3. 栈帧中的局部变量表：本质是数组（槽 slot）

- 字节码文件中的局部变量表：主要做**安全性校验**（生效范围），并让 JVM 知道该方法栈帧要为局部变量**开辟多大的内存空间**；
- 栈帧中的局部变量表：本质是一个**数组**，每个位置称为 **slot（槽）**。

**槽占用规则**：

| 类型 | 占用槽数 |
|---|---|
| `long`、`double` | **2 个槽** |
| 其他基本类型（`int` 等） | 1 个槽 |
| 对象**引用** | 1 个槽 |

示例：`int i` + `long j` → 共 **3 个槽**（槽 0 保存 `i` 的值，槽 1、2 保存 `j` 的值）。

**序号列的意义**：字节码文件中 LocalVariableTable 的「序号」列 = 该变量在槽数组中的起始位置。上例 `i` 序号 0（0 号槽）、`j` 序号 1（1 号槽起，占 1、2）。若再增加 `int m = 1`，则 `m` 序号为 **3**（0、1、2 已被 `i` 和 `j` 占用）。

### 4. 局部变量表存放的 3 类内容
![[Pasted image 20260808223147.png]]
按顺序：

1. **实例方法的 `this` 引用**（0 号槽）：实例方法可在方法体中使用 `this` 拿到调用方法的实例对象，正是通过局部变量表实现的——0 号槽存放当前实例的引用（对象内存地址），之后通过该地址访问实例数据；
2. **方法的参数**：如 `test3(int k, int m)` 各占 1 个槽，位置在 `this` 与方法体局部变量之间；
3. **方法体中声明的局部变量**。

### 5. 槽的复用优化

为节省空间，局部变量表中的**槽可以复用**（类似内存/磁盘空间清理）：一旦某局部变量不再使用，其槽即可被其他局部变量占用。
![[Pasted image 20260808222929.png]]

**思考题**：实例方法，参数 `k`、`m`，方法体含代码块 `{ int a=1; int b=2; }` 及 `int i=0; long j=1;`，局部变量表占用几个槽？

- 直觉计算：`this`(1) + `k`(1) + `m`(1) + `a`(1) + `b`(1) + `i`(1) + `j`(2) = 9 → **答案并非 9，而是 6**；
- 实际过程：0 号槽 `this`，1、2 号槽 `k`、`m`；`a` 存 3 号槽（`istore_3`），`b` 存 4 号槽（`istore_4`）；代码块结束，`a`、`b` 失效 → **3、4 号槽可复用**；`int c` 用 `istore_3` 占用 3 号槽；最终 `i` 占 3 号槽，`j` 占 4、5 号槽 → 共 **6 个槽**。

> 记住局部变量表能放三类数据：**实例方法 this 引用 → 参数 → 方法体内声明的局部变量**。
