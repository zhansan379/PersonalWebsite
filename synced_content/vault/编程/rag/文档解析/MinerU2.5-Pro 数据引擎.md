# MinerU2.5-Pro 数据引擎

> 围绕**覆盖率（Coverage）、信息量（Informativeness）和标注准确性（Annotation Accuracy）**三个维度协同设计的数据工程系统，将训练数据从不足 10M 扩展到 65.5M 页，同时系统性地提升标注质量。

## 一、总体架构

数据引擎包含四个协同组件，形成从粗到细的质量级数：

```
PDF 池 → DDAS 采样 → CMCV 难度分层 → Judge-and-Refine 校正 → 专家标注
 (全量)    (65.5M)       (Easy/Med/Hard)        (Hard→可用)      (终极质量)
```

四个组件：
1. **DDAS**（多样性和困难感知采样）：扩展覆盖、纠正分布偏移
2. **CMCV**（跨模型一致性验证）：对采样数据进行难度分层
3. **Judge-and-Refine**（判断和改进注释管道）：通过渲染-验证迭代校正提高困难样本标注质量
4. **专家标注**：自动校正能力之外的最终质量保证

参见 [[MinerU2.5-Pro]] 了解完整的模型架构与训练策略。

## 二、DDAS：多样性和困难感知采样

### 2.1 设计动机

训练数据面临典型的长尾分布：高频类别（标准学术论文、单列报告）占主导，长尾场景（复杂嵌套表、密集公式布局、非常规多列布局）严重不足。现有方法的**单模型难度估计**无法区分模型特定弱点和普遍困难样本。

### 2.2 两级采样流程

**阶段1：页面级采样**
- 提取所有页面的 ViT-Base (512-dim) 视觉特征
- K-Means 聚类 → 从每个聚类中心均匀采样形成候选集
- 运行页面级 CMCV 获取难度标签
- 按聚类难度分布调整采样权重：Easy 为主的聚类降权，难度分布多样的聚类升权，无效内容聚类过滤

**阶段2：元素级采样**
- 使用 MinerU2.5 和 PaddleOCR-VL 提取块级元素（文本、公式、表格）
- 每种元素类型独立聚类并运行块级 CMCV
- 此时四个子任务（布局、文本、公式、表格）在多样性和难度维度上都获得完整信息

**最终采样**
- 在联合聚类-难度空间中执行平衡采样
- 多样性维度：大聚类下采样、小聚类上采样（纠正长尾偏移）
- 难度维度：提高 Medium 和 Hard 样本权重

### 2.3 设计要点

- 聚类提供多样性信号，CMCV 提供难度信号
- 在页面级和元素级两个粒度上与 CMCV 耦合
- 在控制总数据量的同时最大化训练信号密度

## 三、CMCV：跨模型一致性验证

### 3.1 核心思想

将难度评估从**单模型自省**扩展到**多模型交叉验证**。核心假设（经验验证）：
- 多个异构模型输出一致 → 结果很可能是正确的（Easy）
- 多个模型输出分歧大 → 样本真正困难（Hard）

### 3.2 实现方法

在 DDAS 生成的候选数据上独立运行 **K 个异构 SOTA 模型**（MinerU2.5、PaddleOCR-VL、Qwen3-VL-30B），计算任务特定的两两一致性指标：

| 任务 | 指标 |
|---|---|
| 文本 | 编辑距离 |
| 表格 | TEDS |
| 公式 | CDM |

### 3.3 三层难度分类

以目标模型 MinerU2.5 相对于外部模型的性能为基准：

| 类别 | 标准 | 占比 | 标注策略 | 训练价值 |
|---|---|---|---|---|
| **Easy** | MinerU2.5 至少与一个外部模型高度一致 | ~60% | 直接使用任意模型输出 | 构建基础能力，边际训练价值有限 |
| **Medium** | 两个外部模型一致，但 MinerU2.5 与两者差异大 | ~25% | 外部共识即为伪标签 | **最高**——精确定位能力差距，且可学习 |
| **Hard** | 三个模型均显著不一致 | ~15% | 需要 Judge-and-Refine 或专家标注 | 对能力突破至关重要，但标注不可靠 |

### 3.4 与 IMIC/UACS 的区别

MinerU2.5 的 IMIC 和 PaddleOCR-VL 的 UACS 使用**单模型多次推理**的输出一致性作为难度代理，只捕获单模型的认知不确定性，无法区分模型特定的盲点和普遍存在的难题。CMCV 弥补了这一缺陷。

## 四、Judge-and-Refine：判断和改进注释管道

### 4.1 核心挑战

困难样本的自动标注质量很差，直接使用会降低模型性能。朴素的自我反思在文档解析中存在**确认偏差**：模型倾向于接受自己的输出为正确。

根本原因：**跨模态映射的不对称性**——模型擅长从文档图像生成结构化序列，但很难从结构化序列推断视觉外观。对于 LaTeX 公式和 HTML 表格，模型无法准确判断输出序列在隐式空间中的渲染效果。

### 4.2 渲染-验证迭代校正

**核心设计**：先将结构化输出渲染为图像，再将原始文档图像和渲染图像作为配对输入。

两个优势：
1. **填补缺失映射**：从结构化文本到视觉布局的映射被显式补全，减少跨模态对齐的认知负荷
2. **渲染的错误放大效应**：将微妙的文本域结构缺陷（缺失对齐符号、未闭合标签等）转化为显著的视觉异常或布局崩溃

### 4.3 管道设计

- **Judge-Refine 模型**：Qwen3-VL-235B（强大的多模态推理能力，独立于 CMCV 模型池）
- 通过原始文档图像和渲染图像的直观对比，驱动多轮错误定位和针对性校正
- 超出自动校正能力的样本路由到专家标注工作流

## 五、专家标注

### 5.1 优先级分配

经过 DDAS→CMCV→Judge-and-Refine 三阶段过滤后的标注预算分配：

1. **最高优先级**：Judge 置信度高但 Refine 校正不确定的样本（Judge 已定位错误，只需局部校正）
2. 当前模型最弱的子任务类别（由 CMCV 分歧模式决定）

### 5.2 工作流

- **预标注**：Gemini 3 Pro（独立于 CMCV 模型池，避免数据泄漏）
- **审查和纠正**：专业人工标注
- **自动化 QA 工具**：确保标注一致性

### 5.3 数据产出

| 层级 | 样本量 | 标注方式 | 用途 |
|---|---|---|---|
| Easy + Medium | ~655K | CMCV 自动标注 | 阶段1 预训练 |
| Hard（专家标注） | 192K | 人工智能预标注 + 专家审查 | 阶段2 微调 + 阶段3 GRPO |

## 六、设计原则总结

1. **闭环设计**：采样（DDAS）→ 分层（CMCV）→ 校正（Judge-and-Refine）→ 兜底（专家标注），每个阶段的信息回馈给上游
2. **质量分层**：不同质量层的数据用于不同训练阶段，而非混合使用
3. **模型异构性利用**：CMCV 和 Judge-and-Refine 都依赖多模型能力的互补性
4. **边际效益最大化**：有限的专家标注预算精准投向高信息量、高不确定性的样本
