# 服务降级

> **服务降级**是在**服务器压力剧增**时，有策略地对一些非核心服务/页面不处理或用简单方式处理，**释放资源保证核心业务**。核心主线：**舍小保大——压力高峰保核心，非核心直接给 fallback。**

## 一、这是什么

回答"服务降级"时，先讲**动机**（资源有限 vs 请求无限），再讲**做法**（策略性舍弃非核心 + 返回 fallback），最后与熔断/限流区分。

## 二、核心内容

### 2.1 为什么要降级

- **服务器资源是有限的，请求是无限的**。
- 并发高峰期：影响整体性能，严重会**宕机**，导致重要服务不可用。
- 为了高峰期保证**核心功能可用性**，对某些服务做降级处理——**舍小保大**。

### 2.2 降级的做法

- 从**整个系统负荷**出发，对负荷较高的场景做**策略性舍弃**：
  - 暂时**舍弃对一些非核心的接口/数据的请求**
  - 直接返回**提前准备好的 fallback（退路）错误处理信息**
- 效果：提供的是一个**有损服务**，但保证整系统**稳定性与可用性**。

### 2.3 一句话理解

> 服务降级 = **高峰期主动给非核心功能"退路"，把资源让给核心业务**，用"有损"换"稳定"。

### 2.4 熔断 / 降级 / 限流 三者对比（高频考点）

| 概念     | 触发视角                 | 本质            |
| :----- | :------------------- | :------------ |
| **熔断** | **下游**故障（不可用/超时）主动停调 | 链路保护，快速失败     |
| **降级** | **自身/系统压力大**，主动舍弃非核心 | 舍小保大，有损换取稳定   |
| **限流** | **控制进入的流量速率**        | 防止被打爆，如令牌桶/漏桶 |

> 注释加点：熔断常触发降级（熔断后返回 fallback 就是一种降级）；降级是策略、熔断是触发信号之一。

## 三、可能追问

1. 「熔断和降级的区别？」→ 熔断针对下游故障、降级针对自身压力取舍；熔断后往往伴随降级（返回 fallback）
2. 「降级和限流的区别？」→ 降级是舍非核心、限流是控速率
3. 「降级的实现方式？」→ Spring Cloud（Hystrix/Resilience4j 的 fallback）、Alibaba Sentinel
4. 「什么时候触发降级？」→ 高峰/负载阈值/下游熔断时
5. 「降级策略怎么定？」→ 识别核心与非核心接口、预置 fallback、热点检测（见 [[微服务核心组件（Spring Cloud 全家桶）]]）
