# 将对象转为二进制字节流具体怎么实现？

> Java 序列化本质是利用**序列化协议**定义"字节流格式"，再通过对象流 `ObjectOutputStream`/`ObjectInputStream` 在对象与字节流之间互转；前提是类实现 `Serializable` 或 `Externalizable`，否则抛异常。
## 一、这是什么

序列化和反序列化的可逆操作，和加密解密、TCP 粘包拆包同源——它们都依赖一套**处理/解析协议**。序列化协议就是**定义序列化后字节流的格式**：写方按该格式生成字节流，读方按同一格式把字节流解析回对象（类似 class 文件也有自己定义的字节码格式）。

Java 提供对象流来完成：

- **`ObjectOutputStream`**：`writeObject()` → 序列化
- **`ObjectInputStream`**：`readObject()` → 反序列化

> 只有实现了 `Serializable` 或 `Externalizable` 接口的类，其对象才能被序列化，否则抛 `NotSerializableException`。

## 二、核心内容

### 1. 序列化：对象 → 字节流

```java
import java.io.FileOutputStream;
import java.io.ObjectOutputStream;
import java.io.Serializable;

public class MyClass implements Serializable { /* class code */ }

MyClass obj = new MyClass();
try (FileOutputStream fileOut = new FileOutputStream("object.ser");
     ObjectOutputStream out = new ObjectOutputStream(fileOut)) {
    out.writeObject(obj);        // 序列化写入
}
```

### 2. 反序列化：字节流 → 对象

```java
import java.io.FileInputStream;
import java.io.ObjectInputStream;

MyClass newObj = null;
try (FileInputStream fileIn = new FileInputStream("object.ser");
     ObjectInputStream in = new ObjectInputStream(fileIn)) {
    newObj = (MyClass) in.readObject();   // 反序列化读取
}
```

### 3. 参与 / 不参与序列化的成员

- **正常参与**：所有非 `static`、非 `transient` 的成员变量（且它们的类型本身也必须 `Serializable`）。
- **不参与（默认序列化）**：
  - `transient` 修饰的字段 —— 跳过
  - `static` 修饰的字段 —— 属于类级别，不属于对象，默认不序列化

## 三、如何应用 / 面试怎么讲

**回答骨架：**
1. **点本质**：序列化靠"协议 + 对象流"——定调"有协议"是关键，不要只说"用 writeObject"
2. **讲三要素**：类要实现 `Serializable`；写用 `ObjectOutputStream.writeObject`；读用 `ObjectInputStream.readObject`
3. **讲边界**：`transient`/`static` 不参与；成员类型也要 `Serializable`
4. **抛引导**：引出 `serialVersionUID`、`Serializable` vs `Externalizable`、破坏单例等深水区

**追问预案：**

| 追问 | 应答案点 |
| :--- | :--- |
| `serialVersionUID` 有什么用/不写会怎样？ | 版本校验：序列化时可写回，反序列化时比对；不写则运行时自动生成，类改动后易抛 `InvalidClassException`，所以建议显式声明 |
| `transient` 和 `static` 为何不序列化？ | `transient` 是字段级"我放弃"标记；`static` 属类级归所有实例共享，不属于单个对象状态 |
| `Serializable` 和 `Externalizable` 区别？ | `Serializable` 靠默认机制自动序列化；`Externalizable` 需自定义 `writeExternal`/`readExternal`，可控但更繁琐 |
| 反序列化会调用构造器吗？ | **不会**。它通过字节流直接重建对象，这也是"反序列化/`clone` 绕过构造器破坏单例"争论的根源（对应 `readResolve` 防护） |
| 为什么成员类的类型也要 `Serializable`？ | 序列化是递归的，整张对象图都要能序列化，任一非序列化成员就会抛异常 |
