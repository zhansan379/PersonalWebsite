# 序列化和反序列化

> **序列化**（Serialization）是把内存中的 Java 对象转换成一系列字节（字节流）的过程；**反序列化**（Deserialization）是反过来把字节流恢复成 Java 对象的过程。二字同源于"序列"（Sequence）——一组按特定顺序排列的事物。

## 一、这是什么

- **"序列"（Sequence）**：一组按特定顺序排列的事物，比如一串数字、一段文字。
- **"序列化"（Serialization）**：把对象变成一个"序列"（即字节流）的动作或过程。
- **"反序列化"（Deserialization）**：把字节流重新恢复成 Java 对象的过程。

三者是**互为逆运算**的关系：对象 → 字节流（序列化），字节流 → 对象（反序列化）。

## 二、核心内容

### 1. 为什么需要序列化

对象只活在内存里（JVM 堆），跨出"当前 JVM 存活期/当前进程"就要变成字节流才能搬运。典型场景：

| 场景 | 说明 |
| :--- | :--- |
| **持久化存储** | 把对象写入文件 / 数据库，下次再读回 |
| **网络传输** | 对象跨进程、跨机器传递（如 RPC、消息队列） |
| **进程间转移** | 从一个 JVM 搬到另一个 JVM（见相关页面） |

### 2. 序列化/反序列化本身是什么机制

不是凭空魔法，而是靠**一套协议定义字节流格式**：写入方按协议生成字节流，读取方按同一协议解析回对象——这也与加密解密、TCP 粘包拆包同源（详见 [[将对象转为二进制字节流具体怎么实现？]]）。

### 3. 从"序列"理解本质

"把对象拆成一行按顺序排列的数据"（序列），再按其顺序还原——理解了"顺序"二字，就理解了序列化的存储与解析原理。

## 三、如何应用 / 面试怎么讲

**回答骨架（讲定义时可以出彩）：**
1. **先拆词**："序列"即按顺序排列的一串数据；序列化/反序列化就是"对象 ↔ 字节流"两个方向。
2. **给业务意义**：持哪持久化与跨进程网络传输需要它。
3. **落到 Java**：靠 `Serializable` + 对象流实现，且隐含着"协议定义格式"的思想。
4. **引深水区**：`transient`/`serialVersionUID`、JSON 库（Gson/Jackson）也是一种序列化。

**常见追问：**

| 追问 | 应答案点 |
| :--- | :--- |
| 序列化到底干了什么？ | 把对象按协议顺序地压成字节流，记录其类型与字段数据 |
| 哪些场景必须序列化？ | 存文件、写 DB、跨进程/跨 JVM/网络传输 |
| 序列化一定用 Java 原生？ | 不，JSON（Gson/Jackson）等也是序列化的一种形式 |
