# 面试整理：为什么需要包装类（Integer）

> 这是个偏"为什么"的**原理题**，考验的不是背 API，而是看你能不能从「**面向对象 + 语言机制**」两个角度讲清楚：基本类型够用了，为什么 Java 还要造出一套包装类？答案的骨架是「**泛型只认引用类型 + 集合只存对象 + 需要 null 语义 + 需要工具方法**」四条。
> 一句话记忆：**基本类型"能算数但不能当对象用"，包装类把它"抬进对象世界"——塞进集合、填进泛型、装下 null、挂上方法。**

## 一、回答逻辑（四步骨架）

```
1. 一句话点本质：包装类 = 把基本类型包装成 Object，让它"对象化"
2. 讲第一个刚需：泛型只允许引用类型
3. 讲集合与转换：集合只存对象；int↔String 需要桥接
4. 抛出工具方法 / null 语义 / 进化，收尾
```

**开场句模板：**
> Integer 是 int 的包装类，把基本数据类型包装成 Object 对象。之所以必须存在，是因为 Java 的**泛型和集合都只能处理引用类型**——要用 `List<int>`、`put` 进 Map，就必须先包成 Integer；同时对象封装还能**把数据和处理它的方法绑在一起**（比如 `parseInt`），还能表达 `null`（数据库缺值的语义）。

## 二、回答要点（核心四大刚需 + 两个补充）

### 2.1 泛型只能使用引用类型（最大得分点）

- Java 泛型**类型参数必须是引用类型**，不能用基本类型。
- `List<int>` 编译不过，必须 `List<Integer>`。
- 例子：想对一个列表排序、求和的场景，用 `List<Integer>` 配合 `Collections.sort()`、`mapToInt(...).sum()`。

> **加分表述**：泛型为什么不让用基本类型？因为泛型在**类型擦除**后统一用 `Object` 承装参数，而 int 不是 Object 的子类（基本类型没有对象模型），所以只能通过包装类承接。

### 2.2 集合只能存储对象

- `ArrayList`、`HashMap` 等**全部集合都是"Object 的容器"**，只能存引用类型。
- 想往 `List`/`Map` 里放 int，必须先装箱成 `Integer`。
- 呼应：这正是 [装箱和拆箱] 存在的意义，二者相辅相成。

### 2.3 null 语义（补充，但常被夸）

- **基本类型永远有值**，不能表示"没有/缺失"；包装类可为 `null`。
- 数据库字段为 NULL、JSON 缺失、参数缺席时，用包装类表达"空"。
- 代价：拆箱遇 null 会 NPE（见装箱拆箱整理）。

### 2.4 工具方法 / 面向对象封装（补充）

- 对象封装把**数据 + 方法**放一起：`Integer` 自带 `parseInt()`、`valueOf()`、`toString()`、各种比较和常量。
- 这是"一切皆对象"思想的体现，与其他类用法统一。

### 2.5 转换桥接（int ↔ String）

- 基本类型和引用类型**不能直接互转**，必须经包装类中转。
- `int`→`String`：`Integer.valueOf(i).toString()` 或 `Integer.toString(i)`。
- 反向 `String`→`int`：`Integer.parseInt("123")`。

| 需求 | 基本类型能胜任吗 | 包装类的角色 |
|---|---|---|
| 数值运算 | ✅ | 无需 |
| 放进集合 / 泛型 | ❌ `List<int>` 不行 | ✅ `List<Integer>` |
| Map 键值 | ❌ `Map<...>` key 只能是对象 | ✅ 当 key |
| 表达 null（DB 缺值 / 缺席参数） | ❌ 永远有值 | ✅ Integer 可 null |
| 携带工具方法 | ❌ 一堆裸函数 | ✅ 数据+方法绑定 |
| int↔String 转换 | ❌ 无对象方法 | ✅ parseInt / valueOf / toString |

## 三、最容易答错的对比 / 陷阱

| 场景 | 正确认识 |
|---|---|
| "包装类比基本类型更好" | ❌ 不是替代关系。基本类型性能好、省内存；包装类多一层对象，有装箱/拆箱开销与 NPE 风险。**工程上能基本类型就不包装**。 |
| "空指针只和引用有关" | 基本类型从不会 NPE；NPE 全来自包装类拆箱。 |
| "有了包装类，int 可以彻底不用" | ❌ 泛型/集合需包装，但运算、局部变量、性能敏感处用基本类型。 |
| `Integer` 的 null 和 `int` 的默认 0 | 语义不同：null=缺席，0=数值。若把 null 当 0 用，易埋隐患。 |

## 四、高频追问预测

### 4.1 机制方向

| 追问 | 回答要点 |
|---|---|
| 为什么要泛型只认引用类型？ | 泛型在编译期做**类型擦除**，运行时统一擦回 `Object`；int 不是 Object，无法擦除承接，所以必须用继承 Object 的包装类。 |
| Integer 和 int 是同一个东西吗？ | 不是，转换依赖本文 + 装箱拆箱机制；Integer 是对象（存引用+堆上对象），int 是基本类型（存值）。 |
| 还有哪些基本类型有对应包装类？ | 8 种：Byte/Short/Integer/Long/Float/Double/Character/Boolean；命名规则除了 int→Integer、char→Character 外都是首字母大写。 |
| 包装类和基本类型哪个占内存？ | 基本类型省：int 4 字节；Integer 至少 16 字节（对象头 12 + 值 4，还有对齐）。包装类有明显空间开销。 |

### 4.2 使用 / 场景方向

| 追问 | 回答要点 |
|---|---|
| 数据库字段映射选 Integer 还是 int？ | 看是否允许 `NULL`：允许用 Integer（能表达 null），`NOT NULL` 用 int。MyBatis 返回 null 到 int 字段会 NPE。 |
| 为什么 map/集合的 key 常用包装类？ | HashMap 的 key.value 都是 Object；用 int 存不了 null key。 |
| 什么时候"不该"用包装类？ | 大量并发运算、热点循环、无 null 需求时——省内存省开销避 NPE。 |
| int 转 String 有哪几种？ | `String.valueOf(i)`、`Integer.toString(i)`、`""+i`（字符串拼接越界场景小心）、`Integer.valueOf(i).toString()`。 |
| String 转 int 有哪些方法、区别？ | `Integer.parseInt("123")` 返回 int；`Integer.valueOf("123")` 返回 Integer；非数字字符串都抛 `NumberFormatException`。 |

### 4.3 与装箱 / 缓存联动

| 追问 | 回答要点 |
|---|---|
| 有了包装类为什么还总谈装箱拆箱？ | 因为"对象化"不是免费的：集合取出时拆箱、放入时装箱，配合 IntegerCache 缓存与 NPE，是包装类的三大伴生话题。 |
| 包装类缓存怎么回事？ | 见「装箱与拆箱」整理：IntegerCache 默认 -128~127 复用对象，`new Integer` 已废弃。 |
| 包装类是否实现了 Comparable？ | 是，Integer/Float/Double 等都实现了 `Comparable`，可排序，也是它们能进集合排序的原因之一。 |

### 4.4 与 JVM / 语言设计

| 追问                       | 回答要点                                                                                              |
| ------------------------ | ------------------------------------------------------------------------------------------------- |
| 为什么不能像有些语言一样直接用 int 做泛型？ | 设计取舍：Java 为保持泛型向后兼容 + 类型擦除的简化实现，选择用包装类 + 自动装箱补齐，而非改造基本类型体系。                                       |
| 现代 Java 对这个有改进吗？         | JDK 的 **值类型 / record / 内联对象**（Valhalla 项目、“primitive objects”）方向在探索把"原始类型语义 + 对象能力"统一，属于演进题可点到即止。 |

## 五、口述版答案（40 秒）

> Integer 是 int 的包装类，把基本类型包装成 Object，让它能被当对象使用。**最大的原因**是 Java 的泛型和集合只能接收引用类型——比如 `List<int>` 编译不过，必须 `List<Integer>`；往 `ArrayList`、`HashMap` 里放数字也必须先包装成对象。其次，对象封装有一堆好处：能表达 `null`，对应数据库缺值、参数缺席这种"没有"的语义；能把数据和处理它的方法绑在一起，比如 `Integer.parseInt()`、`toString()`；还能做 `int↔String` 的桥接，因为基本类型和引用类型不能直接转换。所以包装类是 Java 在保留高性能基本类型的基础上，为"对象世界"（泛型/集合/空值/方法）补的桥。但注意包装类不是免费的：占内存更大、有装箱拆箱开销、还多了 NPE 风险，所以**能基本类型就不包装**，只在需要集合、泛型、null 语义时才用。
