# 面试整理：类型转换与互转问题

> 这是 Java 基础面试的**高频题**，考的核心是看你能不能说清「**什么时候需要转、什么时候安全、什么情况下会出问题**」。注意：这里说的是**基本数据类型之间的转换**，别和面向对象的向上/向下转型混为一谈（那道题在 [[01 继承 封装 多态]]）。
> 一句话记忆：**小转大自动且安全，大转小强转必损——要么溢出、要么丢精度**。

## 一、回答逻辑（四步骨架）

```
1. 一句话定调：类型转换分自动 / 强制两类，问题都出在「强转」
2. 澄清概念：小范围 → 大范围自动转；大范围 → 小范围必须强制转
3. 分类展开：说清楚每种转换的机制与风险
4. 抛出两个「问题」+ 判据：溢出 / 丢精度，用什么判断保全
```

**开场句模板：**
> Java 基本类型的转换分两种：**小范围自动转大范围**，安全；**大范围强制转小范围**，可能出问题。问题主要就两类——**数据溢出**和**精度损失**。

## 二、回答要点

### 2.1 转换的两大类（先立框架）

| 转换类型 | 方向 | 是否需要显式语法 | 安全性 | 例子 |
|---|---|---|---|---|
| **自动转换（隐式）** | 小范围 → 大范围 | ❌ 不需要 | ✅ 安全 | `int`→`long`、`float`→`double` |
| **强制转换（显式）** | 大范围 → 小范围 | ✅ `(目标类型)` | ⚠️ 可能溢出 / 丢精度 | `long`→`int`、`double`→`int` |

> 本质是**按取值范围（字节数）看能否无损容纳**：目标范围能装下就自动转，装不下才需要强转——而强转就埋下丢数据的地雷。

### 2.2 两个核心问题（本题的得分点）

**问题一：数据溢出（Overflow）**

- 场景：大范围数值强转成小范围类型，目标类型**装不下**该值。
- 底层机制：强转是**高位截断**——直接丢弃超出目标类型的高位字节，只保留低位。
- 例：`int 300`（二进制 `00000001 00101100`）强转 `byte`，丢掉高 1 字节得到 `00101100` = 十进制 **44**。

**问题二：精度损失（Precision Loss）**

- 两处可能丢精度：
  - **浮点 → 整数**：小数部分被**截断舍弃**（不是四舍五入）。`double 3.14` → `int` 得 **3**。
  - **float → double 或反过来**：浮点表示法本质是近似值，宽窄转换或运算可能损失精度。
- 注意点：自动转换**也会丢精度**——`int → float` 是自动转换（因为范围按指数算更宽），但 float 只有 24 位有效位，大整数转 float 时低位会丢。

> **加分表述**：并不是只有强转才有精度问题。`int → float` 是**自动**转换，但 float 尾数只有 23 位（约 7 位有效十进制），`int` 最大 20 亿（10 位数字），大整数转 float 时低位精度会丢——所以"自动转换 = 绝对安全"是个误区。

### 2.3 与对象转型严格区分（防混淆）

|      | 基本类型转换（本题）      | 引用类型转型                           |
| ---- | --------------- | -------------------------------- |
| 方向   | 按取值范围（字节/位宽）    | 按类继承层级                           |
| 向上   | 自动转换（基本类型）      | 向上转型（自动、安全）                      |
| 向下   | 强制转换，装不下会溢出/丢精度 | 向下转型，类型不匹配会 `ClassCastException` |
| 判断方式 | 看取值范围能否容纳       | 用 `instanceof` 判断实际类型            |

## 三、最容易踩的坑（加分点）

| 坑 | 表现 | 正确认识 |
|---|---|---|
| 以为"小转大永远安全" | `int→float` 自动转但可能丢低位 | 按**能不能无损容纳**判断，而非只看字节宽度 |
| 以为"强转会四舍五入" | `double 3.14→int` | 直接**截断小数**，得 3，不是 4 |
| 溢出后不知道值从哪来 | `300→byte` 得 44 很莫名 | 高位截断，保留低 8 位算十进制 |
| 二进制补码混淆 | 负数强转后值变化 | 高位置被截断自然改变了符号位含义 |
| 字符串转数字报错 | `Integer.parseInt("abc")` 抛异常 | 字符串转换是独立一类，严格模式，非法输入抛 `NumberFormatException` |

## 四、高频追问预测

### 4.1 转换机制方向

| 追问 | 回答要点 |
|---|---|
| 什么时候会自动转换？ | 目标类型**范围能容纳**源类型时——`byte→short→int→long`、`int→double`、`float→double`。范围按字节+表示力判断，不是简单按字节数。 |
| 什么时候必须强制转换？ | 大范围 → 小范围装不下（`double→int`、`long→int`、`int→byte`），或 `int→float` 这种会**丢精度**但方向是"大"的情形（其实自动）。 |
| 自动转换和强转的本质区别？ | 自动转换：编译器知道无损，直接扩展位宽，**不改数值**；强转：编译器知道可能丢数据（**截断高位 / 截断小数**），故必须显式声明"我愿意承担损失"。 |
| `byte`、`short` 和 `int` 做运算结果是什么类型？ | 运算前 `byte`/`short` 会**自动提升为 `int`**，因此结果至少是 `int`。所以 `byte a=1; byte b=2; byte c = a + b;` 编译错误，必须 `(byte)` 强转。这是常见笔试题。 |
| `char = int` 需要强转吗？ | 需要。`int → char` 是强转（可能越界），`char` 的值**没有符号**、属于独立范围，需显式 `(char)`。反过来 `char → int` 自动。 |

### 4.2 精度 / 溢出专项

| 追问 | 回答要点 |
|---|---|
| 精度损失的具体代价是什么？ | 小数被截断（`3.14→3`）；浮点本身有表示误差；大整数转 float 丢尾数。若需精确十进制请用 `BigDecimal`，浮点计算严格不等于精确计算。 |
| 溢出后有没有办法提前判断 / 避免？ | 转换前先比较范围：强转前检查值是否在目标类型范围内（如 `if(x < Byte.MIN_VALUE || x > Byte.MAX_VALUE)`）；或使用 `Math.toIntExact()` 等溢出即抛异常的方法（`ArithmeticException`）。 |
| 为什么 `byte b = 300` 不对而 `b = 100` 对？ | 100 在 byte 范围（-128~127）内，是编译期可验证的**窄常量**，编译器做了隐式窄化；300 超出范围，编译报错——字面量赋值有编译期检查，运行时强转才静默溢出。 |
| float 有什么精度限制？ | 主精度：float 约 7 位有效十进制，double 约 15 位。比较浮点用**误差区间**（`Math.abs(a-b) < epsilon`）而非 `==`。 |
| double 转 float 会有什么问题？ | 精度损失：double 15 位有效数字强转 float 后只保留约 7 位，尾数被截断。 |

### 4.3 与内存 / 类型系统联动

| 追问 | 回答要点 |
|---|---|
| 类型转换和之前学的运行时数据区有关吗？ | 强转的"截断"本质是在**补码位级别**保留低位字节，与栈/堆上的内存表示一致；`byte`/`short` 运算提升 `int` 也与虚拟机的**字长（32 位操作数栈）**相关。 |
| 自动转换为什么在编译期就完成了？ | 因为是无损扩展，**编译期**就能确定结果，属于编译期常量/类型提升，产出的字节码用不同指令即可，不依赖运行期数据。 |
| 是不是转换方向看"字节数"就行？ | 不行。`int`(4字节)→`float`(4字节) 字节数相同却要处理精度；`int→double` 自动；关键是**表示力**而非单纯字节宽。 |

### 4.4 与反射 / 场景结合

| 追问 | 回答要点 |
|---|---|
| 实际项目中什么时候容易踩到？ | 日期时间戳溢出（1970 秒数存 `int`）、ID 用 `int` 存大数值、从 JSON/DB 读取时拿错类型、金额用浮点导致对账不平（应改用 `BigDecimal`）。 |
| 字符串转基本类型有哪些 API？ | `Integer.parseInt` / `Long.parseLong` / `Double.parseDouble` / `Boolean.parseBoolean`，非法输入抛 `NumberFormatException`；包装类 `Integer.valueOf`。 |

## 五、口述版答案（40 秒）

> Java 基本数据类型的转换分两类：**自动转换**是目标范围大于源类型，编译器直接扩展位宽，**无损安全**；**强制转换**是目标范围小于源类型，用 `(类型)` 显式指定，这时候就**可能出问题**。问题主要有两个：一是**数据溢出**，比如 `int 300` 强转 `byte` 会做**高位截断**，丢掉高字节只保留低 8 位，得到 44；二是**精度损失**，比如 `double 3.14` 强转 `int` 会**直接截断小数**得到 3，而且 `int→float` 虽然是自动转换，但因为 float 只有约 7 位有效数字，大整数也会丢尾数。所以判断转换安不安全，不能只看字节数，要看**目标类型能不能无损容纳**。如果要求精确，金额计算要用 `BigDecimal`，溢出可以用 `Math.toIntExact()` 这类方法在溢出时抛异常而不是静默出错。注意这里是基本类型的转换，**和对象的向上/向下转型是两回事**——对象的向下转型类型不匹配会抛 `ClassCastException`。
