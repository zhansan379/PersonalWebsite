# 面试整理：Integer 与 int 的区别与取舍

> 这是"为什么要有包装类"的**姊妹必问题**，面试官常把它和装箱拆箱、IntegerCache 一起连环追问。考的核心是「**基本类型和引用类型的三层差异**（类型性质 / 自动装箱 / 空值语义），以及**为什么 Java 不彻底去掉 int**（性能）。答到"Integer 多占 4 倍内存 + 拆箱 NPE"基本就过关。
> 一句话记忆：**int 小而快、永不 null；Integer 能装 null、能被放进集合泛型——区别核心是"直接存值 vs 存引用指向对象"，取舍核心是"性能 vs 对象能力"。**

## 一、回答逻辑（四步骨架）

```
1. 一句话定调：两者是同类数据在两种"世界观"里的呈现（基本 vs 引用）
2. 展开三层差异：类型性质 / 自动装箱拆箱 / 空指针语义
3. 转向"为什么还要保留 int"：性能（读写效率 + 内存占用）
4. 给出工程取舍：何时用 int、何时用 Integer
```

**开场句模板：**
> Integer 和 int 最本质的区别是：**int 是基本类型，直接存值；Integer 是引用类型，存的是指向对象的引用**。这带来三层差异——一是内存布局和性能不同，二是能否表达空值（null）不同，三是能否进泛型和集合不同；也正因为基本类型在性能上的绝对优势，Java 才保留了 int，而不是全部用 Integer。

## 二、回答要点

### 2.1 三层核心区别（得分点）

| 维度 | int（基本类型） | Integer（引用类型 / 包装类） |
|---|---|---|
| **类型性质** | 预定义基本类型，**直接存值**在内存块，无需实例化，无额外分配 | 类对象，**引用 + 堆上对象**，需实例化分配内存 |
| **内存布局** | 栈/局部直接存 4 字节数值 | 引用指向堆中对象；对象有对象头开销 |
| **默认为** | `0`（数值） | `null`（空引用） |
| **空指针** | 永不 NPE | 拆箱遇 null 抛 `NullPointerException` |
| **自动转换** | —（基本） | 自动装箱/拆箱 与 int 互转（编译器替换） |
| **泛型 / 集合** | 不能进 `List<int>` | 可进 `List<Integer>`、Map 当 key |
| **工具能力** | 无方法 | 自带 `parseInt`/`toString`/常量 |

### 2.2 为什么保留 int（性能论据，本题翻转重点）

| 性能维度 | 数据 | 说明 |
|---|---|---|
| **读写效率** | int 内存块**直接存数据本身**；Integer 要**引用→对象**两级跳 | 基本类型访问少一次解引用，运算通常更快 |
| **存储效率** | 64 位 JVM + 开启引用压缩下：**int 占 4 字节，Integer 占 16 字节（4 倍）** | 对象头（12B，含引用压缩）+ 值（4B）+ 对齐 |

> **结论一句话**：不管读写还是存储，**基本类型都更高效**。大量计算、热点循环、无 null 需求时用 int；需要 null、集合、泛型、方法时才用 Integer。

### 2.3 工程取舍建议

| 场景 | 用 int | 用 Integer |
|---|---|---|
| 局部变量、循环计数、数组元素 | ✅（性能、省内存） | ❌ |
| 数据库字段可空（NULL） | ❌（会 NPE） | ✅ |
| 集合/泛型（`List`、Map key） | ❌ | ✅ |
| 需要传递"无值"语义 | ❌（默认0） | ✅（null） |
| 高并发数值运算 | ✅（避装箱 NPE/开销） | ❌ 除非必要 |

## 三、最容易答错的对比 / 陷阱

| 场景 | 正确认识 |
|---|---|
| "Integer 更功能强大所以更好" | ❌ 功能强但代价高，非替代关系。 |
| "接口/方法统一返回包装类就行" | 注意 NPE：调用方若赋给 int 且值为 null 会炸。 |
| "Integer 默认就是 0" | ❌ **默认 null**，不是 0；只有 int 默认 0。 |
| "反正会自动装箱，可以混着写" | 隐式装箱拆箱有 NPE 和性能隐患，重要路径应显式一致。 |

## 四、高频追问预测

### 4.1 差异机制方向

| 追问 | 回答要点 |
|---|---|
| 底层内存上二者怎么放？ | int 在栈/内存块直接存 4 字节值；Integer 栈上只放引用地址，对象在堆，含对象头和值字段。 |
| 为什么 Integer 占 16 字节？ | 64 位 + 开启 `-XX:+UseCompressedOops`（默认开）时：对象头 12 字节（Mark Word 8 + Klass 压缩 4）+ int 值 4 = **16 字节**（引用压缩使总宽对齐到 8）。int 仅 4 字节。 |
| 什么是引用压缩？ | `UseCompressedOops`：堆 < 32G（默认阈值）时普通对象引用用 4 字节而非 8 字节，省内存；对象头里 Class 指针也从 8 变 4，所以 Integer 头是 12 字节。 |
| 8 种基本类型包装类内存都一样吗？ | 结构类似（对象头 + 对应值），但 char/byte/short 等值字段更短，整体都远大于同值基本类型；还有 CharacterCache 等缓存影响分配。 |

### 4.2 空值 / NPE 方向

| 追问 | 回答要点 |
|---|---|
| Integer 空值的坑具体在哪触发？ | 自动拆箱处：`int y = x;`、`x + 1`、三目 `flag ? 1 : null`、方法返回值赋给 int；ORM 把 null 字段映射到 int 也 NPE。 |
| 为什么基本类型不 NPE、包装类会？ | int 永远有内存位存值，无"空"概念；Integer 是引用可为 null，拆箱调用 `.intValue()` 对 null 调方法即 NPE。 |
| 怎么避免空指针？ | 用 int 兜底（缺省 0）、工具 `Integer` 判 `!= null`、`OptionalInt`、数据库 `NOT NULL` 约束、解包前判空。 |

### 4.3 与装箱 / 缓存联动

| 追问 | 回答要点 |
|---|---|
| `Integer a=100, b=100; a==b`？ | true：100 命中 IntegerCache(-128~127) 同一对象。 |
| `Integer a=200, b=200; a==b`？ | false：超缓存各 new 一个对象，比引用地址。 |
| 与 int 一起比较呢？ | 混合比较时 Integer 自动拆箱成 int 比数值，只要值相等就 true（如 `Integer 127 == int 127`）。 |
| 包装类相等怎么比较最稳？ | `equals()` 或不混用时 `CompareTo`；切勿依赖隐式缓存。 |

### 4.4 场景 / 设计方向

| 追问 | 回答要点 |
|---|---|
| 为什么不让 int 进集合，却要包装类？ | 见「为什么需要包装类」：集合/Object、泛型擦除到 Object、需要 null，是包装类存在的理由，int 天生不具备。 |
| 有什么新的演进方向？ | JDK 值类型/内联对象（Valhalla、"primitive objects"）、`Integer` 的 `compareInt` 等方法在某些 JDK 提供；现代实践对高性能还有 `int[]` 替代 `List<Integer>`。 |
| 用 List<Integer> 还是 int[] 更好？ | 只读数值容器用 `int[]`（省内存、免装箱）；需要集合能力（增删、流、动态）用 `List<Integer>`。性能敏感用原生数组。 |

## 五、口述版答案（40 秒）

> Integer 和 int 最本质的区别是：**int 是基本类型，直接存值；Integer 是引用类型，存的是指向堆对象的引用**。这带来三层差异：第一，内存和性能不同——读 int 就是读那块内存，而 Integer 要先通过引用找到对象；在 64 位 JVM 开启引用压缩时，**Integer 占 16 字节，int 只占 4 字节，差 4 倍**。第二，空值语义不同——int 默认是 0，永远不会 NPE；Integer 默认是 **null**，一旦拆箱就会抛空指针，比如 `int y = 某个为 null 的 Integer` 就崩。第三，能力不同——Integer 能进 `List<Integer>`、泛型和集合，int 不行。**也正是因为基本类型在读写和存储上更高效**，Java 才保留 int：凡是局部计算、循环计数、大量数值运算都用 int；需要 null、要放集合泛型、要表达"没有值"时才用 Integer。所以不是谁更好，而是按场景选。
