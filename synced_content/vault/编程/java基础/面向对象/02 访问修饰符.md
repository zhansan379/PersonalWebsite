# 访问修饰符

> Java 的访问修饰符（Access Modifiers）共 **4 个**，其中一个是「缺省」状态（没有关键字）。它们控制类、方法、字段、构造器的**可见范围**，是**封装**这一特性的语法落地。
> 记忆主线只有一条：**同类 → 同包 → 跨包子类 → 全局**，四个修饰符就是在这条线上依次放宽一格。

## 一、四个修饰符速览（权限由小到大）

| 修饰符 | 关键字 | 作用范围 | 一句话 |
|---|---|---|---|
| 私有 | `private` | 仅限同一个类内部 | 对外完全隐藏，连同包的类也不行 |
| 缺省 | *（不写）* | 仅限同一个包内 | 又叫**包私有**（package-private） |
| 受保护 | `protected` | 同包 + **跨包的子类** | 为**继承**而生的修饰符 |
| 公共 | `public` | 任何地方 | 对外暴露的 API |

> ⚠️ 没有 `default` 这个访问修饰符关键字——「default」只是对**缺省状态**的称呼。（`default` 关键字确实存在，但那是 `switch` 分支和 Java 8 接口默认方法用的，与访问控制无关，别混为一谈。）

## 二、逐个拆解

### 2.1 `private`（私有）

- **范围**：仅限同一个类内部。
- **特点**：最严格。任何外部类都无法访问，**即使是同包下的其他类**。
- **适用**：封装内部实现细节——只给本类方法调用的字段、工具方法。
- **典型用法**：私有构造器，用来禁止实例化（工具类）或控制实例数量（单例）。

### 2.2 缺省（包私有 / package-private）

- **范围**：仅限同一个包内。
- **特点**：不写任何修饰符就是这种模式。比 `private` 宽松，同包下的其他类可以访问；但**包外部的类无法访问，即使它是子类**。
- **适用**：同一模块内部协作的类与方法，不希望成为对外 API。

### 2.3 `protected`（受保护）

- **范围**：同包的任意类 + **不同包中的子类**。
- **特点**：继承体系中的关键修饰符。它比缺省多出来的那一格权限，**只给"子类"这一种关系**，不给跨包的无关类。
- **适用**：希望被子类重写或扩展的基类方法、供子类复用的字段。

### 2.4 `public`（公共）

- **范围**：任何地方。
- **特点**：最宽松。
- **适用**：对外暴露的 API 接口、入口类（`main` 方法必须是 `public`）、常量定义。

## 三、对比一览表（背这张就够）

| 修饰符 | 同类内 | 同包内 | 跨包子类 | 任何地方 |
| :--- | :---: | :---: | :---: | :---: |
| **`private`** | ✅ | ❌ | ❌ | ❌ |
| **缺省（package-private）** | ✅ | ✅ | ❌ | ❌ |
| **`protected`** | ✅ | ✅ | ✅ | ❌ |
| **`public`** | ✅ | ✅ | ✅ | ✅ |

> 表格是严格的**嵌套包含**关系：每往下一行，只是在上一行基础上多开一格权限，没有交叉。所以只要记住列的顺序「同类 → 同包 → 跨包子类 → 全局」，四行自然推得出来。

## 四、高频坑与易错点

### 4.1 外部类只能用 `public` 或缺省

**顶层类（top-level class）不能用 `private` / `protected` 修饰**——因为这两者的语义都依赖「外层作用域」或「继承关系」，而顶层类没有外层。

但**嵌套类（内部类）可以用全部四种**，因为它有外层类作为作用域：

```java
public class Outer {
    private static class Inner { }      // ✅ 合法：嵌套类可以 private
}
// private class Foo { }                // ❌ 编译错误：顶层类不能 private
```

### 4.2 `protected` 跨包访问必须通过「子类型」引用

这是最容易写错的一条。在**不同包的子类**中访问父类的 `protected` 成员时，**限定表达式的类型必须是该子类或其子类**，不能是父类类型：

```java
// ── 包 a ──
public class Base {
    protected int x;
}

// ── 包 b ──
public class Sub extends Base {
    void f(Base b, Sub s) {
        this.x = 1;   // ✅ 自己
        s.x = 1;      // ✅ Sub 类型
        b.x = 1;      // ❌ 编译错误：Base 类型，跨包不允许
    }
}
```

**原因**：`protected` 授予的是「子类可以访问自己继承来的那一份」，而不是「子类可以访问所有 Base 对象」。否则任何人都能写个子类去撬开别的包里 Base 实例的字段，封装就失效了。

> 注意：如果 `Sub` 和 `Base` 在**同一个包**，`b.x` 是合法的——此时生效的是「同包可见」这一格权限，与 `protected` 的继承规则无关。

### 4.3 重写时访问权限只能放宽，不能收窄

子类重写父类方法时，**访问修饰符不能比父类更严格**：

```java
class Base    { protected void run() { } }
class Sub extends Base {
    @Override public    void run() { }   // ✅ protected → public，放宽
    // @Override private void run() { }  // ❌ 编译错误：不能收窄
}
```

**原因**：多态要求「子类对象能替换父类对象使用」（里氏替换）。若子类收窄了权限，通过父类引用调用就会出现「能编译却不该能调用」的矛盾。

> 另外两条同源规则：`private` 方法**不能被重写**（子类里写同名方法只是新方法）；`static` 方法是**隐藏**而非重写。详见 [[01 继承 封装 多态]]。

### 4.4 `public` 不等于真的「任何地方」（JDK 9+ 模块化）

常见说法是「`public` 意味着整个工程都能访问」，在 **JDK 9 引入模块系统（JPMS）之后这句话不再严格成立**：一个 `public` 类若所在的包没有被 `module-info.java` 用 `exports` 导出，**模块外部依然无法访问**。

```java
module my.module {
    exports com.example.api;      // 只有这个包的 public 类对外可见
    // com.example.internal 下的 public 类，模块外访问不到
}
```

也就是说 JDK 9 之后访问控制变成了**两层**：模块层（`exports`）+ 类层（四个修饰符）。

> 模块化带来的其他连带变化见 [[编程/jvm/04 类加载器]]。

### 4.5 接口成员的默认权限

- 接口中的**字段**隐式为 `public static final`（常量）；
- 接口中的**抽象方法**隐式为 `public abstract`，写不写 `public` 都一样；
- Java 8 起的 `default` / `static` 方法也是 `public`；
- **Java 9 起**接口允许 `private` 方法，用于在多个 `default` 方法之间复用逻辑；
- 接口方法**不能是 `protected`**。

> 相关：[[四大函数式接口]]。

## 五、最佳实践

**原则：优先使用最严格的级别，按需逐步放宽。**

```
private  →  缺省  →  protected  →  public
（默认从这里开始）        （只在确有需要时才往右走）
```

- 字段一律先写 `private`，需要读写再加 getter/setter（而不是直接放宽字段权限）；
- 只有明确设计为「给子类扩展」的成员才用 `protected`——它等于向所有子类做出**长期兼容承诺**；
- `public` 意味着这是对外契约，一旦发布就很难改；
- 权限放宽随时可以做，收窄却会破坏调用方。所以**宁可一开始收紧**。

这正是**封装**原则的直接体现：对外暴露越少，可以自由重构的空间越大。

## 六、面试速答

| 问题 | 答案要点 |
|---|---|
| 访问修饰符有几个？ | **4 个**：`private` < 缺省（包私有）< `protected` < `public`；其中缺省**没有关键字** |
| `protected` 和缺省的区别？ | 缺省只到**同包**；`protected` 在同包基础上多给了**跨包的子类** |
| 顶层类能用 `private` 吗？ | ❌ 不能，顶层类只能 `public` 或缺省；但**嵌套类可以用全部四种** |
| 跨包子类访问父类 `protected` 字段要注意什么？ | 限定表达式类型必须是**子类型**：`this.x` / `sub.x` ✅，`base.x` ❌ |
| 重写方法能改访问权限吗？ | 只能**放宽或相同**，不能收窄（否则违反里氏替换） |
| `public` 就一定全局可见吗？ | ⚠️ JDK 9+ 未必：包若没被 `module-info.java` 的 `exports` 导出，模块外仍不可见 |
| 接口里的方法默认什么权限？ | 隐式 `public abstract`；Java 8 起 `default`/`static` 也是 public；Java 9 起可有 `private` 方法 |
| 该怎么选？ | 一律从 `private` 起步，按需放宽；权限易放难收 |
