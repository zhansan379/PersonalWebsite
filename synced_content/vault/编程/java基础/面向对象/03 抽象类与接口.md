# 抽象类与接口

> 一句话抓住本质：**抽象类回答「这个东西是什么」，接口回答「这个东西能做什么」**。抽象类不能实例化但**有构造方法**、能有状态、只能单继承；接口没有状态、可以多实现，Java 8 起有 `default`/`static` 方法、Java 9 起有 `private` 方法。`abstract` 与 `final` 语义互斥，不能同时修饰。
## 〇、先约定两个说法：「是一种」和「能够」

后文反复用到两个判断关系，先说清楚：

| 说法 | 英文叫法 | 含义 | 例子 | 对应语法 |
|---|---|---|---|---|
| **「是一种」** | is-a | 子类型**是**父类型的一种，属于同类事物，能完全替代父类型使用 | 圆**是一种**图形；`ArrayList` **是一种** `List` | **继承**（抽象类 / 父类） |
| **「能够」** | can-do | 一个类**具备某种能力**，与它「是什么」无关 | 订单**能够**被序列化；任务**能够**被运行 | **实现接口** |
| （对照）**「有一个」** | has-a | 一个类**持有**另一个类作为成员 | 汽车**有一个**发动机 | **组合**（成员字段） |

**判断方法就是把句子念出来**：

- 「圆 **是一种** 图形」—— 念得通 → 用继承，考虑抽象类
- 「订单 **是一种** 可序列化」—— 念不通，只能说「订单 **能够** 被序列化」→ 用接口
- 「汽车 **是一种** 发动机」—— 念不通，是「汽车 **有一个** 发动机」→ 用组合，别用继承

这个「念出来」的测试是 *Effective Java* 判断该不该用继承的标准做法。

> **说明**：`is-a` 是 OOP 的标准术语（与里氏替换原则直接相关）；`can-do` 则源自微软 .NET 的设计规范，在中文面试资料里被广泛借用来形容接口 —— **判断本身是对的，但它不是 Java 官方术语**。面试时用中文说「是一种 / 能够」更稳妥，不必刻意飙英文缩写。

## 一、三个高频问题速答

| 问题 | 一句话答案 |
|---|---|
| 抽象类和普通类的区别？ | **只有两个真区别**：抽象类**不能实例化**、可以声明**抽象方法**（没有方法体）。其他一切（继承规则、成员、构造方法）都一样。 |
| 抽象类和接口的区别？ | 抽象类**有状态、只能单继承，描述「是一种什么」**；接口**无状态、可以多实现，描述「能够做什么」**。 |
| 抽象类能加 `final` 吗？ | **不能**。`abstract` 要求被继承，`final` 禁止被继承，语义互斥，编译报错。 |

## 二、抽象类 vs 普通类

| 维度 | 普通类 | 抽象类 |
|---|---|---|
| **实例化** | 可以直接 `new` | **不能被实例化**，只能被继承 |
| **方法实现** | 方法必须有具体实现 | 方法**可以有实现，也可以没有实现**（抽象方法） |
| **继承规则** | 只能被单继承（`extends`），可实现多个接口（`implements`） | **完全一样** —— 这一点两者没有区别 |
| **定位** | 可被其他类继承和使用 | 一般作为**基类**，被其他类继承和扩展 |

### 2.1 三条容易答错的细节

1. **抽象类可以完全没有抽象方法** —— 此时它依然不能被实例化。这是一种「刻意禁止实例化的基类」写法。
2. **一个类只要有抽象方法，就必须声明为 `abstract`**（反过来不成立）。
3. **抽象类有构造方法**。虽然不能 `new`，但子类实例化时会通过 `super()` 调用它来初始化父类字段 —— 这是高频追问点。

```java
public abstract class Shape {
    protected final String name;

    public Shape(String name) {     // ← 抽象类有构造方法
        this.name = name;
    }

    public abstract double area();   // 抽象方法：无方法体，以分号结尾

    public String describe() {       // 具体方法：抽象类可以有实现
        return name + " 面积=" + area();
    }
}
```

### 2.2 为什么 `new Shape(){...}` 能编译

```java
Shape s = new Shape("圆") {          // 这不是在实例化抽象类！
    public double area() { return 3.14; }
};
```

这是**匿名内部类** —— 编译器悄悄生成了一个 `Shape` 的子类并实例化它。所以「抽象类不能被实例化」这句话依然成立。**面试官很爱用这段代码反问。**

## 三、抽象类 vs 接口

### 3.1 两者的定位

| | 抽象类 | 接口 |
|---|---|---|
| 用途 | 描述类的**共同特性和行为**，可以有成员变量、构造方法和具体方法 | 定义**行为规范** |
| 适用场景 | 有明显**继承关系**的场景 | 定义类的**能力或功能** |

### 3.2 核心区别对比表

| 维度         | 抽象类                                                                                       | 接口                                                                                               |
| ---------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **关键字**    | `extends`（继承）                                                                             | `implements`（实现）                                                                                 |
| **数量限制**   | 一个类**只能继承一个**抽象类                                                                          | 一个类**可以实现多个**接口 → **间接实现多重继承**                                                                   |
| **方法实现**   | 可以有定义与实现，方法可在抽象类中实现                                                                       | 原本只有定义；**Java 8 起可定义 `default` 方法体和 `static` 方法**，Java 9 起可定义 `private` 方法（用于辅助 `default` 方法的实现） |
| **成员变量**   | 可包含**实例变量和静态变量**，默认**缺省（包私有）**权限，可在子类中重新定义或赋值                                             | **只能包含常量**：默认 `public static final`，**必须赋初值且不能修改**                                               |
| **抽象方法权限** | `abstract` 修饰，**不能被 `private`、`static`、`synchronized`、`native`、`final` 修饰**，必须以分号结尾、不带花括号 | 隐式 `public abstract`                                                                             |
| **构造方法**   | **有**                                                                                     | **没有**                                                                                           |
| **有没有状态**  | **有**（可持有实例字段）                                                                            | **没有**（只有常量）                                                                                     |
### 3.3 为什么 Java 单继承多实现？
1. 如果类允许多继承，当多个父类存在同名的具体方法，子类就不知道该执行哪一个父类的逻辑，产生歧义。所以 Java 限制类只能继承一个父类，规避这个问题。
2. 而接口中大多是抽象方法，只有方法声明，没有具体实现。就算多个接口方法重名，冲突由实现类自己重写方法解决，不会产生二义。Java8 引入 default 默认方法之后，如果多个接口 default 方法冲突，编译器会强制子类重写该方法，由开发者显式处理冲突，所以依然支持多实现。
3. 单继承限制直接父类只有一个，但可以链式继承，实现多层继承。

### 3.4 Java 8 为什么要给接口加 `default` 方法

解决**接口版本迭代、向后兼容**的痛点。

**为了接口演化（interface evolution）**：在不破坏所有已有实现类的前提下给接口新增方法。典型例子是 `Collection.stream()` 和 `Iterable.forEach()` —— 如果它们是抽象方法，全世界实现了 `Collection` 的类都会编译失败。


## 四、抽象类能加 final 修饰吗

**不能。**

- Java 中的抽象类是**用来被继承**的
- `final` 修饰符用于**禁止类被继承**或方法被重写
- 因此 `abstract` 和 `final` 是**互斥**的，不能同时使用（编译错误：`illegal combination of modifiers: abstract and final`）

### 4.1 顺手记住这一组互斥关系

| 组合 | 合法？ | 原因 |
|---|---|---|
| `abstract` + `final`（类） | ❌ | 要求被继承 vs 禁止被继承 |
| `abstract` + `final`（方法） | ❌ | 要求被重写 vs 禁止被重写 |
| `abstract` + `private` | ❌ | 子类看不见，无法重写 |
| `abstract` + `static` | ❌ | 静态方法属于类、不参与多态派发 |
| `abstract` + `native` | ❌ | `native` 已表示实现在本地库中，与「无实现」矛盾 |
| `abstract` + `synchronized` | ❌ | 同步是**实现细节**，无方法体无从加锁 |
| `abstract` 类 + `final` 方法 | ✅ | 抽象类里完全可以有不允许重写的具体方法（模板方法模式的骨架方法就这么写） |

> 权限修饰符的完整规则见[[02 访问修饰符]]。

## 五、工程选型：什么时候用抽象类，什么时候用接口

| 判断依据                   | 选抽象类                 | 选接口                                |
| ---------------------- | -------------------- | ---------------------------------- |
| 语义关系                   | **「是一种」**：圆**是一种**图形 | **「能够」**：这个类**能够**被比较 / 被序列化 / 被运行 |
| 是否需要共享**状态**           | 需要（字段、初始化逻辑）         | 不需要                                |
| 是否需要提供**骨架实现**         | 需要（模板方法）             | 不需要，或只需少量 `default`                |
| 是否需要一个类具备**多种能力**      | 做不到（单继承）             | ✅ 多实现                              |
| 是否要作为 **Lambda** 的目标类型 | ❌ 不行                 | ✅ 函数式接口                            |

**JDK 里的经典案例**：

| 类型 | 例子 | 说明 |
|---|---|---|
| 接口=能力 | `Comparable`、`Runnable`、`Serializable` | `Serializable` 是**标记接口**，一个方法都没有 |
| 抽象类=骨架 | `AbstractList`、`AbstractMap`、`InputStream` | 实现共性逻辑，只留几个抽象方法给子类 |
| **两者配合** | `List`（接口）+ `AbstractList`（骨架）+ `ArrayList`（实现） | **标准范式**：接口定契约，抽象类给默认骨架，具体类按需继承 |

**「接口 + 抽象骨架类」是工程中最推荐的组合**，Spring 里到处都是这种结构（`ApplicationContext` 接口 → `AbstractApplicationContext` 骨架 → 各种具体上下文）。

## 六、面试答题逻辑与追问预案

### 6.1 答题框架（四步）

```
① 一句话定性差异        「抽象类描述『是一种什么』并共享实现，接口描述『能够做什么』只定契约」
        ↓
② 摆语法差异（有限几条）  数量限制 / 状态 / 构造方法 / 成员默认权限
        ↓
③ 讲设计意图            为什么 Java 单继承多实现？default 方法为何而生？
        ↓
④ 落到选型与例子         接口定契约 + 抽象类给骨架 + 具体类实现（JDK/Spring 实例）
```

**关键**：语法差异谁都能背，**第③④步才是区分度**。只要能把「`default` 方法是为了接口演化」和「接口 + 抽象骨架类」讲清楚，这道题就答到位了。

### 6.2 三种时长的版本

**30 秒速答版**

> 抽象类和接口最本质的区别是**语义定位**：抽象类表达**「是一种什么」的同类关系**，用来共享状态和骨架实现，所以它有构造方法、有实例字段，但只能被单继承；接口表达**「能够做什么」的能力**，只定义行为契约，没有状态，所以可以被多实现，用来给一个类叠加多种能力。语法上主要差三点：**数量限制**（单继承 vs 多实现）、**有无状态**（实例变量 vs `public static final` 常量）、**有无构造方法**。Java 8 之后接口有了 `default` 和 `static` 方法，Java 9 有了 `private` 方法，但这是为了**解决接口演化问题**，不是为了让接口取代抽象类。

**2 分钟版**：上面 + 抽象类 vs 普通类的两个真区别（不能实例化、可有抽象方法）+ `abstract` 与 `final` 互斥 + `default` 方法冲突的三条解决规则。

**5 分钟版**：再加上选型判断表、`List`/`AbstractList`/`ArrayList` 这套标准范式、Spring 的 `ApplicationContext` → `AbstractApplicationContext` 结构，以及函数式接口只能是接口（Lambda 目标类型）。

### 6.3 得分点清单（说到就加分）

| #   | 得分点                                                                 |
| --- | ------------------------------------------------------------------- |
| 1   | 先用**「是一种」/「能够」**定性（继承关系 vs 能力契约），不是一上来就背语法表                         |
| 2   | 抽象类和普通类**只有两个真区别**（不能实例化、可有抽象方法），继承规则完全相同                           |
| 3   | **抽象类有构造方法**，供子类 `super()` 调用                                       |
| 4   | 抽象类**可以没有抽象方法**，但仍不能实例化                                             |
| 5   | 接口成员变量隐式 `public static final`，**必须赋初值**                            |
| 6   | 接口方法隐式 `public abstract`；Java 8 `default`/`static`、Java 9 `private` |
| 7   | 多实现是**类型与行为**的多继承，**不是状态**的多继承 —— 解释了 Java 为何单继承                    |
| 8   | **`default` 方法的目的是接口演化**（`Collection.stream()` 不破坏已有实现）             |
| 9   | `default` 冲突三规则：**类优先 → 子接口优先 → 否则显式 `X.super.m()`**                |
| 10  | **`abstract` 与 `final` 互斥**，并能顺带说出 `private`/`static`/`native` 也互斥  |
| 11  | 选型能落到**「接口定契约 + 抽象骨架类 + 具体实现」**这套范式，并举 JDK/Spring 例子                |
| 12  | 知道 **Lambda 的目标类型只能是函数式接口**，抽象类不行                                   |

### 6.4 加分点（超出预期）

| #   | 加分点                                                                       |
| --- | ------------------------------------------------------------------------- |
| 1   | **匿名内部类**：`new Shape(){...}` 不是实例化抽象类，是编译器生成了匿名子类                         |
| 2   | **接口的 `static`/`private` 方法不被继承**，只能通过接口名调用                               |
| 3   | **接口常量的编译期内联坑**：改常量值只重编接口，调用方拿到的还是旧值                                      |
| 4   | **标记接口** `Serializable`：一个方法都没有，纯粹用类型传递元信息                                |
| 5   | 抽象类里可以有 `final` 方法 —— **模板方法模式**的骨架方法就该这么写（`final` 定流程，`abstract` 留钩子）    |
| 6   | 不拿「接口调用比抽象类慢」当卖点 —— `invokeinterface` 与 `invokevirtual` 的差距在现代 JIT 下基本不存在 |
| 7   | 密封类（`sealed`，Java 17）作为「受控继承」的新选项，与抽象类配合限制子类范围                            |

### 6.5 追问预案

#### A 组：抽象类的边界（最常问）

| 追问 | 答法要点 |
|---|---|
| 抽象类**能有构造方法**吗？为什么？ | **能**。构造方法不等于实例化 —— 它的作用是初始化父类字段，子类 `new` 时通过 `super()` 链式调用 |
| 抽象类能有 `main` 方法吗？能直接运行吗？ | **能**，`main` 是静态方法，不需要实例，可以正常运行 |
| 抽象类能**没有**抽象方法吗？ | 能，且依然不能被实例化 |
| 那为什么 `new Shape(){...}` 能编译过？ | 匿名内部类 = 编译器生成的匿名子类，实例化的是子类不是抽象类 |
| `abstract` 能和 `final`/`static`/`private` 同用吗？ | 都不行，逐条讲语义矛盾（见第四章的表） |
| 抽象方法能是 `protected` 吗？ | **能**。只是不能 `private`（子类不可见就没法重写） |
| 抽象类能实现接口但不实现其方法吗？ | **能**，未实现的方法继续保持抽象，留给具体子类 |

#### B 组：接口深水区

| 追问 | 答法要点 |
|---|---|
| Java 8 为什么给接口加 `default` 方法？ | **接口演化**：给已有接口加方法而不破坏所有实现类，例证 `Collection.stream()`、`Iterable.forEach()` |
| 两个接口有同名 `default` 方法怎么办？ | 三条规则：类优先 → 子接口优先 → 都不适用则编译报错，实现类必须显式覆写并用 `A.super.hi()` 指定 |
| 有了 `default`，接口是不是能取代抽象类了？ | **不能**。接口**没有状态、没有构造方法**，无法共享字段与初始化逻辑；语义上仍是**「能够做什么」**而非**「是一种什么」** |
| 接口的 `static` 方法能被实现类继承调用吗？ | **不能**，只能 `接口名.方法()` |
| 接口里能写 `private` 方法吗？ | Java 9+ 可以，用于抽取多个 `default` 方法的公共逻辑，且不被继承 |
| 接口里的变量能改吗？ | 不能，隐式 `public static final`，且必须在声明时赋初值 |
| 为什么 Java 类是单继承但接口可以多实现？ | **状态冲突无法调和**（多个父类同名字段），而类型/方法冲突有明确规则可循 |

#### C 组：选型与设计

| 追问 | 答法要点 |
|---|---|
| 实际项目中你什么时候用抽象类，什么时候用接口？ | 用第五章的判断表回答：**需要共享状态或骨架实现→抽象类；需要叠加多种能力或作为对外契约→接口**；并举自己项目中的一个例子 |
| 能同时用吗？ | **这才是标准做法**：`List` 接口 + `AbstractList` 骨架 + `ArrayList` 实现；Spring 的 `ApplicationContext` → `AbstractApplicationContext` |
| 模板方法模式怎么用抽象类实现？ | 父类用 `final` 方法定义**不可变流程**，中间步骤声明为 `abstract` 或 `protected` 钩子留给子类；例：`InputStream`、`AbstractApplicationContext.refresh()` |
| 抽象类会不会造成继承层次过深？怎么办？ | 会。**优先组合而非继承**；层次控制在 2~3 层；用接口 + 委托替代深继承 |
| 只有一个实现类，还要不要抽接口？ | 看是否**跨模块契约**或有**测试替身/多实现预期**；否则不必为了「面向接口」而抽象，避免过度设计 |

#### D 组：关联扩展

| 追问 | 答法要点 |
|---|---|
| 为什么 Lambda 只能赋给接口，不能赋给抽象类？ | Lambda 的目标类型必须是**函数式接口**（`@FunctionalInterface`，只有一个抽象方法）；抽象类可能有状态和构造方法，无法用 `invokedynamic` 动态生成实例 |
| 抽象类和接口都能实现多态吗？ | 都能 —— 父类型引用指向子类型对象。区别只在类型来源。见[[01 继承 封装 多态]] |
| 接口的多实现和多态是什么关系？ | 一个对象可以有**多个父类型**，因此能在不同上下文中扮演不同角色（既是 `Runnable` 又是 `Comparable`） |
| 抽象方法和重写、`@Override` 的关系？ | 实现抽象方法本质就是**重写**，遵守「访问权限只能放宽、不能收窄」等规则 → [[02 访问修饰符]] |
| Java 17 的 `sealed` 类了解吗？ | 密封类限定**允许哪些子类**继承，把「开放继承」变成「受控继承」，常与抽象类配合表达封闭的类型层次 |

### 6.6 可以反问面试官的问题

1. 「团队里对『接口 + 抽象骨架类』这套结构有统一约定吗？还是倾向于直接用接口 + `default`？」
2. 「项目的 JDK 版本是多少？能用上 `sealed`、`record` 这些新的类型建模手段吗？」
3. 「有没有因为继承层次过深而重构成组合的经历？」

## 七、小结

1. **抽象类 vs 普通类只有两个真区别**：不能实例化、可以有抽象方法；继承规则完全相同
2. 抽象类**有构造方法**、可以有 `main`、可以没有抽象方法，但始终不能被 `new`
3. `new 抽象类(){...}` 是**匿名内部类**，实例化的是编译器生成的子类
4. **抽象类 =「是一种」+ 状态 + 骨架**；**接口 =「能够」+ 无状态 + 契约**（判断方法：把句子念出来看通不通）
5. 接口成员变量隐式 `public static final` 且必须赋初值；方法隐式 `public abstract`
6. Java 8 起接口有 `default`/`static`，Java 9 起有 `private`；`default` 的目的是**接口演化**
7. `default` 冲突：**类优先 → 子接口优先 → 显式 `X.super.m()`**
8. 多实现是**类型与行为**的多继承，不是**状态**的多继承 —— 这就是 Java 单继承的理由
9. **`abstract` 与 `final` 互斥**（`private`/`static`/`native` 同理）；但抽象类里可以有 `final` 方法
10. 工程首选范式：**接口定契约 + 抽象骨架类给默认实现 + 具体类落地**
11. **Lambda 只能以函数式接口为目标类型**，抽象类不行
