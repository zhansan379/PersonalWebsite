# 面试整理：接口成员与抽象类实例化（三连问）

> 这是抽象类与接口的**"细节点"必问题**，常被面试官当成"看你基础牢不牢"的刁钻题。三问同源，记住同一条根：**接口是"纯契约"，天生不能被 new → 所以不能有构造方法、成员全是隐式 public；抽象类"半成品"，不能被 new → 但可以有构造器（由子类调用）**。
> 一句话记忆：**接口能定义方法（抽象/default/static/private 四类）但不能构造对象；抽象类能定义构造器但不能被直接实例化；两者都"不能 new"，区别在"有没有实现骨架"。**

## 一、回答逻辑（三问并答的骨架）

```
1. 先亮共同点：接口和抽象类都「不能被 new」
2. 接口：能定义哪些方法 → 列出四类 + 各自的 JDK 版本
3. 抽象类：能不能实例化 → 不能，但构造器怎么被调用
4. 接口：为什么不许构造方法 → 因为不能 new;底层由 JVM 校验
```

**开场句模板：**
> 这三个问题都围绕"接口和抽象类能不能、该不该实例化"展开。**接口是纯契约，不能 new，所以不能有构造方法，但能定义抽象方法、default、static、private 四类方法；抽象类有实现骨架，也不能直接 new，但可以有构造器——由子类实例化时 implicit 调用。**

## 二、回答要点

### 2.1 接口可以定义哪些方法？（四类，必背版本）

| 方法类型 | JDK | 特点 | 例子 |
|---|---|---|---|
| **抽象方法** | 一直 | 无方法体，实现类**必须**实现；**隐式 `public abstract`** | `void makeSound();` |
| **默认方法（default）** | **Java 8** | 有实现，实现类可覆盖；为接口**兼容演进**而生 | `default void sleep(){...}` |
| **静态方法** | **Java 8** | 属于接口本身，**接口名直接调用**，实现类对象不能调 | `static void staticMethod(){...}` |
| **私有方法** | **Java 9** | 仅供接口内部辅助（default/static 复用），实现类不可见 | `private void logSleep(){...}` |

> **加分表述**：接口**字段默认是 `public static final`**（常量），接口方法默认 `public abstract`（Java 8/9 的 default/static/private 其实也隐式 public）。即接口成员天生是公开的。

### 2.2 抽象类可以被实例化吗？（不能，但构造器会被调用）

- **不能**用 `new` 直接创建抽象类对象（有 abstract 方法无体，不完整）。
- 抽象类 **可以有构造器**，但它在**子类实例化时被调用**（`super()`），完成必要初始化——这是"间接使用"，不是"实例化抽象类本身"。
- 例：`ConcreteClass extends AbstractClass`，`new ConcreteClass()` 时父抽象类构造器先跑。

> **关键纠正**：说"抽象类有构造方法所以被实例化了"是错的。被 new 的是**子类对象**，抽象类构造器只是被子类 `super()` 链式调用，抽象类本身始终没有实例。

### 2.3 接口可以包含构造方法吗？（不能）

- **不能**。写构造方法编译器报 `Interfaces cannot have constructors`。
- 原因链：构造方法是"new 的一瞬间初始化对象属性"用的 → 接口**不能 new → 没有实例可初始化 → 构造方法无意义**。
- 结论：接口里**连实例字段都不能有**（只有隐式 `static final` 常量），本就没有"对象初始化"这回事。

## 三、最容易答错的对比 / 陷阱

| 场景 | 正确认识 |
|---|---|
| "接口有 default 方法就是半实现" | 半实现（可复用）没错，但仍**不能 new**，接口重点还是契约。 |
| "抽象类能 new" | ❌ 不能；能 new 的是实现了全部抽象方法的子类。 |
| "抽象类必须至少一个抽象方法" | 可一个都没有，但它仍是抽象类、仍不能 new（用 `abstract` 声明即不可实例化）。 |
| "接口可以声明普通字段" | ❌ 接口字段必须是 `public static final` 常量，不能有普通实例变量。 |
| "抽象类构造器 = 能实例化抽象类" | ❌ 见 2.2 关键纠正。 |

## 四、高频追问预测

### 4.1 方法 / 成员定义方向

| 追问 | 回答要点 |
|---|---|
| default 方法为什么引入？ | 为接口**向后兼容**：JDK8 给 Collection 加 `stream()`、`default` 方法以免破坏所有实现类；它让接口可以不破坏子类的前提下加新行为。 |
| 接口里可以有变量吗？ | 只能有**常量**：字段隐式 `public static final`，调用/引用不能修改。普通实例字段不行。 |
| 接口方法默认是什么访问级别？ | 全部**隐式 `public`**（abstract/default/static 都是），不能设 private（除 Java 9 private 辅助方法）与 protected。 |
| 一个类实现多个接口有同名 default 方法？ | 冲突**必须重写解决**，否则编译错误（冲突三规则）；接口引用调用时按"最具体实现"解析。 |
| `abstract` 方法能是 `static`/`final`/`private` 吗？ | 都不能，语义矛盾（abstract 要被子类实现，static 属类、final 不可重写）。 |

### 4.2 实例化方向

| 追问 | 回答要点 |
|---|---|
| 接口能不能 new？ | **不能**，接口无构造方法、不能被实例化。也没有父类可 new。 |
| 匿名内部类算不算实例化接口/抽象类？ | **不算**真实的实例化。`new Runnable(){...}` 创建的是**接口的匿名实现类的对象**，不是接口对象；抽象类同理。 |
| 抽象类构造器有什么用？ | 提取子类公共初始化逻辑：父类构造器里初始化公共字段、保证不变量，子类 `super()` 触发。 |
| 为什么接口不需要也不需要构造方法？ | 接口没有实例状态（无实例字段可 init），构造方法失去意义；设计上就是纯契约。 |
| 抽象类和接口谁更接近实例化？ | 都不可实例化；但抽象类**有构造器+实例字段+具体方法**，更接近"半成品类"；接口是纯抽象。 |

### 4.3 选择 / 联动（若往深里问）

| 追问 | 回答要点 |
|---|---|
| 什么时候用抽象类 vs 接口？ | 见「03 抽象类与接口」完整版：抽象类=「是一种」+可复用状态与骨架；接口=「能够」+纯契约。多继承多个能力用接口。 |
| 接口有了 default 方法，抽象类会不会被淘汰？ | 不会。抽象类仍独占**实例字段、构造器、非 final 状态、方法覆盖共享**；default 只是最小化兼容手段。 |
| JDK 里常见 default 方法例子？ | `Collection.stream()`、`Map.getOrDefault()`、`Comparator.thenComparing()`。 |
| 与装箱/构造相关的坑？ | 接口不能 new → 无法直接调构造器；抽象类构造器可能被子类误用；与前面"包装类为什么存在"的"对象化"是两回事，别混。 |

## 五、口述版答案（40 秒）

> 这三个其实是同一件事。先说**接口能定义哪些方法**：抽象方法（必须实现）、Java 8 的 default（有实现可覆盖，为了向后兼容加新行为不破坏子类）和 static（接口名直接调用）、Java 9 的 private（接口内部辅助）。接口**字段是隐式 `public static final` 常量**，方法都是隐式 public。再说**抽象类能不能实例化**：不能 `new`，但它可以有构造器——子类实例化时经 `super()` 调用，那是在初始化会被创建的子类对象，抽象类本身仍然没有实例。最后**接口为什么不能有构造方法**：构造方法是 new 时初始化对象用的，而接口不能 new、没有实例状态可初始化，所以构造方法对接口毫无意义，写了会直接编译报错。一句话：接口是纯契约不能 new，抽象类是半成品不能直接 new，但都有各自的边界。
