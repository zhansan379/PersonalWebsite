# synchronized 锁静态方法和普通方法区别？

> 一句话定调：区别在**锁的对象**不同——**普通方法锁的是当前对象实例 `this`**，**静态方法锁的是当前类的 `Class` 对象**。由于 `this` 每个实例各有一个（不同实例互不影响），而 `Class` 对象每个类**全局唯一**，所以互斥的**作用范围**随之不同：普通方法只对同一实例互斥、不同实例可并行；静态方法对整个类的所有实例互斥、同一时间仅一个线程能执行。

> **这道题对应的「答题主线」**，面试官问「synchronized 修饰静态方法和普通方法有什么区别？」，可以按这条主线串起来：
> 一句话定调（锁对象不同：`this` vs `Class`）→ 展开两个角度：**静态 / 实例归属**（静态方法属于类、无实例依赖，故用 Class 作锁；普通方法绑定实例，故用 this 作锁）→ 推出**作用范围差异**（实例锁只约束同一实例、类锁约束所有实例）→ 落到**多实例场景**（不同实例的普通同步方法可并行，静态同步方法全局串行）→ 收尾用对比表 + 一两条易错点。

## 一、锁的对象不同（根本差异）

| 方法类型 | 锁的对象 | 说明 |
| :--- | :--- | :--- |
| **普通方法** | **当前对象实例 `this`** | 同一对象实例的 synchronized 普通方法，同一时间只能被一个线程访问；**不同对象实例间互不影响**，可被不同线程各自访问同步普通方法 |
| **静态方法** | **当前类的 `Class` 对象** | 类的 `Class` 对象**全局唯一**；无论多少个对象实例，该静态同步方法同一时间只能被一个线程访问 |

## 二、作用范围不同

- **普通方法**：仅对**同一对象实例**的同步方法调用互斥，**不同对象实例**的同步普通方法可并行执行。
- **静态方法**：对**整个类所有实例**的该静态方法调用都互斥——一个线程进入静态同步方法后，其他线程无法进入同一类任何实例的该方法。

## 三、多实例场景影响不同

- **普通方法**：多线程访问**不同对象实例**的同步普通方法时，可同时执行。
- **静态方法**：不管有多少对象实例，**同一时间仅一个线程**能执行该静态同步方法。

| 场景 | 普通方法（锁 this） | 静态方法（锁 Class） |
| :--- | :--- | :--- |
| 同一实例的两个同步方法 | 互斥，只能一个线程进 | — |
| 不同实例的各同步普通方法 | **可并行** | — |
| 同一类的静态同步方法（任意实例） | — | 全局互斥，同时仅一个线程 |

> **本质**：互斥范围取决于**锁对象是不是全局唯一**。`this` 每实例一份 → 不同实例互不影响；`Class` 每类一份 → 全类共享一把锁。

## 四、面试速答与追问预案

### 4.1 三十秒速答版

区别在锁对象：普通方法锁 `this`（当前实例），只约束同一实例的同步方法、不同实例可并行；静态方法锁类的 `Class` 对象（全局唯一），约束整个类所有实例、同时仅一个线程能执行。本质是"锁对象的粒度决定互斥范围"。

### 4.2 追问预案

**Q1：一个实例的静态同步方法和其他实例的普通同步方法能并行吗？**
**A**：能。两者锁的对象不同（一个是 `Class` 对象、一个是 `this`），互不影响，可以并行执行。

**Q2：为什么静态方法锁的是 Class 对象而不是实例？**
**A**：静态方法属于类、不依赖任何实例而存在。因此用类的 `Class` 对象作为锁，它是每类全局唯一的一个对象，正好能表达"该类所有实例在这一点上共享一把锁"的语义。

**Q3：this 和 Class 对象本质区别？**
**A**：`this` 是当前对象实例的引用，多实例各有各的 this；`Class` 对象是每个类在 JVM 里唯一的元信息对象。锁两个不同的对象互不互斥，所以一个管实例范围、一个管类范围。

**Q4：多个不同的静态同步方法之间互斥吗？**
**A**：互斥。它们锁的是**同一个类的同一个 Class 对象**，所以同一时间只能有一个线程执行该类的任意一个静态同步方法。
