# java 数组和集合的使用场景

> 答题主线：**底层/中间件用数组，业务/接口用集合**。一句话收口——"数据量极大且长度确定用数组；日常 CRUD、长度动态、需复杂算法统一选集合"。二者的分水岭在**长度是否固定、能否存基本类型、是否需要丰富 API**。

## 一、四步回答骨架

1. **定调**：数组是"固定长度的原生容器"，集合是"动态可变、功能丰富的容器体系"，核心差异在**长度 + 类型 + 能力**。
2. **讲三层核心区别**：长度（固定 vs 动态）、数据类型（基本类型 vs 仅对象/装箱）、API 丰富度（极简 vs 极丰富）。
3. **给使用场景**：数组（长固定 / 存基本类型性能敏感 / 多维 / 变长参数）；集合（个数不定 / 频繁增删 / 去重 / 键值映射 / 业务流式处理 / 接口返回值）。
4. **收尾给最佳实践**：`Arrays.asList` 陷阱、`toArray(new String[0])`、性能时刻用 FastUtil 等。

## 二、核心要点

### 1. 数组 vs 集合对比速览

| 对比维度 | **数组 (Array)** | **集合 (Collection)** |
| :--- | :--- | :--- |
| **长度** | **固定不变**，定义时必须指定长度 | **动态可变**，可自动扩容/缩容 |
| **数据类型** | **协变**且支持**基本类型**（`int[]`） | 只能存**对象**（基本类型需装箱如 `Integer`） |
| **性能** | **最优**，内存连续、CPU 缓存友好 | 有对象开销（链表指针/哈希结构），略逊 |
| **类型安全** | 编译期+运行期都严格检查 | 泛型仅编译期检查，运行期**类型擦除** |
| **API 丰富度** | 极简，只有 `length`/`clone()`，需手动遍历 | 极丰富（`sort`/`binarySearch`/`stream`/`remove`） |
| **存储结构** | 一维线性（多维=嵌套数组） | 多结构（List/Set/Map/Queue） |

### 2. 深入细节（面试加分项）

- **协变 vs 逆变**：数组协变（`String[]` 是 `Object[]` 子类型），运行时抛 `ArrayStoreException`；集合靠泛型（`List<String>` 不是 `List<Object>` 子类型）把错误**提前到编译期**，更安全。
- **内存分配**：数组在堆上**连续分配**；集合内部虽也用数组（如 ArrayList），但额外维护 `size`/`modCount` 字段，内存占用更大。
- **访问方式**：数组 `arr[0]` 下标 O(1) 最直接；集合要 `get(index)` 方法调用。

### 3. 使用场景

**优先数组**：
1. 存基本类型且长度固定（`double[] temps`），避免频繁装箱拆箱性能损耗
2. 高频随机访问、对 CPU 性能极致敏感（算法库、报文缓冲）
3. 多维结构（棋盘 `int[][]`、矩阵转置）
4. 变长参数（`String... args` 底层就是数组）

**优先集合**：
1. 元素个数不确定（DB 查询结果 → `ArrayList`）
2. 需要频繁增删（尾 `ArrayList` / 头中 `LinkedList`）
3. 去重唯一 → `Set`；键值映射 → `Map`
4. 业务层配合 Stream `filter`/`map`/`collect`
5. 接口返回值返回 `List<String>` 比 `String[]` 更具扩展性

## 三、如何应用 / 面试怎么讲

**黄金建议：**
1. **底层/中间件用数组，业务/接口用集合**。
2. **数组转集合陷阱**：`Arrays.asList(arr)` 返回**固定长度视图**，不能 `add`/`remove`（抛 `UnsupportedOperationException`），且改原数组集合会同步变（共享引用）。
3. **集合转数组类型**：推荐 `list.toArray(new String[0])`（新版 JVM 优化反射，性能优于预分配大小写法）。
4. **性能妥协**：大量基本类型又求性能，用 FastUtil/Eclipse Collections 的 `IntArrayList` 等，避免装箱。

**一句话总结**：操作数据量极大且长度确定用数组；日常 CRUD、长度动态、需复杂算法支持无脑选集合。

## 四、可能被追问的点与预案

| 追问 | 应答案点 |
| :--- | :--- |
| 数组和集合哪个更快？ | 数组最快（连续内存、CPU 缓存友好、O(1) 下标）；集合有对象与扩容开销 |
| 为什么集合不能存基本类型？ | 泛型只认引用类型 + 类型擦除后统一 `Object`；用集合存基本类型需装箱（`Integer`），存在开销 |
| `ArrayStoreException` 什么情况出现？ | 数组协变：`Object[] o = new String[3]; o[0] = 123;` 运行期发现类型不符即抛 |
| ArrayList 底层是数组，为什么不直接用数组？ | 数组长度固定；ArrayList 封装了动态扩容（`grow`）与便捷 API（`add`/`remove`/`stream`），代价是额外字段 |
| `Arrays.asList` 返回的列表能增删吗？ | 不能。底层是固定长度数组的视图，`add`/`remove` 抛 `UnsupportedOperationException` |
| 泛型为什么运行期没类型信息？ | **类型擦除**：编译期擦掉泛型参数统一为 `Object`/上界，运行时无 `List<String>` 的类型信息，故类型安全检查只在编译期 |
| 什么时候非用数组不可？ | 存基本类型避免装箱、极致性能、多维结构、变长参数时更贴合数组 |
| 数组转集合、集合转数组有哪些坑？ | 转集合：`Arrays.asList` 固定长度没法增删、与原数组共享引用；转数组：要传对数组类型，`new String[0]` 更优 |
